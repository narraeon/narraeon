# 前端分别核对命令结果与页面读取

一次游玩请求可能已经提交玩家原文，模型仍在生成，浏览器同时失去 HTTP 回包。创建内容包也可能已经成功，随后一次工作区列表读取才失败。页面需要分别回答三个问题：这次操作已经完成了哪一步，当前页面读到了哪个版本，用户现在可以采取什么行动。[ADR-0001](0001-runtime-is-the-sole-committer.md) 和 [ADR-0044](0044-runtime-is-single-process-and-recovers-by-retry.md) 将提交与恢复能力的判断交给 Runtime。

传输模块负责解码各自协议的响应，保留 HTTP 状态、Runtime 错误码与结构化详情。未收到可用回包时，命令结果仍待确认。即使 Runtime 返回错误，多步骤命令也可能已经完成前面的步骤。具体进度需要从该命令的回执或权威记录判断。

| 界面获得的证据 | 界面行为 |
| --- | --- |
| 收到命令回执 | 立即采用其中已确认的结果。需要完整列表、文件或世界详情时再读。后续读取失败时保留回执并显示同步问题。 |
| 回包丢失，权威记录包含本次提交标识 | 按记录恢复本次操作已接受、进行中或结束的状态。游玩使用本次 exchange，作者会话使用本次 request 和对应会话。 |
| 只能读取旧记录，或核对也失败 | 保留未确认的输入，说明当前可见的通信问题。相同文字、同一会话或同一次打开的页面都可能对应更早的操作。 |
| Runtime 确认模型调用中断 | 按返回的原因与能力显示重发、继续发送或切换上下文。玩家决定是否再次调用模型。 |
| SSE 断开或展示快照失败 | 保留最后一次有效显示，单独反馈连接或同步状态。后续有效投递可以清除对应提示，切换目标后丢弃旧读取。 |

已确认提交后的刷新只包含可独立执行的读取。创建、导入、删除和模型派发各有自己的副作用，把整个回调交给通用重试器会重复副作用。能用回执完成的界面更新直接使用回执；需要额外核对时，由了解请求身份和持久记录的领域模块解释。缺少可关联的记录时，浏览器保留不确定性。这沿用了现有的本地持久化模型。

页面以当前目标及其只读加载函数建立读取入口，首次加载、手动重新读取、命令失败和实时观察异常共用该入口。普通读取失败后自动恢复一次；恢复读取本身失败时保留最后有效画面与草稿，显示「暂时无法同步」和只读的「重新读取」。写命令不进入读取重试。

同一目标合并重叠恢复需求，但故障之前已在途的读取不能代替故障之后的新读取。局部回执会使较早读取失效，却不能取消尚待完成的完整页面读取；完整有效观察则使较早读取的成功与错误一同失效。目标关闭后，迟到结果与错误均丢弃。实时观察的重复断线通知按一次断线处理，连接重建后的新断线才产生新的恢复需求。
