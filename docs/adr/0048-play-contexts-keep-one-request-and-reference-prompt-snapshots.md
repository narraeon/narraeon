# 游玩上下文只保留一份冻结请求，提示运行快照按引用保存

每次模型派发前，Runtime 把完整 `ModelHostExchange` 写进世界级 `runtime/play-requests/`，每次发送都把完整编译结果写成一份 `prompt-runs/N.json`，每个运行快照的首次派发还各写一份请求编码。一个约 200 轮的世界因此把 1.8 MB 的故事历史放大到约 305 MB：冻结请求只有每个上下文续传项 `lastRequestDigest` 所指的那一份会被读取，其余从不再被读；同一上下文的运行快照只有 `firstEventId`、`head`、`exchange` 不同；请求编码只有最近两份会被诊断读取。[ADR-0044](0044-runtime-is-single-process-and-recovers-by-retry.md) 不要求保留被替换的请求，因此这些副本没有保存价值。本 ADR 记录三条存储规则，由 #92 实现。

**冻结请求属于它的上下文，且只保留最新一份。** 每个游玩上下文在自己的目录下 `requests/` 保存一份完整冻结请求，文件名为摘要。写入新请求时，先原子写新文件，再发布新的续传项与状态，最后删除不再被状态引用的旧请求与旧续传项；任一步崩溃都由下一次写入或读取收敛到一致状态。读取仍校验摘要与 `lastRequestDigest` 一致。修改或分叉产生的新上下文以 `lastRequest` 为空开始，因此不复制任何请求；源上下文之后替换自己的请求不影响新上下文的文件。

**运行快照与其基底相同时只写引用。** 基底是上下文的 `base.json` 与 `index.json` 中的编译结果（第一份快照），或同一上下文的前一份快照。编译结果（预设身份、bootstrap、tools、followups、presetFiles、预设脚本开关）与基底相同时，快照记录只写 `kind: play_prompt_run_reference`，包含自己的事件、head、exchange、基底编号与基底编译结果的摘要；读取时按基底重建，摘要不符即拒绝。不同时仍写完整快照。这使连续多次不改预设的发送只在预设真正变化时新增一份完整内容。

**请求编码只保留最近两次。** 每个上下文的请求编码只保留两个最大 exchange 的文件，正好覆盖"AI 读取"诊断比较的当前与上一个运行快照；尚无运行快照的上下文以 exchange 1 读取，仍在这两个之内。分叉与归档只复制源上下文最近两份编码，与诊断比较的集合一致。

**已发布的游玩布局按 ADR-0034 原子迁移。** 世界升级时，若已有游玩上下文或旧 `runtime/play-requests/` 却缺少 `runtime/play-timeline-layout.json`，在世界锁内逐个上下文执行：把续传项引用的请求复制进上下文目录并校验摘要，把可折叠的完整快照改写为引用，删除多余编码与旧续传项；全部上下文完成后才删除 `runtime/play-requests/`，最后写入标记。每一步都可重跑：已存在的请求副本保留，已是当前形式的记录不改写。新写入的上下文自带标记，没有游玩记录的世界无需标记，读取不写入任何文件。世界归档导入以同一入口升级。

被拒绝的方案：

- **请求改存引用，读取时从其他文件拼回。** 拼接出错会让原样重发失去逐字节保证，而且把请求的生命周期绑在共享的内容寻址目录上。按上下文保存完整的最新请求更简单，原样重发天然逐字节相同。
- **通用内容寻址存储与垃圾回收。** 维护者已排除：这里只需要规范化与就地删除。
- **保留全部请求编码，只压缩快照。** 编码仍随发送线性增长，且不是诊断需要的全部。

与 [ADR-0025](0025-prompts-compile-into-append-only-model-sessions.md) 的运行快照与 [ADR-0035](0035-provider-continuation-is-opaque-and-bound.md) 的续传载荷不冲突：快照与续传的对外形状不变，变化只在磁盘布局。
