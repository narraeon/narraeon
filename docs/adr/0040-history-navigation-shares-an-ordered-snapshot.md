# 历史导航与注入共用有序快照

已提交叙事使用独立的 `history_list`、`history_search`、`history_read`；`HistoryQuery` 从 Authority 恢复的完整当前时间线集中产生稳定 ref、快照位置、角色、邻接和查询结果，PromptCompiler 只负责作者材料选择及编排。先选择消息，再按身份去重和过滤原生对话，避免位置随注入范围变化；注入与工具共用元信息及原文边界，但不把叙述角色解释为事实确认或角色知识。

list 页内和完整 read 始终由旧到新；search 可按最新或最早命中排序，提供有限多词字面匹配及最多三个正确映射回原文的片段。read 用消息数量限制窗口，保持完整正文而不引入字节截断。稳定 ref 连接历史快照；位置只是本次快照的 1-based 地址，不是身份、回合或故事日期。

Runtime 签名游标绑定版本、世界、工具、完整查询和有序消息身份及内容，不相信客户端声明的快照；历史追加／修订失效，纯状态变化保留有效性。签名密钥只在当前 Runtime 进程存在，重启后明确拒绝旧游标并要求原查询重做；这样无需新增 Authority 格式或持久游标账本，代价是跨进程不能续同一分页。冻结旧会话保留原工具全集、定义和 Provider 原生 transcript，旧历史调用通过兼容入口复用查询模块，旧偏移游标不猜测迁移。
