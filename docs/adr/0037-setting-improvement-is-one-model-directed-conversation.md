# 设定完善统一为模型主导的当前树对话

设定完善不由 Runtime 编排计划、生成、确认或模型终态。用户默认把消息追加到当前选中的模型会话；显式选择“全新上下文”建立新的 bootstrap 与模型绑定；每次普通发送重新编译当前作者编排，但保留原对话。旧会话可再次选中并继续；作者显式修改一条历史用户消息时，取代该消息及其后的 Provider 原生续传、工具轨迹和回复，不再采用旧的永久 append-only 合同。模型始终拥有稳定的设定读写工具全集，并根据用户语义自行选择讨论、询问、读取或修改。

内容包当前树是设定内容的唯一权威，不存在隔离草稿、候选快照、Apply 或 Discard 生命周期。Runtime 先持久保存一个完整 Provider 工具响应，再让其中调用针对同一受租约保护的当前树 revision 按顺序执行；各调用独立返回成功或失败，成功调用可被后续调用读取，失败调用不回滚成功的同级调用。完成整份响应后，Runtime 把所有成功变化原子发布到当前树，并把每个调用对应的已生效 diff、自动内容树检查与生产等价 Prompt Preview 作为工具结果继续交给 Provider。新建文档由 AI 给出公开短引用和业务元数据，Runtime 分配且隐藏内部文档 ID；既有内部 ID 在所有模型表面投影为 `@短引用`。

设定 patch 的 YAML locator 同时支持 map key 与从 0 开始的数组下标，并用 `remove` 精确删除已有节点。内容包整理允许物理删除整份 world 文档，但 Runtime 只在目标已经完整读取，且 currentSituation、frame slot、player-view selector 和其他文档 `$ref` 均未指向它时接受；拒绝结果必须列出全部阻挡位置。文档 ref 保持不可修改，move 保持不覆盖已有路径。游玩阶段不复用这项物理删除能力，而采用 ADR-0030 的可恢复退役状态。

Runtime 在“完整 Provider 响应与它可结算的原树指纹已保存”“当前树已发布”和“工具收据已追加”之间保存可恢复的结算意图。重启只确认已经发布的目标树，或从仍未变化的该原树重放这份完整工具响应；只有完整响应却没有该指纹的旧中间状态会失败关闭，绝不借用恢复时恰好存在的新树。流式片段从不进入 transcript 或执行工具，无法与结算前后任一 revision 对应的树也不会被冒认成成功。读取授权绑定内容树指纹，因此其他会话或手动编辑改变当前树后，旧会话必须重新读取才能写入。每段会话冻结模型 binding，每次新发送冻结自己的玩法预设与编译快照；恢复时可以找回匹配的已保存模型配置而不切换工作区当前配置。实际启用的主持／叙事块仍作为只读设计参考进入 bootstrap，自动检查继续反馈游玩读取覆盖，而不增加新的阶段或审批门槛。

能精确识别的旧隔离草稿 schema 在首次读取时先按该旧格式的完整结构严格验证并持久保留不可变旧源，再以当前会话文件作为迁移完成 marker；任一字段、差异或模型项不匹配都 fail closed，不默认、过滤或强制转换。迁移不发布未应用草稿；旧 Apply 收据在内容包操作租约内用当前树与精确 base/draft 指纹定类为已应用、未应用或结果未知，任一类都只保留审计事实而不写树。新 bootstrap 保留原语义和 Provider assistant 续传载荷，但在 Runtime-system 层追加明确取代旧草稿指令的当前树写入契约，并换用当前稳定工具定义。因此历史 transcript 不被重写，而后续消息也不会受更高优先级的旧 Apply/Discard 契约支配。当前 schema 同样对所有非 opaque 字段使用完整 codec，包括结算意图、diff、prompt、binding、usage 与各类 model item；未知字段不会被静默忽略。

当前树 schema 2 会话继续按旧 codec 读取和结算；下一次主动发送原子升级到 schema 3，原 bootstrap、模型项与原预设证据保留，新增 requests 保存每次请求的完整前部、资源与追加位置。工具循环始终使用该次快照，不能在内部往返重新读取编辑。旧请求不被新编排重建，未知版本或快照字段失败关闭。

内容包作者对话在派发前持久记录请求身份、交换序号与 transcript 边界，普通协议的断流、取消和空响应可显式原样重发，继续使用该次冻结编排与模型绑定，不追加用户消息或未完成片段。运行中崩溃也按此标记恢复；没有这一证据的旧中断会话不能推测出重发能力。已确认的工具响应必须先完成结算：已发布的树只补收据，原树未变才执行，树冲突则不开放重发。原生续传损坏、绑定不匹配、上下文或输出限制及 Google 已派发结果未知均不开放重发。重试操作身份用于去重，不替代原模型请求身份；世界修订的恢复语义保持原样。

派发证据属于当前树会话 schema 4，不修改已发布 schema 2 或 3 的 codec。首次升级时先校验并保存不可变旧源，再以原子替换的 schema 4 会话作为完成标记；旧未结算请求没有新证据时不会被推测为可重发。

消息修改保留所选消息之前的原生前缀，以修改稿发起新请求；作者选择保留当前树，或逆序撤回被替换部分的 AI 文件差异。撤回时逐路径检查后像与中间差异链，并校验结果没有新增内容树错误；冲突整次拒绝。会话 schema 5 保存修改意图、目标文件与替换后的对话，包级标记先于意图持久化；持有包租约的后续读取或写入先恢复意图，已发布树只完成会话提交，未发布树只在原指纹匹配时发布，其他状态失败关闭。完成后的请求身份用于去重，不能以不同内容复用。升级前保留精确的 schema 4 原文，先前已发布 codec 保持不变。

设定完善会话的磁盘 schema 7 在同一个 JSON 文件内保存冻结编译、玩法预设和预设源文件表。创建会话、每次发送、重试、可续写的中断请求和待完成的消息修改均按其自身内容引用表项。同一次保存只收录可由当前会话访问的快照；内容完全相同的表项复用，绑定、追加位置和原始 Provider 续传各自保留。读回时从表中还原当时的证据；悬空、类型不符或没有引用的表项使读取失败。新会话以此格式原子发布。既有 schema 2–5 延用各自升级边界，schema 6 在下次写入时先保留逐字节一致的旧源；这些备份随显式删除该会话清理。
