# 设定完善统一为模型主导的当前树对话

设定完善不由 Runtime 编排计划、生成、确认或模型终态。用户默认把消息追加到当前选中的模型会话；只有显式选择“全新上下文”才从内容包当前树和当时选中的模型／玩法预设重新编译 bootstrap。旧会话及其 Provider 原生续传、返回推理、工具轨迹和已生效差异永久保留在该内容包的历史中，任一旧会话都可再次选中并继续。模型始终拥有稳定的设定读写工具全集，并根据用户语义自行选择讨论、询问、读取或修改。

内容包当前树是设定内容的唯一权威，不存在隔离草稿、候选快照、Apply 或 Discard 生命周期。Runtime 先持久保存一个完整 Provider 工具响应，再让其中调用针对同一受租约保护的当前树 revision 按顺序执行；各调用独立返回成功或失败，成功调用可被后续调用读取，失败调用不回滚成功的同级调用。完成整份响应后，Runtime 把所有成功变化原子发布到当前树，并把每个调用对应的已生效 diff、自动内容树检查与生产等价 Prompt Preview 作为工具结果继续交给 Provider。新建文档由 AI 给出公开短引用和业务元数据，Runtime 分配且隐藏内部文档 ID；既有内部 ID 在所有模型表面投影为 `@短引用`。

设定 patch 的 YAML locator 同时支持 map key 与从 0 开始的数组下标，并用 `remove` 精确删除已有节点。内容包整理允许物理删除整份 world 文档，但 Runtime 只在目标已经完整读取，且 currentSituation、frame slot、player-view selector 和其他文档 `$ref` 均未指向它时接受；拒绝结果必须列出全部阻挡位置。文档 ref 保持不可修改，move 保持不覆盖已有路径。游玩阶段不复用这项物理删除能力，而采用 ADR-0030 的可恢复退役状态。

Runtime 在“完整 Provider 响应与它可结算的原树指纹已保存”“当前树已发布”和“工具收据已追加”之间保存可恢复的结算意图。重启只确认已经发布的目标树，或从仍未变化的该原树重放这份完整工具响应；只有完整响应却没有该指纹的旧中间状态会失败关闭，绝不借用恢复时恰好存在的新树。流式片段从不进入 transcript 或执行工具，无法与结算前后任一 revision 对应的树也不会被冒认成成功。读取授权绑定内容树指纹，因此其他会话或手动编辑改变当前树后，旧会话必须重新读取才能写入。每段会话冻结玩法预设 revision 和模型 binding；恢复时可以找回匹配的已保存模型配置而不切换工作区当前配置。实际启用的主持／叙事块仍作为只读设计参考进入 bootstrap，自动检查继续反馈游玩读取覆盖，而不增加新的阶段或审批门槛。

能精确识别的旧隔离草稿 schema 在首次读取时先按完整已发布结构严格验证并持久保留不可变旧源，再以当前会话文件作为迁移完成 marker；任一字段、差异或模型项不匹配都 fail closed，不默认、过滤或强制转换。迁移不发布未应用草稿；旧 Apply 收据在内容包操作租约内用当前树与精确 base/draft 指纹定类为已应用、未应用或结果未知，任一类都只保留审计事实而不写树。新 bootstrap 保留原语义和 Provider assistant 续传载荷，但在 Runtime-system 层追加明确取代旧草稿指令的当前树写入契约，并换用当前稳定工具定义。因此历史 transcript 不被重写，而后续消息也不会受更高优先级的旧 Apply/Discard 契约支配。当前 schema 同样对所有非 opaque 字段使用完整 codec，包括结算意图、diff、prompt、binding、usage 与各类 model item；未知字段不会被静默忽略。
