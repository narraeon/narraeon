# 设定完善统一为模型主导的隔离草稿对话

设定完善不再由 Runtime 编排计划、生成、确认或模型终态；每条普通用户消息都进入同一条 append-only 模型会话，模型始终拥有稳定的候选读写工具全集，并根据用户语义自行选择讨论或修改。Runtime 只机械保证完整响应、逐工具调用独立结算、自动检查、Provider 原生续传、失败恢复和用户唯一的精确版本 Apply：同一模型响应里的成功写调用按顺序留在隔离草稿中，每个失败只在自己的工具结果中说明原因，模型只需重试失败调用。新建文档由 AI 给出公开短引用和业务元数据，Runtime 分配且隐藏内部文档 ID；既有内部 ID 在所有模型表面投影为 `@短引用`。这让“先讨论计划”和“直接修改”都成为普通对话，而不会把任何模型写入直接提升为内容包当前树。为让这种自由创作仍能针对真实游玩语义，会话冻结当前玩法预设 revision，并把实际启用的主持／叙事块作为只读设计参考；每次已接受写入后，Runtime 从生产等价 Preview 反馈确定性读取覆盖，而不是增加新的计划、预览或结束阶段。
