# 生产游玩统一为模型主导的调用链

生产游玩只有“全新上下文”和“追加上下文”两个提交动作，不区分独立回合与连续会话，也不由 Runtime 编排裁决、叙事或集中结算阶段。全新上下文从当前端点重新编译稳定 bootstrap 并追加首条玩家原文；追加上下文继续现有 transcript，空输入时直接续写，没有上下文时自动全新开始。

玩家原文与每个完整且含叙事或世界变化的模型响应分别推进 Authority，后续失败不会回滚已经成立的前序提交；工具调用、Provider 返回推理、流式片段、失败与 usage 保留在可恢复的页面调用轨迹中，但不因此成为世界权威。Runtime 在模型派发前保存完整请求，但只有 Provider 明确拒绝或持久状态能证明尚未派发时才允许原样重试；流中断、传输失败或进程可能已开始派发却没有完整结果时属于 outcome unknown，旧请求不能重放，中断片段也不进入模型上下文。完整响应的后续追加遵循 [ADR-0035](0035-provider-continuation-is-opaque-and-bound.md) 的协议原生续传规则。

全新上下文只替换模型 transcript，页面时间线继续保存此前上下文；历史玩家消息的“修改”与独立世界的“创建分叉”采用 ADR-0032 定义的不同 Authority 操作。这个模型允许 AI 自行交错叙事、读取与写入，代价是 Runtime 不再用固定阶段强迫注意力分配，连续性质量依赖作者语义、模型能力和真实验收。
