# 整理检查点限定完整原文补充的边界

主持通过独立工具登记整理检查点，Runtime 在随后非空且无工具调用的最终正文成功提交时令其生效，边界包含该正文；登记后仍可继续工具调用。它是主持对截至本轮停笔位置整理程度的声明、历史重放边界和玩家可选择的新上下文建议，不是自动切换或语义完整性认证。回复结束、截至此刻记录整理完成与世界内事件结束分别成立；正常回复无需打点，登记也不完成场景。当前端点继承当前时间线可达的最近检查点，修改玩家消息和分叉沿用相同的可达性规则。

新上下文完整补入边界之后已提交的玩家原文和最终叙事，先从完整有序历史快照取得 ref、position、role 与开场白标识，再以精确消息身份去重；尾段非空时替代 frame 的 recent 选择，尾段为空时仍采用作者的 recent 声明。Runtime 不为这段恢复材料设置预算、截断或摘要，也不重放工具、工具中间文本和 Provider 返回推理；每条新玩家输入前另追加完成回合数，不改变玩家原文；后续发送重新编译前部时排除已在原生对话里的历史身份，不重新编号。注入显示本次快照总数、实际位置和完整正文边界；去重后可有间隔，不能宣称剩余记录覆盖连续区间。稳定 ref 可直接用于专用历史工具（[ADR-0040](0040-history-navigation-shares-an-ordered-snapshot.md)）。

这扩展了 [ADR-0025](0025-prompts-compile-into-append-only-model-sessions.md) 的新上下文材料选择。选择完整原文是为了允许可恢复的普通状态在事件收尾或合适的中间整理点归并，代价是长事件的输入增长；玩家视图显示的值和未在原文中记录但需要保留的信息仍须当场保存。主持先按授权与互动需要确定停笔位置，再保存其范围内的事实和待回应内容；活动进行中也可以整理完成并打点，检查点不反过来驱动事件到结算点。这是可编辑作者政策，机械层只描述登记、提交和重放关系。异常恢复继续使用既有持久推进，放弃恢复后直接切换的严格语义一致性不作为本机制的要求。

文档增长与最后写入位置来自已接受的正文及元信息变化；查询缓存可以丢弃，文件时间和模型自报不得替代 Authority。缓存排序只提供真实编译与编码诊断、显式作者顺序建议，不自动重排或改变 Provider 会话隔离。实施与模型验收证据见 [Issue #29](https://github.com/narraeon/narraeon/issues/29)。
