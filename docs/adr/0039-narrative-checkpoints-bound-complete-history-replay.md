# 事件间隙检查点限定完整原文补充的边界

主持通过独立工具登记检查点，Runtime 在随后非空且无工具调用的最终正文成功提交时令其生效，边界包含该正文；登记后仍可继续工具调用。它是主持对已经出现的事件间隙的声明、历史重放边界和下一次输入使用全新上下文的预选依据，不是自动切换或语义完整性认证。最新已提交主持正文成为检查点时，世界页自动预选下一次输入使用全新上下文，玩家可以取消；同一检查点不重复预选，新检查点才再次预选，不自动提交。取消或实际发送后的已处理选择按世界身份与不可变检查点端点保存在浏览器本地 UI 偏好，跨页面、刷新及相同浏览器配置／Runtime 地址的浏览器或 Runtime 重启保持；尚未处理的预选仍保留。清除站点数据、换浏览器或 Runtime 地址会重置选择，分叉世界独立。此选择不进入 Authority、世界文件或模型请求。叙事下方不再提供切换按钮，历史检查点仅在详细模式显示轻量标记。回复结束、截至此刻记录整理完成与世界内事件结束分别成立；登记不完成场景。当前端点继承当前时间线可达的最近检查点，修改玩家消息和分叉沿用相同的可达性规则。

新上下文完整补入边界之后已提交的玩家原文和最终叙事，先从完整有序历史快照取得 ref、position、role 与开场白标识，再以精确消息身份去重；尾段非空时替代 frame 的 recent 选择，尾段为空时仍采用作者的 recent 声明。Runtime 不为这段恢复材料设置预算、截断或摘要，也不重放工具、工具中间文本和 Provider 返回推理；新请求直接追加玩家原文，不生成检查点完成回合数提示，冻结的旧请求和原生对话保留原提示；后续发送重新编译前部时排除已在原生对话里的历史身份，不重新编号。注入显示本次快照总数、实际位置和完整正文边界；去重后可有间隔，不能宣称剩余记录覆盖连续区间。稳定 ref 可直接用于专用历史工具（[ADR-0040](0040-history-navigation-shares-an-ordered-snapshot.md)）。

这扩展了 [ADR-0025](0025-prompts-compile-into-append-only-model-sessions.md) 的新上下文材料选择。选择完整原文是为了允许可恢复的普通状态在事件收尾或合适的中间整理点归并，代价是长事件的输入增长；玩家视图显示的值和未在原文中记录但需要保留的信息仍须当场保存。主持先按授权与互动需要确定停笔位置，再保存其范围内的事实和待回应内容。整理随时可做，活动中途归并进展、更新认知与待办、去重不需要登记。默认主持只在事件自然告一段落或实际换场景、切换不会丢失仍然重要的细节时登记，无需玩家提醒；登记前核对上次检查点后的交互并保存后续所需结果。持续活动中途、反馈待玩家回应或仍有玩家待决事项时不登记。检查点只标记已经出现的间隙，不是本轮目标，不为到达间隙加速、压缩过程、代玩家完成未授权步骤或提前结束事件。一个事件跨越很多轮是正常的；玩家中途主动开启全新上下文，会取得上一个间隙后整个当前事件的原文，单个事件超过上下文窗口暂不处理。这是可编辑作者政策，机械层只描述登记、提交和重放关系，不判断事件结束或整理完成。异常恢复继续使用既有持久推进，放弃恢复后直接切换的严格语义一致性不作为本机制的要求。

文档增长与最后写入位置来自已接受的正文及元信息变化；查询缓存可以丢弃，文件时间和模型自报不得替代 Authority。缓存排序只提供真实编译与编码诊断、显式作者顺序建议，不自动重排或改变 Provider 会话隔离。事件间隙政策与新请求计数提示变更见 [Issue #65](https://github.com/narraeon/narraeon/issues/65)。原机制实施与模型验收证据见 [Issue #29](https://github.com/narraeon/narraeon/issues/29)。
