# 世界归档复用分叉闭包，并经隔离区导入

> 按 [ADR-0044](0044-runtime-is-single-process-and-recovers-by-retry.md)，导出时的来源快照锁与导入的 operation 幂等重试由进程内按世界串行取代。路径安全、体积上限与内容校验仍然有效；导入是否继续审计全部 Authority 提交随 #77 的存储决定一并确定。

世界归档是一个便携 ZIP：一份 `narraeon.world-archive/v1` 清单，加上一棵由“创建分叉”产出的自足世界目录。导出在来源快照锁下把当前端点分叉到导出暂存区，不写入世界列表，再按条目流式打包。导入先按条目解到与正常数据根隔离的临时数据根，完成路径与体积检查、完整文件清单与摘要校验、既有格式迁移和全部 Authority 提交的审计，再以跨数据根分叉发布为新的本地世界，最后删除隔离区。

世界的正确性来源仍然只有 genesis 锚点和不可变 Authority 事实。归档中的 state、history、物化检查点与页面时间线都是可重建投影；导入由分叉流程从 Authority 重新物化。普通历史分叉仍截取所选故事事件的前缀，完整归档则保留当前页面的全部上下文及冻结请求，再重新分配身份：世界修正、应用修订等没有对应故事事件的 Authority 端点不能让轨迹变空，已结束的失败调用诊断也属于备份。各上下文保留自己的端点，不把旧模型链伪装成已追上修正后的 Authority。归档中用于定位隔离源的身份不成为导入世界的本地身份；目标 worldId 由 import operation 确定性派生，同一归档可多次导入为独立世界。名称保持原名，扩展开关保留，包脚本授权清空。

归档不包含模型连接、凭据、工作区预设、偏好、未应用的世界修订与作者会话。`runtime/activity.json` 是本地显示缓存，不属于 Authority 或来源分叉闭包；导出显式排除分叉暂存区中新建的缓存，导入在任何迁移或读取前丢弃来源缓存，由本机按需重建。已有请求及产物的冻结资源仍属于世界的轨迹闭包。导入不信任来源机器的 Provider 绑定：每个导入上下文在不可变的小 index 中持久记录来源标记，始终拒绝续传它的旧 Provider 状态；分叉与历史修改保留的旧前缀继承标记。本机首次发送或全新上下文修改只消除世界的首次发送提示，不撤销旧上下文的限制，本机新建链可正常继续。普通世界读取只检查活动链的小 index，不加载旧 transcript 或 bootstrap。旧页面轨迹保留阅读、修改与分叉能力，修改旧记录只能采用本机选择重新编译全新上下文。

ZIP 上传上限为 1 GiB，解压总量为 2 GiB，最多 200,000 条目，单条目最多 256 MiB；上传、解压、摘要和打包均使用流式背压。未知归档格式、符号链接、特殊文件、非 UTF-8 文件名、绝对或穿越路径、重复及大小写冲突路径均拒绝。文件摘要不足以证明 Authority 正确，所以导入在迁移后还校验整条审计链及每个端点的结果 root 和 blob。

目标完整 staging 的一次 rename 是导入的 durable commit point。重试先检查确定性目标的 publication，已发布则返回同一世界；未发布则清理暂存后重做。启动清理遗留上传、隔离区及导出目录，并只清理由遗留导入 operation 确定的目标 staging；下载完成或一小时到期清理导出。清理不改变已发布世界。

我们拒绝“直接复制世界目录并改写世界 ID”，因为可变投影与页面轨迹中的世界局部身份会形成第二套容易漏改的迁移逻辑；也拒绝“只导出 Authority，丢弃页面时间线”，因为导入后会失去逐条修改、分叉与调用详情。复用 [ADR-0036](0036-authority-facts-are-world-neutral-and-forks-retain-physical-closures.md) 的分叉闭包，使导出、导入和分叉共享已经验证的身份重分配与原子发布实现，并沿用 [ADR-0034](0034-released-storage-formats-require-atomic-migrations.md) 的已发布存储格式迁移。
