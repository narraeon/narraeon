# 已发布持久格式必须提供原子迁移

正式发布或公开预发布过的 Narraeon 持久格式建立了升级兼容义务，不能因为新格式更干净就拒绝旧世界。对于能够精确识别的已发布 schema，Runtime 在首次使用前执行一次性、幂等迁移：保留旧源，先写完并验证当前不可变事实和投影，最后发布当前 Authority 小端点作为整个新布局的 durable marker；任一切点退出都从旧源和已写事实继续，不重放 Provider 或 Authority。

迁移完成后 Runtime 只读写当前格式，旧累计文件不再增长。我们拒绝长期双读／双写和对未知格式的启发式兼容，因为它们会把旧复杂度永久泄漏到正常读写 seam，并让损坏数据与真实旧版本无法区分。
