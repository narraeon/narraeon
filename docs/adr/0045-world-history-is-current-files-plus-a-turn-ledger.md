# 世界历史是当前文件加一份按轮记录的前像账本

[ADR-0033](0033-long-timelines-use-immutable-facts-and-rebuildable-projections.md) 与 [ADR-0036](0036-authority-facts-are-world-neutral-and-forks-retain-physical-closures.md) 把世界历史存成内容寻址、双父关系、带物化检查点的不可变事实链，服务于精确恢复任意旧端点、完整审计和崩溃后幂等续作。按 [ADR-0044](0044-runtime-is-single-process-and-recovers-by-retry.md) 确认的前提，审计不需要，崩溃靠重试，被替换的历史不保留；旧端点恢复只剩两个调用方：修改玩家消息时回退，和从故事事件创建分叉。两者都只需要"回到第 N 轮结束时的状态"。#77 的评估结论是替换，本 ADR 记录新模型。

**当前文件是权威。** 世界目录里的 `state/`、`control/`、`history/` 就是当前端点的内容，模型与编辑器直接读写，不再有另一份内容寻址的副本，也没有需要重建的物化检查点。

**轮账本记录前像。** 每一次推进世界的操作（玩家消息、完整模型响应、连续性修正、世界修订应用、回退）是一轮，轮号从 1 起单调递增，`commit:N` 继续作为端点别名，`genesis` 是第 0 轮。每轮在 `runtime/turns/` 下保存一条记录：轮号、模式、本轮改动的每个 state 文件的前像（新建记为空）、附加材料清单的前像、本轮追加的历史消息身份、叙事检查点声明、playContext 与 worldClock。记录只写一次，不内容寻址，不保存父摘要。

**推进顺序与恢复规则只有一条。** 推进先写本轮记录，再原子替换当前文件，最后推进 `runtime/head.json`。加载时若存在轮号大于 head 的记录，该轮未完成：用它的前像恢复文件并删除记录。除此之外没有其他恢复路径。

**回退是一轮，轮号不重用。** 回退到第 K 轮之后的状态，等于追加一轮 `rewind`：它像其他轮一样保存当前文件的前像，应用时沿账本把第 K+1 到 head 轮的前像倒序写回、删除这些轮追加的历史消息，然后删除这些轮的记录（编号保留，不再出现）。回退之后不能再从被丢弃的轮分叉，这是 ADR-0044 已接受的限制。页面时间线、模型上下文、产物与附件等派生数据的截断由回退的调用方负责。

**分叉与备份是目录复制。** 创建分叉把世界目录整份复制到暂存区，在副本上执行到所选轮的回退并重新分配世界身份，再一次 rename 发布；不再区分不可变与可变部分，不用 hardlink 或 reflink，不保留物理闭包。备份导出就是分叉到导出暂存区后打包；导入解压到隔离区、做路径安全、体积与账本结构校验后以分叉发布，不再逐轮审计。

**旧布局按 ADR-0034 一次性迁移。** 首次打开 Authority V3 世界时，从 genesis 逐提交恢复端点、按相邻差异生成每轮前像记录，写出当前文件和 head，再删除 `authority-v3/`；V1/V2 世界先经既有迁移器到 V3 再转换。迁移保持 `commit:N` 编号与历史消息身份不变。V1/V2 迁移器已按 #85 删除，不再直接升级：由 v0.2.0 及更早版本创建的世界须先用 v0.3.0–v0.6.0 打开一次（见 [ADR-0034](0034-released-storage-formats-require-atomic-migrations.md) 的迁移链约定）。

被拒绝的方案：

- **保留事实链、只删周边机制**。事实链的复杂度主要在它本身：内容寻址、双父关系、物化检查点、按 head 关联派生数据、分叉的物理闭包和导入审计，都是模型的直接推论，删不掉周边就删不掉成本。
- **每轮保存完整快照**。前像足以回退和分叉，完整快照让每轮体积随世界大小线性增长。
- **回退物理截断并重用轮号**。页面时间线与产物用 `commit:N` 引用端点，重用编号会让没清干净的引用悄悄指向新内容。

本 ADR 取代 ADR-0033 与 ADR-0036 的存储模型，取代 [ADR-0007](0007-v1-history-is-linear-and-immutable.md) 残留的"不可改写总顺序"决定，并修订 [ADR-0042](0042-world-archives-reuse-fork-closures-through-a-quarantine.md) 中关于闭包、hardlink 与全链审计的部分。[ADR-0039](0039-narrative-checkpoints-bound-complete-history-replay.md) 的叙事检查点与 [ADR-0040](0040-history-navigation-shares-an-ordered-snapshot.md) 的历史导航不受影响：它们读取的是 `history/` 与轮记录。
