# 提示词编排、编排方案与世界控制框架规格

本规格定义提示词分层、编排方案存储与迁移、双编排结构、本轮提示机制、世界提示框架及维护声明 schema，对应代码模块 `src/runtime/prompt/` 与 `src/runtime/config/`，并承接 [ADR-0025](../adr/0025-prompts-compile-into-append-only-model-sessions.md)、[ADR-0029](../adr/0029-author-prompt-layers-split-by-capability.md)、[ADR-0034](../adr/0034-released-storage-formats-require-atomic-migrations.md) 与 [ADR-0043](../adr/0043-tabletop-gameplay-is-world-identity-and-runtime-derives-resolution.md)。

## 1. 能力分层与编排方案边界

提示词按各层的**实际作用域与写入能力**切分，而不按语义主题切分（[ADR-0029](../adr/0029-author-prompt-layers-split-by-capability.md)）：

| 层级 | 所有者与可变边界 | 职责范围 |
| --- | --- | --- |
| **编排方案（外层作者框架）** | 工作区级跨世界资产；设定完善与游玩 AI 均不可修改 | 跨世界成立的通用作者语义（游玩编排与作者编排）、后置请求编排与纯界面扩展配置 |
| **世界提示框架（内层作者框架）** | 内容包 `control/frame.yaml` 及块文件；创建世界时复制入 `world/control/`，游玩 AI 不可修改 | 本世界特有的题材边界、专属规则／保存位置说明，以及确定性材料 slot 与维护声明 |
| **Runtime 机械说明** | 应用代码内置，不可由作者提示篡改或绕过 | 当前请求真实提供的工具、句柄、读取覆盖、写入授权、提交与检查点机械边界 |

- 一份 file-native 编排方案同时携带游玩编排（`playPrompts`）、作者编排（`authorPrompts`）、后置请求编排与纯界面扩展配置，是复制、导入、导出、应用与每次发送冻结的共同便携与 revision 边界；合入同一方案不扩大任一入口的工具或写入权限。
- 每次正常游玩发送（含空输入续写）或作者主动发送重新读取当前已应用的编排方案，并冻结为该次发送及完整工具循环的**游玩运行快照**（或作者请求快照）；内部工具往返不读取期间的编辑；对话本身不冻结后续发送的方案选择。
- **不绑定玩法模式或判定方案**：工作区只有一份当前编排方案，服务所有互动式小说与跑团世界。跑团世界的判定工具与世界占位处的只读规则块由 Runtime 依据世界的 `control/gameplay.json` 派生；内置跑团指导项（`play.tabletop`、`author.tabletop`）仅在跑团世界或跑团内容包编译中展开，互动式小说请求保持逐字节不变。用户自定义提示块也可限定为仅跑团生效；克隆跑团限定内置项时保留该限定。

## 2. 编排方案存储格式与分版本迁移

### 2.1 `narraeon.orchestration/v1` 叠加表示与系统种子所有权

新编排方案与应用模板使用 `orchestration.yaml`，格式为 `narraeon.orchestration/v1`。本地库 `file-native-orchestrations.json` 保存 `schemaVersion: 1`、`currentOrchestrationId` 与 `orchestrations`。便携导出为 `.orchestration.json`，只包含路径和文本内容。Runtime 在导出前用当前导入规则校验格式与请求体积。

- **应用目录所有权**：内置系统块的正文、稳定身份、元信息、默认启停与默认顺序属于应用目录，不复制完整系统正文进磁盘文件。
- **持久化叠加内容**：`playPrompts` 与 `authorPrompts` 仅持久化用户自定义正文、必要的系统引用身份、显式角色／启停／尾部行覆盖（包括清空）、选项组选择和自定义顺序。编辑器、保存校验、复制、导入导出、Prompt Preview 与生产编译共用同一有效编排解析层。
- **便携导出语义**：导出的系统引用在接收端按当地应用目录解析对应正文；用户正文、用户克隆与渲染资源保持原文。
- **系统种子所有权标记**：仅仍带 Runtime 所有权标记的系统推荐方案种子会跟随新版内置正文或界面语言生成新 revision。用户一旦编辑或重命名该方案，所有权标记立即永久移除，此后升级、重启或切换界面语言均不得覆盖它。复制、导入与用户新建的方案从不带该标记。

### 2.2 应用目录演进：新块插入与旧四块退役映射

应用目录新增系统块或退役旧复合块时，**不改写已有磁盘方案文件、不生成新 revision**，而在有效编排解析层确定性合成：

- **新块插入规则**：新项继承应用默认启停；已有项的明确停用、选项组选择、发送角色与尾部行覆盖（含清空）保持不变。插入位置依次取默认目录中**最近的已存在前项之后**；无前项时置于**最近的已存在后项之前**；再无邻项时追加至末尾。已有项彼此的相对顺序保持不变，重复合成无漂移、不重复。
- **旧四复合块退役原位展开映射**：历史上四个复合内置块退役后，解析层在有效编排中按原位置展开为对应后继项，继承原条目的启用状态、发送角色与尾部覆盖（已有明确后继定制时以后继定制为准）；用户克隆出的旧正文保持原文不动，如需采用新规则须由用户在工作台显式替换或改用系统引用：

| 退役复合块 | 原位展开的后继语义边界（不含具体默认文案） | 展开后的默认子项启停 |
| --- | --- | --- |
| 通用文风 | 叙事质感与节奏、人物与场面 | 继承原条目启用状态 |
| 裁判与玩家代理权 | 代理权选项组、裁决与事实、NPC 自主 | 代理权选项组按应用默认单选启用（其余同组项停用）；其余后继继承原条目启用状态 |
| 叙事建议 | 停笔选项组、结尾、输出边界 | 停笔选项组按应用默认单选启用（其余同组项停用）；其余后继继承原条目启用状态 |
| 状态维护建议 | 保存时机与整理、信息归属与事件、当前情境与玩家视图、检查点政策 | 继承原条目启用状态 |

### 2.3 已发布 v1、v2、v3 的一次性迁移

首次初始化发现旧库 `file-native-play-presets.json` 且新库尚不存在时，Runtime 按 [ADR-0034](../adr/0034-released-storage-formats-require-atomic-migrations.md) 将当前修订与可解析草稿一起迁移。旧库、历史修订、不可解析草稿保留原始内容。Runtime 在同目录写入并校验临时文件，再用一次原子 `rename` 发布新库。中断后从原库重试。新库发布后是常规读写入口。未知或损坏的库原样移至 `.unreadable-*.json`，工作区显示备份位置，并重建默认库。

| 旧 `preset.yaml` 格式 | 转换规则 |
| --- | --- |
| `narraeon.play-preset/v1` | 旧主持块和叙事块成为独立用户条目，保留正文、启停和顺序。对应的可选系统游玩块默认停用。世界指令和材料合并在首次世界位置。原有作者正文成为独立条目并停用对应系统建议。没有旧作者声明时采用应用目录的默认作者指导。超出当前便携格式体积或条目上限的方案继续使用原修订。工作台提示缩短提示词并保存、应用后再复制或导出。原文可在「高级文件」查看。 |
| `narraeon.play-preset/v2` | 原完整列表按已发布的必选身份校验，再转为叠加表示，保留用户块、克隆、顺序、角色和尾部覆盖。后续发布的必选块由有效编排解析层补入。 |
| `narraeon.play-preset/v3` | 沿用原叠加内容，仅更新清单文件名和格式标识。 |

旧 `narraeon.play-call-chain/v1` 的后置定义转换为 `v2` 有序引用，原定义、挂载和扩展资源随方案保留。v1.0.0 仍可导入 `.play-preset.json` 和上述三种旧清单，导入的副本使用当前格式。v1.0.0 之后的旧格式兼容清理见 [#244](https://github.com/narraeon/narraeon/issues/244)。

Runtime 在服务端校验保存和导入。草稿须应用才会切换有效修订。历史编译结果、冻结资源、Provider 原生续传与合法原样重试沿用当时的快照。

### 2.4 编排工作台 AI 会话与持久草稿

每段会话固定绑定一份方案，与其他方案的对话和续传独立存储。正常发送使用随应用发布的双语编辑 System，并冻结当时活动连接的模型提示词。编排名称与所选条目作为目标数据传递。待编辑的作者提示、条目正文和导入来源由专用工具按需读取。预览复用无实例编译，世界材料保持占位。工具的作用域是当前方案的游玩与作者提示，可在空工作区咨询。每次发送最多派发 64 步，随后可继续。工具续步沿用保存的编排和连接配置并追加新结算的回执。原样重试重放中断时保存的请求。

手动保存与 AI 写入都以 `draftRevision ?? currentRevision` 为基准。第一方工作台传入 `expectedRevision`，旧 v1 手动保存请求可省略。AI 使用稳定条目 ID 与结构化操作。修改既有条目前必须在该版本完整读取；同一响应的多项写入一起验证和落盘。内置尾部行可用空串清空，也可恢复随应用提供的默认行。条目差异记录前后版本、响应和操作身份。服务端先保存准备结算，再原子发布草稿及结算标记，重启后根据标记恢复工具回执。撤销仅在该批仍位于当前草稿末端时恢复其前像。后续批次尚未撤销、已有手改或方案已应用时会得到冲突。

作者显式应用才会推进已用版本。复制与便携导出读取已保存草稿，继续保持工作区当前选择。放弃已保存草稿退回已用版本并回收撤销前像。附带的对话和撤销日志按方案独立保存，不进入便携导出，复制方案不复制对话。主编排库只持有当前版本和最新草稿，原先保留的版本及后续换下的已用版本在库外继续支持历史读取。

## 3. 游玩编排与作者编排（`playPrompts` / `authorPrompts`）

### 3.1 块类型与互斥选项组机制

编排方案在统一有序列表中管理系统引用、用户提示、独立尾部条目和动态占位；列表顺序即编译进入请求前部的真实顺序（支持拖拽、上移／下移与 `Alt` + 方向键排序）：

- **必选块**：由 Runtime 机械说明拥有，只读、不可删除、不可停用，固定以 `System` 发送，允许排序。
- **选项组**：若干互为替代的内置块构成一个互斥组。同一组内启用任意一项会自动关闭同组其余项；允许组内全部停用，但不会同时启用两项。分组仅影响编辑器呈现与切换逻辑，编译仍按列表顺序逐块输出。本规格不锁死具体选项组名称枚举或默认文案。
- **独立政策块**：各自承载独立作者规则，可单独启停、排序或克隆为独立用户块。
- **文风块**：可多选叠加，默认停用，可独立启停与克隆。
- **用户提示**：作者独立拥有稳定身份、名称、正文、发送角色、启用状态与可选跑团限定；克隆系统块得到的用户正文不再随应用升级变化。

### 3.2 动态占位

1. **完整世界提示占位**：可排序与选择发送角色。游玩编译时在此展开世界提示框架的指令（与跑团只读规则块，如适用）；具体正文仅在绑定真实世界或内容包的 Prompt Preview 中展开。选定世界材料仅在全新上下文作为初始预加载工具结果提供。
2. **模型提示词占位**：每个本地模型连接可在模型 ID 下方保存一段可选多行「模型提示词」（克隆连接独立编辑，旧连接默认空白，同模型 ID 不同连接可不同）。`playPrompts` 与 `authorPrompts` 各自拥有独立的模型提示词占位，默认启用、以 `System` 发送、紧跟必选机械说明（旧方案补齐默认占位时保留已有项相对顺序与显式设置）。每次正常发送按当次实际连接展开；空正文或纯空白不生成消息；工具往返、后置请求、原样重试与历史查看沿用当次冻结正文；便携导出保留占位配置，导入后读取本地活动连接。

### 3.3 独立作者编排（`authorPrompts`）

- 设定完善与世界修订复用同一套 `authorPrompts` 编排，**不含后置请求**；工作台顶部在「游玩」与「设定完善」间切换编辑，互不影响各自配置与纯界面扩展。
- 创作工具与结算说明、创作目标占位为可排序必选项；创作建议与「未来游玩参考」可停用。
- **未来游玩参考**：按顺序只读展开当前 `playPrompts` 中已启用的作者语义块，明确标作参考而非本轮叙事要求，且**跳过游玩编排中的模型提示词**以避免同正文在作者请求中重复。
- 世界修订复用 `authorPrompts`，在编译时将机械说明与目标替换为世界修订工具契约与独占 epoch 信息。
- 旧方案缺少 `authorPrompts` 字段时，按原作者引用投影为用户正文，无旧声明才采用应用推荐，显式停用不触发回退。

### 3.4 发送角色与合并相邻同角色消息

- 除固定 `System` 的必选机械说明外，游玩与作者编排的其余条目均可选择 `System`、`User` 或 `Assistant` 发送角色（缺省 `System`）。发送角色独立于逻辑 role，不改变内容来源或写入授权。
- 世界占位的发送角色应用于世界指令，不影响以工具结果承载的初始预加载材料。
- 方案级开关 **「合并相邻同角色消息」** 共用于两套编排：新建方案默认关闭，缺少该字段的旧方案保留合并行为。未合并时每条启用且非空条目生成一条独立消息；开启时仅把相邻同角色正文连接合并，绝不重排，也不跨入真实对话或玩家输入。
- 当前 Anthropic Messages 适配器要求所有 `System` 项位于 `User`／`Assistant` 之前，不满足时明确报错。

### 3.5 编排工作台的无实例预览

- `play.orchestration.preview` 只读绑定一份编排及明确的当前或草稿 revision。也可提交基于该 revision 的候选文件和可选结构化表单。候选复用保存路径的序列化与校验，预览不会保存或应用它。对照以该编排的当前 revision 为基准，按条目身份显示增删，以及正文、角色、位置、启停、尾部行和合并设置的变化。
- 选择游玩或作者表面、互动小说或指定判定方案的跑团。作者侧可切换设定完善和世界修订，按对应目标展开机械说明、创作建议和未来游玩参考。未来游玩参考可以展示游玩尾部行，但实际作者请求无游玩尾部。
- 游玩前缀中的世界指令、全新上下文初始工具回执中的材料、世界尾部行和玩家本轮临时要求保留有来源及注入时机的动态占位。作者目标和预载材料同样保留占位。预览共享生产编译的叠加、互斥组、限定玩法、角色合并、尾部软上限和协议角色顺序。
- 若启用的世界指令或作者预载会改变消息分组，分组标记为条件性。尾部数量以已知静态行为下界。即使已知行未超限，总数仍取决于世界和玩家行。连接不可用或选择跳过连接时，协议检查为「未检查」。Anthropic 同时检查编译时世界占位的 System 顺序，Google Interactions 检查派发前缀的 System 顺序。可选动态材料造成的潜在冲突与可确定的冲突分别显示。
- 预览不建立虚拟世界、不派发模型，也不列举、读取内容包、世界或历史。绑定真实内容包的 `prompt.preview` 和后置产物预览仍可从各自入口使用。

### 3.6 编排助手会话与共享草稿

- 在同一编排方案身份内，创作助手和手动工作台检查同一有效 revision（`draftRevision ?? currentRevision`）。表单或源码有未保存修改时，输入区提供保存或放弃并保留待发文字。已接受的请求继续结算。只读同步更新版本信息，手动输入仍保留原基准直至作者处理冲突。
- 编排目录的内置摘要用于筛选可能重叠的条目。需要精读时，`orchestration_read` 可指定一个条目，也可在同一表面和 revision 指定最多 8 个明确条目。批量使用共同的 UTF-16 起点与长度，返回总量上限 64 KiB，条目可单独续读。只有返回的片段计作读取，写入前仍须逐条完整读取。
- 咨询保持只读。编辑工具先读当前版本，逐个完整模型响应原子结算结构化差异并记录操作身份。只允许更改指定游玩或作者表面的提示条目。使用独立编辑 System 和冻结模型绑定，待编辑内容作为材料。助手不应用编排方案，也不访问内容包、世界、游玩历史或脚本授权。
- 当前与最新草稿是编排库的活跃 revision。撤销所需快照随会话保存，只有当前草稿仍处于对应批次时才可撤销。作者可从最新已保存草稿复制或导出，复制和导出不携带对话；放弃整份未应用草稿退回原当前版本。系统推荐在原身份定制，首次保存与手动编辑采用相同的种子规则。
- 讨论会话按编排和会话身份恢复，支持取消、达到工具步数上限后继续，以及按调用记录允许的恢复方式重放冻结请求。删除会话只移除会话和撤销资料，删除方案则同时删除会话。实际发送采用新草稿仍须作者明确应用。

## 4. 本轮提示、尾部行与本轮临时要求

游玩主链每次派发（玩家提交、工具续步、空输入续写）均按本轮需要动态拼装一段短小的 **本轮提示（`turn_guide`）**：

- **来源与合成顺序**：按当前运行快照的有效编排顺序收集全部启用条目的尾部行，并在最末接上玩家当场输入的单行「本轮临时要求」：
  - 内置块默认尾部行或条目级覆盖／清空（`preset:builtin/<id>`，无需克隆整块正文即可修改或清空尾部行）；
  - 用户块尾部行与无前部正文的独立尾部条目（`preset:prompt/<id>`）；
  - 世界提示框架 `instructions[i]` 中声明的 `turnGuide`（在世界占位处按序展开，`world:control/frame.yaml#instructions[i]`）；
  - 玩家输入区「本轮临时要求」（`player:turn`）。
- **固定抬头与边界**：抬头由 Runtime 固定生成（中文 `[Runtime 本轮提示]`／英文 `[Runtime turn guide]`），不可由用户编辑；没有任何有效尾部行时整条后缀不追加。
- **软上限**：单行 **120 字**、总数 **10 行**为软上限，超出时在工作台预览与 Prompt Preview 诊断中给出警告，不拒绝保存或编译。
- **生命周期与作用域**：本轮提示仅属于当前派发请求，不进入 transcript 回放、Authority、历史或回合计数；随冻结请求保存，合法原样重试沿用保存的那份；恢复的旧会话从下一次正常发送起追加。设定完善、世界修订与后置请求不附加本轮提示。
- **玩家「本轮临时要求」**：独立于运行快照与冻结 bootstrap；Runtime 仅校验单行与长度上限，不解释其语义。成功结算后自动清空，中断或取消后保留；运行中、世界修订锁定时或未配置模型时随输入区禁用。界面旁提供的「在此收尾」快捷按钮仅将预置收尾文本填入（或以空格追加、不重复添加）输入框，不自动发送、调用工具、切换上下文或写入持久偏好。

## 5. Runtime 必选机械说明的精确边界

Runtime 必选机械说明只解释当前请求真实存在的机械契约，严禁暗中塞入文风、人称、玩家代理权、具体裁决偏好或状态保存策略等作者语义；作者提示亦不得伪造或覆盖机械能力：

1. 当前请求真实提供的工具清单与句柄合法来源；
2. 初始预加载材料的读取覆盖范围与写入授权资格（目录摘要不授正文写权）；
3. 精确 patch、元数据更新与文档退役的机械语义；
4. 写入成功回执所代表的最终状态与结算含义；
5. 工具中间步文本与终态无工具叙事的提交边界；
6. `world_checkpoint {}` 登记、生效时点与新上下文历史原文补充的边界；
7. 历史工具的按需检索与证据使用约定（已有材料足够时不例行检索、零命中不证明未发生、角色标签不确认事实、旧叙事不推翻明确当前修订、主持读取不授予角色知识）。

设定完善与世界修订的稳定工具全集、参数 schema、读取授权、逐响应原子发布及写后检查说明始终由 Runtime 内置，不进入可编辑正文。新请求不再生成距最近检查点的完成回合数提示，冻结旧请求与旧原生对话保持原样。

## 6. 世界提示框架（`control/frame.yaml`）与维护声明 Schema

### 6.1 `narraeon.world-frame/v1` 编排契约

内容包与世界的 `control/frame.yaml` 采用受限 YAML，只保存作者指令路径与确定性材料选择，**严禁内嵌世界状态实际值或自由字符串模板／语义查询**：

- `bindings.currentSituation`：必需，精确绑定当前情境文档的公开短引用（如 `@current-situation`）；Runtime 不按路径、文件名或标题猜测当前情境。
- `instructions`：有序数组，每项可引用相对 `control/` 的 Markdown 块路径（`markdown`）和／或声明单行 `turnGuide`（也可仅含 `turnGuide`）。
- `context`：有序 slot 数组，**必须恰好包含一个 `current_situation` 与一个 `additional_materials`**。允许的确定性 slot 类型：
  - `document`：精确整份文档；
  - `node`：精确 YAML 路径或 Markdown 标题路径节点（持久 locator 不得依赖易漂移的数组下标）；
  - `reference_targets`：精确 YAML 节点中显式 `$ref` 的一层目标（有界 `maxEntries`）；
  - `catalog`：相对 `world/`／`state/` 真实目录的直接子文档索引（`title`、`summary`、`@ref`），有界 `maxEntries`；默认 `required: true`（至少一份直接子文档），允许空占位目录显式标注 `required: false`；
  - `history`：近期历史槽（`kind` 仅限 `history`，不存在 `kind: recent`），只接受可选整数 `recent`（范围 `1–32`，例如 `{ kind: history, recent: 2 }`），不支持在历史槽中指定单条历史消息（精确历史消息引用走 `additional_materials` 附加材料清单）；
  - `current_situation` 与 `additional_materials`。
- **去重与重叠**：固定 `document` 与 `reference_targets` 等 slot 若选到同一整份文档，编译器保留首次出现位置并仅注入一次；整份文档与其中节点等范围重叠直接拒绝。

### 6.2 `maintenance` 维护声明与体积／时钟诊断 Schema

`control/frame.yaml` 可选声明文档建议体积、材料槽建议体积与写入时钟节点（均为提示性诊断，超限仅提示，**绝不拒绝写入、截断正文或阻止结算**）：

```yaml
maintenance:
  documents:
    "@current-situation": 8000
    "@alex": 12000
  clock:
    document: "@current-situation"
    locator:
      yaml: [时间]
context:
  - slot:
      kind: document
      document: "@world-rules"
      id: rules
      advisoryBytes: 24000
```

- **字段约束**：
  - `maintenance.documents`：键为稳定文档短引用，值为正整数 UTF-8 字节数（非 token 预算）。
  - `maintenance.clock`：显式指定文档短引用与逻辑节点 `locator`，用于记录写入时世界时间（仅采标量或 Markdown 文本；未绑定、不可读、复杂 YAML 对象或旧提交缺失时显示「未记录」）。
  - `context[].slot.id`：稳定唯一标识符（调整 slot 顺序后保持）；`advisoryBytes` 为正整数 UTF-8 字节数。
- **报告口径与增长基准**：
  - 区分单文档原始正文字节、去重后的真实注入贡献（含该文档真实标题与标记，合计不重复计跨文档公共标记）、世界材料总量、检查点历史补充、作者与 Runtime 提示、以及逻辑工具 JSON。
  - 增长基准取世界起点文档正文（游玩中新建文档取首次接受正文并标「创建后新增」）；分叉保留来源基准；空基准不计算倍数。
  - 正文与元信息各自最近一次已提交写入位置按当前可达 Authority 历史分别计算（不使用文件 `mtime`，无变动写入／重启／复制不改变位置），**仅在维护诊断中展示**，不注入模型材料或 `context_read` 回执。
  - 诊断读取失败时仅显示「不可用」，不得阻断写入、叙事结算或世界修订，也不得展示旧事实冒充现值。

## 7. SillyTavern 预设导入与静态宏阅读

- **支持来源**：SillyTavern 完整 Chat Completion 预设与 Prompt Manager v1 的 `full`／`character` 导出。
- 向导分栏显示目录与详情。选择标题可查看该项详情，移动端使用上下布局。首次自动选中顺序组及切换顺序组时，勾选该组源中已启用项。作者可以批量选回这些项、清空，也能逐项勾选源停用或未编排的项。选择、名称或顺序组变化都会清除旧预览。预览分别展示来源启停、是否勾选、目标启停与兼容诊断。
- **兼容策略**：可表达的静态提示转为独立用户提示；选中的不兼容提示保留原文并默认停用；动态占位与缺失内建定义仅作说明不伪造正文；未编排提示单列展示，选中后停用。必要来源元数据与诊断随方案保留；模型、采样、连接、扩展配置不自动迁移，凭据不显示不保存。导入创建**不自动应用的独立副本**，保留原有 Narraeon 便携导入路径。
- **静态宏与脚本阅读**：阅读区按勾选条目提供 `setvar` 声明与 `getvar` 引用的保守静态列表（不代表求值顺序或运行时值；动态、重复、条件与外部变量标为不确定；不模拟执行，宏类别参考见 [SillyTavern 宏阅读参考](../sillytavern-macro-notes.md)）。已识别的酒馆助手嵌入脚本与正则仅在独立只读目录查看源码，缺失源码明确提示，不读取外部引用、不执行、不导入。
- 来源快照保留所选顺序组的完整顺序、原始启停、勾选状态和 marker 位置，并保留所选可阅读条目的原文及宏、插入和触发等诊断。Runtime 按本地方案身份单独保存快照，复制和删除方案时同步处理快照。导入先原子写入快照，再发布方案与可重试的回执。旧方案可以选择与原始导入匹配的 JSON 来补全来源，即使导入的用户块后来已修改。
- 「导入并用 AI 整理」创建未应用副本后直接打开编排编辑工作台。没有模型时，作者仍可查看来源与手动编辑。模型设置结束后回到原方案，保留已输入的待发文字。模型请求由作者主动发送。
- 编排助手按派发时绑定的来源快照分页读取目录，可分段读取作者已选正文。目录也包含未勾选的 marker。来源角色与正文均作为工具数据，变量摘要仅记录可静态识别的声明和引用。提取需先读每个引用片段，可拆分或合并。草稿显示原条目、UTF-16 片段位置、改写理由和未保留的条件。原先依赖宏、历史深度或触发器的提取草稿在作者核对前保持停用。源历史位置只提供原语境线索，每次模型派发的尾部提醒仍按本轮提示规则运行。方案与本地目录可核对缺失的写回、事实归属、当前情境、检查点和裁决指导。
- 出处按本地方案、修订、编排表面和条目单独保存。手动修改正文后标记其变化，撤销或回到先前版本时读取相应出处。复制所选版本带上其来源和出处。便携导出保留编排文件和轻量导入报告。
