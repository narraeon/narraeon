# 游玩调用链、历史导航与世界生命周期规格

本规格定义生产游玩调用链、按需读取与写入授权、历史导航与检查点重放、跑团机械判定、轮账本权威提交、幂等去重、世界外修改机制与世界备份归档，对应代码模块 `src/runtime/play/`、`src/runtime/history/`、`src/runtime/world/` 与 `src/runtime/archive/`，并承接 [ADR-0030](../adr/0030-production-play-is-one-model-directed-call-chain.md)、[ADR-0032](../adr/0032-player-edits-append-current-world-timeline-revisions.md)、[ADR-0039](../adr/0039-narrative-checkpoints-bound-complete-history-replay.md)、[ADR-0040](../adr/0040-history-navigation-shares-an-ordered-snapshot.md)、[ADR-0041](../adr/0041-history-captures-optional-situation-background.md)、[ADR-0042](../adr/0042-world-archives-reuse-fork-closures-through-a-quarantine.md)、[ADR-0043](../adr/0043-tabletop-gameplay-is-world-identity-and-runtime-derives-resolution.md)、[ADR-0044](../adr/0044-runtime-is-single-process-and-recovers-by-retry.md) 与 [ADR-0045](../adr/0045-world-history-is-current-files-plus-a-turn-ledger.md)。

## 1. 游玩调用链时序与提示包装

生产游玩只有一套模型／工具循环（[ADR-0030](../adr/0030-production-play-is-one-model-directed-call-chain.md)），两个提交动作均为单次动作而非需要维持的模式：

- **全新上下文**：从世界当前端点重新编译稳定 bootstrap，冻结当前编排方案、世界 frame、材料与工具全集，将本次玩家原文作为首条普通玩家消息。仅替换模型工作上下文，页面保留此前全部已提交剧情与调用轨迹，并在新上下文起点插入分隔标记。
- **追加上下文**：在已有调用链且输入非空时，按当前编排方案更新指令前部，保留初始世界材料、目录索引与原顺序的 Provider 原生对话并追加玩家消息；无既有上下文时自动按全新上下文开始；已有上下文且输入为空时，不追加玩家消息：若上次请求中断则原样重发保存的未完成步骤，若上次响应完整则触发空输入续写。

### 1.1 请求包装、工具中间步与终态提交

```text
玩家消息 -> Authority（独立一轮）
  -> 模型完整响应
       -> 含至少 1 个工具调用（工具中间步）：
            -> 执行工具；如有世界变化 -> Authority（独立一轮）
            -> 同响应 text 仅留在调用轨迹与 Provider 续传载荷，不进入主持叙事
            -> 全部工具结果后追加 Runtime 结算提示，继续下一次模型请求
       -> 无工具调用且 text 非空（终态叙事）：
            -> 主持叙事 -> Authority（独立一轮）
            -> （如有）串行派发后置请求（不推进 Authority）
```

- **玩家输入包裹**：新请求在模型侧以明确开闭标记包裹完整玩家原文（中文 `<本轮玩家输入>`／英文 `<current_player_input>`），标记不进入已提交历史或玩家界面；Prompt Preview、实际请求与上下文诊断共用同一投影；旧冻结请求与原生对话保留原字节不补标记。
- **本轮提示与结算／续写提示**：每次主链派发附带当次编译的本轮提示（[提示词编排规格 §4](prompt-orchestration-and-presets.md#4-本轮提示尾部行与本轮临时要求)）。全部工具结果后追加 Runtime 结算提示，要求根据回执在无工具调用的最终正文中呈现尚未展示的内容并与已提交状态一致（不要求在此后再推进剧情），该提示随结算持久化。最终主持正文已提交后的空输入续写，在原生对话末尾追加独立 Runtime 续写提示（声明无新玩家输入、旧正文已提交、不得重复提交旧正文），不入历史或回合计数，随冻结请求保存。
- **无整体原子提交**：玩家原文、工具产生的世界变化、终态主持叙事分别推进轮账本；后续模型或传输失败不会回滚已成立的前序步骤。每次 Authority 写入须基于该上下文当前已提交端点；若世界已被其他操作推进，只能开启全新上下文。

### 1.2 「重新生成」菜单

- **只重写这段正文**：针对当前时间线最新已提交主持正文，仅回退最后这段叙事，保留此前玩家提交、全部已结算工具调用、工具结果与世界状态变化，使用最后叙事派发前的冻结原生请求和当前兼容连接重发（[ADR-0048](../adr/0048-play-contexts-keep-one-request-and-reference-prompt-snapshots.md)）。目标过期、请求证据不可用或续传不兼容时拒绝；重发后若模型再次返回工具调用，不执行工具并允许重试。
- **整轮重来**：仅当最新已提交主持正文在同一上下文中的上一条可见故事项是可用的已提交玩家消息时提供。撤回本轮进展，复用该玩家原文重新推演，且不新增玩家回合。若上一条可见故事项是判定卡，则无此入口。原上下文可用时直接沿用；归档导入、续传不可用或原上下文生成失败时说明原因，并提供「用全新上下文重新生成」（由玩家确认后采用当前连接与编排方案）。若时间线修订已完成，恢复起点以修订后的同一玩家节点为准。

## 2. 初始材料预加载、按需读取与游玩写入授权

### 2.1 预加载材料、开场白与附加材料清单

- **创建与首次派发**：`world.create` 可省略 `model`，从已校验的内容包独立发布世界，持久化 genesis 开场白。旧客户端传入的 `model` 字段仍可接受，有活动连接时可获得只读预览。发布、重开及读取开场白不派发请求，也不写入模型绑定、调用链或续传记录。首次实际发送前解析届时有效的连接；没有活动连接时拒绝发送，世界端点、历史和调用链保持原样。
- 全新上下文按 `control/frame.yaml` 选定的材料，在指令之后、玩家输入之前编码为一组 Runtime 预填调用与工具结果（`runtime_load_context` 仅标识预加载，不供模型调用，也不计作 AI 工具行为）。
- 预加载覆盖报告说明每份材料的写入范围。完整正文授予整份正文及元数据的写入资格。节点仅授予该节点和子节点的写入资格。目录摘要不授予写入资格。缺少正文或写入资格时用已有句柄直接精读，需要发现未知句柄时再列目录。
- **逻辑起点开场白**：尚未发生玩家对话时，首次游玩 bootstrap 直接携带已展示的完整 `opening.md`（genesis 主持原文）一次，标明玩家已读且当前状态与明确修订优先；后续全新上下文在没有生效检查点时，从所选世界时间线已保存的 genesis 开场白开始按顺序补入已提交原文。生产编译始终从 `recent` 与附加材料中排除 genesis 引用。持续有效的线索与待回应事项由作者写入合适的世界文档；Runtime 不从开场白或其他叙事抽取并写回当前事实。
- **附加材料清单**：全新上下文读取当前端点的附加材料清单并冻结，同上下文后续发送不刷新。仅允许精确文档、逻辑节点、历史消息或历史提交引用；Runtime 逐项检查引用、重叠与数量，任一项失败整份拒绝，不静默截断。

### 2.2 三种机械读取面与目录句柄

模型读取面仅限三种诚实机械能力：

1. **有界目录枚举（`state_list`）**：整份返回并声明范围与完整性，不分页。`control/frame.yaml` 中声明的 `catalog` 目录即使当前没有任何文档，`state_list` 也必须返回其 `@dir-*` 句柄，`world_create` 可在其中创建首份文档；既不存在又未被 frame 声明的目录句柄一律拒绝。空目录句柄是冻结 frame 的只读投影，不构成持久文件。
2. **字面搜索（`context_search`）**：仅搜当前状态文档（不承担新会话历史查询），结果声明范围、cursor 与完整性；零命中不证明世界不存在某事。
3. **精确读取（`context_read`）**：一次返回完整文档或精确逻辑节点原文，不按字节截断或分页。整文档读取将 `title`、`summary`、`aliases` 作为明示元信息与可写正文分开返回。

`state_list` 和 `context_read` 按本次派发的编排语言呈现回执框架。精读回执标明完整文档或节点对应的写入范围，文档内容、元数据值和句柄按原文投影。原生对话中已派发的回执原样保留。

### 2.3 游玩精读授权的内存态与重启／回退恢复

- **仅存内存，不以整棵 `state/` 指纹作前提**（[ADR-0044](../adr/0044-runtime-is-single-process-and-recovers-by-retry.md)）：游玩文档写入的「先精确读取再写入」授权仅保存在进程内存，不再持久化授权检查点，也不再要求旧读取凭据与整棵 `state/` 指纹逐字节一致。目录摘要与玩家视图绑定标记均不授予正文写入资格。
- **同对话保留与重放恢复**：
  - 同一进程、同一原生对话的后续追加发送（`#refreshPrompt`）会按当前编排方案重新编译编排前部、工具定义、后置请求与方案资源，同时保留已取得的内存精读与写后延续授权，**绝不重新绑定初始 bootstrap 材料覆盖**（避免重新授予先前轮次已失效的范围）。
  - 进程重启或回退（修改玩家消息／重新生成）时，从初始 bootstrap 授权出发，按保留对话顺序重放成功的 `context_read` 和已生效编辑对授权范围的变化。已删除节点和因删除而移位的列表下标失去旧资格，后来成功的精读可以重新授权。只保留当前世界快照中仍可解析的范围。
  - 保留对话里的 `world_create` 成功提交后，模型继续拥有该文档的整文写入资格。恢复时按已提交的文档身份解析；旧记录可以凭已提交步骤中的 `@实际短引用 write succeeded` 回执和当前快照恢复。创建失败、缺少可确认的成功回执或回退到创建前时，需按普通精读流程取得资格。
  - **重启后语义保证**：仍有效的精读可继续用于修改，未读的兄弟节点依然不可修改。旧回执缺少结构化的逐编辑结果时，Runtime 用已结算调用的参数识别可能失效的范围。无法确认某条编辑是否改变该范围时，需要重新精读。
  - **写入提交安全**：真正的防过期写保护由轮账本提交时逐文件核对原内容／前像哈希提供。
- 开启**全新上下文**不继承旧对话的读取授权，仅从新 bootstrap 授权开始。

### 2.4 `world_patch`、`world_create`、`world_retire` 与回执

游玩 AI 只能操作候选 `state/`，不得修改 `control/`、旧叙事、提交账本或编排方案，也不得物理删除或移动整份文档。游玩顶层文档写工具为 `world_patch`、`world_create` 与 `world_retire`（另有登记检查点的 `world_checkpoint`）：

- **`world_patch`（单次 1–32 条 `edits`）**：
  - 接收 `target`（`@ref`）与 **1 至 32 条 `edits`**（拒绝空数组、超过 32 条或字符串化的非数组参数）。
  - **批前校验（整批拒绝）**：在执行第一条编辑前，Runtime 先校验整批 `edits` 的写入授权（包含批内连续编辑的范围演进，例如不得删除数组元素后利用被删位置越权改写未读的后继元素），并用 `assertToolReferenceHandles(args.edits)` 检查整批中所有 `$ref` 对象的语法形态——**包含 `$ref` 的对象只能有 `$ref` 这一个键，且值必须是以 `@` 开头的字符串**（例如 `{ $ref: "qin" }` 会在执行第一条编辑前拒绝整批）。**任一编辑越出授权范围或违反 `$ref` 对象语法形态，整次调用在执行第一条编辑前即整体拒绝**，不落地任何改动；通过批前语法检查后，具体的 `@短引用` 目标解析（如空引用 `@` 或不存在的短引用）在逐条执行时进行，只影响对应编辑项而不阻断同批其他合法编辑。
  - **逐条执行**：批前校验全部通过后，在候选快照上按顺序逐条应用编辑（单条无法应用的编辑被跳过、其余照常生效）；仅当整批编辑全部失败（`!revised.ok`）或快照不可用时整次调用按失败返回；若编辑合法执行但未产生文档字节改动（如 `remove` 缺失路径或幂等写入相同值，`revised.ok === true` 且 `changes.length === 0`），整次调用仍返回成功（`ok: true`，状态 `@<ref> 无变化` 或 `@<ref> unchanged`），且无变化不推进 Authority。
  - **模型可见回执**：Runtime 内部逐条记录结果，发给模型的回执按整次调用结果分两类：
    - **整次调用失败（整批所有编辑均失败，`!revised.ok`）**：回执说明整批未应用到 `@<ref>` 并列出各失败项原因，**不附**已应用数汇总，也**不附**仅重发被拒编辑的提示；
    - **整次调用成功（`revised.ok === true`）**：全部编辑均成功应用时不列逐项明细；含失败项或 `no-op` 项时，汇总已生效数（`已应用 <applied>/<total> 条编辑` 或 `<applied>/<total> edits applied`）并**只逐条列出失败项与 `no-op` 项**（不列出成功项序号），且**仅在其中存在失败项时**附带仅重发被拒编辑的提示。
  - **共用路径写入规则**：`add` 与 `replace` 均为 upsert——无论目标路径是否存在均写入，缺失的父级 map 自动创建，数组下标越界时追加到末尾；`remove` 删除已存在精确路径，目标路径不存在时记为 no-op 并在回执中注明。YAML locator 可混合 map key 与从 `0` 开始的数组下标。
  - **`op: "set_metadata"`（元数据更新操作）**：作为 `world_patch` 的一个编辑操作（而非独立顶层工具），用于更新过时的 `title`、`summary`、`aliases`，调用时只传需要改动的字段（至少提供一项），省略字段由 Runtime 原样保留，不得直接 patch `$document` 内的不可变 `id`／`ref`。
- **`world_create`**：在合法 `@dir-*` 目录下新建文档，AI 提供唯一 `ref`、元数据与正文，Runtime 生成并隐藏内部 `$document.id`。
- **`world_retire`**：切换一份状态文档的可恢复退役标记。退役文档仍保留在 `state/` 与轮账本中，可列出、搜索、精确读取、引用和取消退役，但后续全新上下文的 frame `catalog` 不再注入它，也不影响历史叙事。
- **紧凑写入回执**：按被派发请求的编译语言呈现整份工具响应结算后的最终状态，区分写入成功、无变化（无变化不推进 Authority）与失败。结算与授权以结构化结果为准，旧创建记录继续兼容英文成功回执。重复调用重用已结算回执的原文。若文档或材料槽超过 `frame.yaml` 声明的建议字节，回执附一行整理提示（正文字节、建议上限与本次变化）；不回显全文、节点或内部提交编号；体积诊断失败仅省略提示，不撤销已接受写入。

## 3. 历史导航、可选历史背景与检查点重放边界

### 3.1 专用历史导航工具（ADR-0040）

已提交叙事由专用 `history_list`、`history_search`、`history_read` 导航，范围严格限定为当前时间线的开场白、玩家原文与最终主持原文（不含工具中间步、工具结果或返回推理）。位置、角色、开场白标识与邻接来自完整有序历史快照，不解析 ID 猜测回合或日期：

- **`history_list`**：默认返回最新一页，`before`／`after` 取排除锚点的紧邻页，页内恒由旧到新，返回独立 `earlierCursor`／`laterCursor`；列表预览为前 **120 个 Unicode 码点**，原文长度不代表 token 数。
- **`history_search`**：接收 **1–5 个**字面 `queries`、`any`／同一消息内 `all`、NFKC 规范化与可选大小写匹配；默认最新命中优先（可改最早优先，时间区间不随排序变化）；每项返回逐词次数及最多 3 个从正确原文位置提取的片段（优先覆盖不同词）。
- **`history_read`**：支持 `latest`（**1–21 条**）或指定稳定 `ref` 加前后条数（合计最多 **20 条**），恒为正序、无截断、保留空白，并标明窗口外紧邻的 `earlier`／`later`。
- **签名游标与失效边界**：`history_list`／`history_search` 续页只传游标。游标由 Runtime 签名，绑定世界、工具、查询条件与有序快照（含消息身份、原文与历史背景）。叙事追加或时间线修订返回 `history_changed`（纯状态或纯控制修改不使游标失效）；非法、跨世界／工具、旧偏移或进程重启后的游标均要求重新查询；`ref` 离开当前时间线返回 `history_ref_not_in_current_timeline`（不声称旧记录已被物理删除）。冻结旧会话保持原工具定义与原生对话，不向旧全集注入新工具。

### 3.2 可选历史背景采集（ADR-0041）

Runtime 从受限 YAML 当前情境选择精确顶层的历史背景，随每条已提交叙事不可变地保存所选完整节点（不解释内部语义、不展开 `$ref`、不附带兄弟字段、不截断长文本）。

- 优先按精确顶层键 `背景` 读取，仅在该键缺失时读取 `background`。两键均缺失，或所选值为 `null`、空白字符串、空映射或空数组时，视为未记录。空中文键也优先于英文键。保留 `0` 与 `false`。Markdown、其他大小写拼写与嵌套同名字段不参与。
- 采集时点：开场白取起点状态；玩家原文取接受输入时的已提交状态；主持叙事在工具修改前冻结绑定与起点，在最终正文结算时采集同一文档终点（工具循环、原样重试与恢复沿用起点；正文提交后的空输入续写建立新起点）。
- 呈现规则：历史工具、`recent`、附加材料、检查点补充与 Prompt Preview 在原文边界之外共用同一记录——前后相同只显示一次，不同则标推进前／后，单端缺失明示未记录；搜索、片段偏移与长度只计算原文。
- 不可变边界：后续状态更新、改名、绑定切换或世界外修订不改写旧记录。旧中文世界无需迁移。冻结请求沿用已保存的起点值（包括空值），缺少起点记录的旧冻结请求继续不采集背景。普通读取直接使用关联投影，不逐条恢复世界树或为旧记录回填。

### 3.3 叙事检查点与完整原文重放（ADR-0039）

- **工具登记与生效**：主持调用空参数 `world_checkpoint {}` 持久登记检查点，登记后仍可继续调用工具；只有随后非空且无工具调用的最终正文成功提交后检查点才生效，边界包含该正文。检查点标记历史重放边界，不结束世界内事件，不自动切换上下文，Runtime 不认证语义完整。当前端点沿当前时间线继承最近可达检查点；时间线修订与分叉不采用被舍弃后续中的检查点。
- **新上下文完整原文补充**：全新上下文完整补入当前时间线上最近生效检查点之后的全部已提交玩家原文与最终主持叙事。当前时间线没有生效检查点时，从世界起点补入，先放玩家已读的 genesis 开场白，再按顺序放其他已提交原文。仅登记尚未生效的检查点不改变选择。生产派发与对应全新上下文预览使用同一编译规则；原生续步保留既有材料，原样重试重发冻结请求。
  - 尾段非空时替代 frame 的 `recent` 选择（即使 frame 未声明 history slot 亦补入）；尾段为空时沿用 frame 的 `recent` 声明（可带入检查点所在正文）。
  - 置于当前世界材料之后，从完整有序快照选取、按精确消息身份去重并过滤原生对话中已有项（不重新编号），标明总数、原位置、role、开场白标识、可直调工具的 `ref` 与非连续间隔提示；保留原文字节与顺序，不设预算、不截断、不摘要，不含工具与返回推理。
- **界面预选偏好**：当前时间线最新已提交主持正文为检查点时，前端自动预选下一次输入为「全新上下文」（不自动提交）；玩家可取消，同一检查点不重复预选。取消或实际发送后，以「世界 ID + 不可变检查点端点」保存在本地 UI 偏好中。浏览器偏好跨页面、刷新及同配置／同地址重启保持；清除站点数据、换浏览器或地址不继承。Android 应用偏好在本次安装的回环端口改变后继续生效，并在升级时继承原 4317 来源的选择。分叉世界独立；该偏好不进入 Authority、世界文件或模型请求。

## 4. 跑团机械判定与崩溃恢复

跑团与互动式小说运行在同一套游玩运行时上（[ADR-0043](../adr/0043-tabletop-gameplay-is-world-identity-and-runtime-derives-resolution.md)）：

- **玩法身份**：保存在 `control/gameplay.json`（`narraeon.gameplay/v1`），缺失即互动式小说。跑团包另指定判定方案（`d20`、`d100` 或基础混乱袋 `bag`）。内容包创建时选定模式不可切换，方案可在内容包阶段修改；世界创建时复制并固定，世界修订、控制编辑与归档导入后的世界均拒绝更改模式或方案。
- **工具与规则派生**：跑团世界每次正常发送由 Runtime 派生对应判定工具（`d20_check`、`percentile_check` 或 `bag_check`）以及辅助工具 `roll_dice`、`calculate`，并在世界占位处注入只读跑团规则块；互动式小说不获得任何判定工具。工具与规则块均独立于编排方案。
- **机械与语义分工**：Runtime 拥有随机、算术、比较、工具契约与结构化回执；AI 拥有行动目标、字段、数值、难度、世界规则、叙事与世界更新。判定成功须兑现声明目标，失败不得兑现，关键结果不得在抽样后改写；无效参数仅构成工具错误，不构成角色行动失败。
- **随机种子与崩溃恢复**（[ADR-0043](../adr/0043-tabletop-gameplay-is-world-identity-and-runtime-derives-resolution.md)、[ADR-0044](../adr/0044-runtime-is-single-process-and-recovers-by-retry.md)）：
  - 跑团随机种子**仅在单次工具结算的内存中现场生成，永不持久化到磁盘**。
  - 若判定工具在结算完成前遇到进程崩溃或中断，玩家重试该未完成步骤时会**重新生成随机种子并重新掷骰**。
  - 已经结算提交的工具结果与判定回执永久保留，不会因后续步骤失败或重试而重新抽样。
- **结构化判定回执**：随 `tool_result` 时间线事件持久保存，结构化记录目标、输入、掷出值、选定值、目标／难度、差值、结果与所用标记袋（不保存排版后的展示文本）。模型接收本地化文本，界面由结构化字段渲染单行可展开卡片。

## 5. 轮账本、权威提交与跨操作幂等去重

### 5.1 当前文件 + 按轮前像账本（ADR-0045）

- 世界目录中的 `state/`、`control/` 与 `history/` 即当前端点的权威内容，不再维护内容寻址副本或物化检查点。
- `worldId` 仅属于本地外壳；历史消息使用世界内局部身份，不嵌入 world 或 operation 身份。
- 每次推进（玩家消息、完整模型响应、世界修订应用 `revision_apply`、控制编辑应用 `control_apply`、回退 `rewind`）为独立一轮，轮号自 `1` 单调递增且**永不重用**，`commit:N` 为端点别名，`genesis` 为第 `0` 轮。
- 每轮在 `runtime/turns/` 写一条记录：轮号、模式、本轮改动 `state/` 与 `control/` 文件的前像（新建记空）、附加材料清单前像、追加的历史消息身份、叙事检查点声明、`playContext` 与 `worldClock`。
- **唯一推进与恢复顺序**：先写本轮记录 → 逐文件原子替换当前文件 → 最后推进 `runtime/head.json`。打开世界时若存在序号大于 `head` 的记录，说明该轮未完成，Runtime 用其前像恢复文件并删除记录。原子 `rename` 是唯一持久化保证，不为断电做 `fsync`。
- **单进程并发前提**（[ADR-0044](../adr/0044-runtime-is-single-process-and-recovers-by-retry.md)）：一个数据目录假定只有一个服务进程；对同一世界的语义写入在进程内按世界串行，读取不排队、依赖原子发布。已撤销跨进程世界锁、pid 存活检测、心跳与 Provider 结果重放回执（启动时顺手清理历史遗留 pid 锁文件）。删除世界前先中止该世界进行中的生成，再删除目录。

### 5.2 四类持久发布去重与游玩重复发送判定

以下四类幂等去重路径仍然有效并承担不同的持久化边界（不得与 ADR-0044 撤销的跨进程锁或 Provider 重放回执混淆）：

| 路径 | 持久化依据 | 重复提交且载荷匹配 | 同身份改载荷 / 冲突 |
| --- | --- | --- | --- |
| **1. 新建世界** | 目标世界 `publication.json` 保存 `operationId`、初始标题与 `sourceFingerprint`（标题 + 内容包全部文件） | 幂等返回已创建的原世界；**兼容仅按文件计算指纹的旧发布记录（`legacySourceFingerprint`）** | 拒绝（`operation_conflict`） |
| **2. 分叉世界** | 目标世界 `publication.json` 写入 `derivationRequestFingerprint` 与 `operationId` | 校验匹配后幂等返回已发布的分叉世界 | 拒绝（`operation_conflict`） |
| **3. 归档导入** | 优先读取确定性目标路径的 `publication.json` | 只要 `operationId` 与 `worldId` 匹配即直接幂等返回原导入世界——**既不要求临时上传 ZIP 仍在，也不会将新上传 ZIP 与先前已导入归档做内容比对** | 仅当目标 `publication.json` 中 `operationId` 或 `worldId` 与本次操作不匹配时拒绝（`integrity_failed`） |
| **4. 游玩重复发送** | 首发入口读取当前调用链持久保存的玩家事件 | `chainId`、`exchangeId`、玩家原文与上下文模式（`fresh`／`append`）全部相符时直接返回已有视图——**进程重启后同样可识别** | 拒绝（报错同一 `exchangeId` 已绑定不同文本或模式） |

## 6. 时间线修订、分叉与世界外修改机制

### 6.1 时间线修订（修改已提交玩家消息）

仅作用于当前世界，不创建新 `worldId`（[ADR-0032](../adr/0032-player-edits-append-current-world-timeline-revisions.md)、[ADR-0044](../adr/0044-runtime-is-single-process-and-recovers-by-retry.md)、[ADR-0045](../adr/0045-world-history-is-current-files-plus-a-turn-ledger.md)）：

1. 追加一轮 `rewind`，将 `state/`、`control/`、`history/` 与附加材料清单回退至目标消息的逻辑父端点，并删除被丢弃轮的记录（轮号不重用）。
2. 截断并删除这些轮之后的页面轨迹、模型上下文与玩法产物（`discardAfterHead`）。
3. 将修改稿作为一次普通发送提交。默认由 Runtime 在回退前选择可用的后续上下文，并在自动切到新对话时通知玩家。玩家可展开「修改后如何继续」手动指定：
   - **沿原上下文继续**：新 chain 身份保留逻辑父端点前的 transcript、Provider 原生续传与冻结绑定；
   - **作为全新上下文保存**：将修改点前轨迹封存为旧上下文前缀，用当前编排方案与模型绑定从父端点重新编译 bootstrap，修改稿作为唯一首条玩家 append（不读取旧 Provider 续传，旧上下文缺 durable binding 不受阻）。
   - 原上下文可续传时，未配置模型也可先保存修改，配置后留空继续。必须开启新对话且没有模型配置时，保存前提示配置模型，端点与当前故事保持原样。
4. 被替换的原消息及其后续不再保留，不可再从它们创建分叉。

### 6.2 创建分叉

唯一创建独立世界的历史操作（[ADR-0045](../adr/0045-world-history-is-current-files-plus-a-turn-ledger.md)、[ADR-0046](../adr/0046-artifacts-live-in-the-world-directory-as-stateful-records.md)）：

- 玩家可在任一已提交玩家或 AI 节点发起；Runtime 按轮账本复制所选端点所需的文件到暂存区，并用前像恢复 `state`、`control`、`history` 与附加材料。Runtime 调用 `forkArtifactClosure` 裁剪并重分配产物身份，再按账本校验当前投影，修复缺失或有差异的文件并移除多余文件。暂存区获得独立的扩展控制覆盖、来源脚本授权、世界身份与活动 chain 身份，最后一次原子 `rename` 发布。
- 世界管理可从当前进度创建独立分叉，时间线操作可选择历史端点。目标与来源不共享任何文件，删除来源后完全自足。分叉不调用 Provider 或重新执行工具，编排方案采用创建分叉时的工作区选择。默认名称在来源世界当下显示名称后加「 · 分叉」（英文「 · Fork」），占用时依次尝试「 · 分叉 2」「 · 分叉 3」等，过长只截短前面的来源名称。
- 若分叉节点属于持久游玩时间线，保留此前完整页面轨迹并截断所选上下文截至该节点的模型 transcript 与调用轨迹（含推理、工具参数与结果）；若截断后末项为玩家消息，玩家可留空，在输入区的「更多」中选择「接着当前对话继续」重新生成正文。

### 6.3 世界外修改机制对照

| 维度 | 世界修订 | 控制编辑 |
| --- | --- | --- |
| **官方定位** | **主路径与后续演进目标**（[ADR-0038](../adr/0038-world-revision-uses-one-locked-worktree.md)） | **保留的高级人工修改入口** |
| **何时开始排斥冲突操作** | 进入修订页仅只读不锁定；**首次实际文件编辑（`world.revision.files.replace`）或发送首条消息（`world.revision.message`）**创建持久 epoch 时起锁定 | 仅在 `save`／`apply` 单次调用执行期间占用进程内按世界串行；草稿存在本身不锁定游玩；`apply` 时若存在进行中游玩／修订锁则被拒绝 |
| **排斥范围** | 游玩、时间线修订、控制草稿保存与应用、分叉、导出、删除世界（只读检查、故事导出与本地重命名仍可用） | 单次写入调用期间按世界串行互斥，无持续排斥 |
| **何时释放** | `world.revision.apply`（`revision_apply` 轮落盘且 epoch 标 `applied` 后）或 `world.revision.discard` | 当次 `save`／`apply` 调用结束立即释放（`apply` 成功后删除 `runtime/control-draft`） |
| **进程重启后是否保留** | **是**（持久 epoch 与非过期独占锁跨刷新与重启保留） | 草稿目录 `runtime/control-draft` 留盘，但**无跨重启互斥锁** |
| **Runtime 命令** | `world.revision.*`（`open` / `overview` / `preview` / `status` / `files.replace` / `rollback` / `apply` / `discard` / `session.*` / `message` / `message.edit` / `cancel` / `resume` / `call.context` / `request.preview`） | `world.control-draft.save`、`world.control-draft.preview`、`world.control-draft.apply` |
| **当前 Web 可达入口** | 世界页「世界修订」工作区 | 世界页「世界控制 · 高级编辑」折叠面板 |
| **可达能力** | 手动编辑与 AI 对话共享 `state/*` + `control/*` 工作树，支持逐文件回滚、历史只读导航与预览后原子应用（不可改 `control/gameplay.json` 与已提交 `opening.md`） | 按文件编辑 `control/*` 的本地草稿，复用框架和玩家视图表单，预览后整批原子应用为 `control_apply` 轮（不可改 `control/gameplay.json`） |

高级控制编辑保存后返回草稿指纹。Web 预览携带该指纹，确认应用时携带预览中的同一指纹。若草稿已被替换或移除，操作以 `operation_conflict` 拒绝，端点和轮账本保持原样，当前浏览器保留编辑文字供重新预览。应用在原有的单次按世界串行窗口内，使用读到的同一份草稿和最新世界状态再次校验。已发布 v1 客户端可继续省略 `expectedFingerprint`，沿用按当前保存草稿预览或应用的行为。

> 世界名称重命名仅原子替换世界本地外壳，不改写创建记录或 Authority，与上述两种语义写入正交。

旧 `correction.*` 写入协议由世界修订取代。向 `/api/runtime/v1` 发送这些命令返回 HTTP 400，错误码为 `invalid_request`。已发布归档或本地世界中的 `correction` 轮、前像和冻结请求继续通过历史路径读取。旧格式迁移按 [#244](https://github.com/narraeon/narraeon/issues/244) 的发布边界处理。

## 7. 世界备份归档、故事导出与旧格式迁移边界

### 7.1 世界备份归档（`.narraeon-world.zip`，ADR-0042 / ADR-0045）

- **内容边界**：包含完整故事、当前 `state/` 与 `control/`（含 `control/gameplay.json`）、轮账本、页面调用轨迹及保留的冻结产物与资源；**不包含**模型连接、API Key、工作区编排方案、应用偏好、未应用的世界修订、作者会话与 `runtime/activity.json` 本地缓存。
- **导出**：要求世界空闲且无活动世界修订；实质为分叉到导出暂存区后按条目流式打包，下载完成或 1 小时到期清理暂存。
- **隔离导入**：上传上限 **1 GiB**，解压总量上限 **2 GiB**，最多 **200,000** 条目，单条目上限 **256 MiB**（上传暂存区并发保留上限 32 文件 / 2 GiB，上传完成 1 小时未导入自动回收）。拒绝未知格式、符号链接、特殊文件、非 UTF-8 文件名、绝对／穿越路径、重复及大小写冲突路径。解压至临时隔离区完成安全、体积、账本结构校验与必要旧格式迁移后，以分叉方式原子 `rename` 发布为新独立世界（同一归档可多次导入，各自获得独立 `worldId`）。启动时清理遗留上传、隔离区、导出目录与未完成导入 staging。
- **导入后边界**：保持原世界名称、玩法模式／判定方案与扩展开关，来源脚本授权清空为未授权。每个导入上下文在不可变小 index 中永久标记禁止旧 Provider 续传（分叉与保留前缀修改继承该标记）；旧轨迹供阅读、修改（仅能用新上下文）与分叉，本机首次游玩须以当前连接开启全新上下文，本机新建链可正常继续。

### 7.2 故事导出

世界管理中的「导出故事」允许玩家显式下载 Markdown 或纯文本：

- 从已接受的当前端点按当前时间线顺序导出开场白、玩家原文与最终主持正文，保留段落与空白；玩家输入带界面语言前缀（「我」／`Me`），Markdown 用标题与引用块，纯文本用普通标题与前缀。
- 不含历史背景、工具中间步、返回推理、usage、上下文分隔或检查点，也不读取页面／模型轨迹；修订仅导当前可达正文，分叉含继承前缀。
- 该只读操作在世界修订锁定时仍可用，不增加首屏读取或权威提交。

### 7.3 旧存储格式升级与停止迁移边界（ADR-0034 / ADR-0045 / ADR-0048）

- **自动一次性原子迁移**：首次打开由 v0.3.0–v0.6.0 创建的世界时，Runtime 在该世界的串行操作内按明确版本执行迁移：
  - Authority V3 世界从 `genesis` 逐提交恢复端点、按相邻差异生成每轮前像记录、写出当前文件与 `head.json` 后删除 `authority-v3/`（保留 `commit:N` 与历史消息身份不变）；
  - 游玩布局缺少 `runtime/play-timeline-layout.json` 时，按 [ADR-0048](../adr/0048-play-contexts-keep-one-request-and-reference-prompt-snapshots.md) 将续传引用请求移入上下文目录、折叠重复运行快照、清理多余编码并删除旧 `runtime/play-requests/` 后写入完成标记；
  - 产物旧布局迁移见 [玩法扩展与产物规格 §4.4](extensions-and-player-views.md#44-旧布局一次性迁移)。
  - 任一迁移中途退出时旧源完整保留，下次打开幂等重做；完成后只读写当前格式。
- **停止迁移边界**：v0.1.x（V1）与 v0.2.0（V2）世界存储不再由当前 Runtime 直接迁移，须先经 v0.3.0–v0.6.0 打开一次再升级；无法升级或损坏／未知格式的世界一律 **fail closed**，显示为不可打开且绝不改写原文件。
