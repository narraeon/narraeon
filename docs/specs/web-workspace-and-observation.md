# Web 工作区、路由、对话观察与前端状态同步规格

本规格定义浏览器端 Hash 路由与草稿保护、视觉与信息分层、首屏加载边界与首页活动缓存、统一 SSE 对话观察、调用详情投影、上下文窗口占用提示、输入快捷键以及前端命令／读取同步模型，对应代码模块 `src/web/` 与 `src/server/`，并承接 [ADR-0019](../adr/0019-v1-uses-a-typescript-node-local-web-stack.md) 与 [ADR-0049](../adr/0049-frontend-command-results-and-projections.md)。

## 1. Hash 路由、导航锁与工作区布局

### 1.1 Hash 路由表

页面位置以 Hash 地址保存，**仅编码页面名与本地身份**，世界页内部面板不进入地址：

| 页面 | Hash 地址 | 备注 |
| --- | --- | --- |
| 工作区首页 | `#/` | 直接展示世界与内容包列表 |
| 世界页 | `#/world/<worldId>` | 内部子面板不写入 Hash |
| 内容编辑 | `#/content/<packageId>` | 缺少内容包身份的地址绝不自动新建内容包 |
| 编排方案工作台 | `#/orchestrations`、`#/orchestrations/<id>` | 列表地址默认显示当前方案，详情地址打开指定方案 |
| 新建世界 | `#/create` | 预览所选内容包已保存开场；切换来源立即使旧预览失效 |
| 提示词预览 | `#/preview` | 只读真实编译器预览 |
| 模型连接 | `#/models` | 工作区设置，非第五个内容任务 |

- **旧书签**：v1.0.0 识别 `#/presets` 与 `#/presets/<id>`，用对应的新地址替换原历史项。后续移除边界见 [#244](https://github.com/narraeon/narraeon/issues/244)。
- **历史与草稿保护**：刷新与书签恢复对应页面；跨页切换追加浏览器历史，同页内选择替换当前地址；未保存修改（文件、编排方案、模型配置、世界修订）或其他导航锁拦截浏览器后退／前进时，立即恢复原地址并提示；目标不存在时返回首页并提示。移动端沿用相同入口与保护策略。
- **暖白文稿工作区原则**：前端统一采用暖白底色、细分隔线、紧凑控件与清晰文字层级。设定完善与游玩以对话和正文为主体，文件、历史、模型参数说明与管理详情按需展开。全局导航不提供隐式选择某个世界的「游玩」入口，已有世界一律从明确命名的世界条目进入。设定完善快捷创建世界时，未保存文件、运行中请求、待修复内容与重复点击均不得绕过创建前检查。
- **页头模型连接切换**：页头显示当前活动连接名，点击打开连接设置；存在其他已保存连接时，旁侧下拉箭头支持按名称与模型 ID 原地切换，保留当前页面与输入。在途模型请求及工具往返沿用发送时捕获的连接，新选择从下一次主动发送起生效。

## 2. 故事模式、详细模式与首屏边界

### 2.1 故事模式 vs 详细模式

- 世界页默认采用**故事模式**，阅读设置中的「显示技术信息」开关可即时切换为**详细模式**，并与其他阅读偏好一并保存在本机。
- 故事模式保留开场白、玩家原文、主持正文、玩家视图、玩法产物、待定输出以及需处理的失败／取消状态，隐藏调用详情、派发标签、历史检查点标记与机制说明；模型上下文起点仅显示细分隔线。
- 正文操作（「修改」「创建分叉」等）在桌面端悬停或聚焦时显示，在触屏与窄屏设备上始终可见。

### 2.2 世界页首屏完成边界

世界页首次打开以「故事立即可读」为完成边界，严禁为计算「完整对话」而在首屏遍历 Authority、读取全部模型上下文或重放全部工具记录：

1. 首屏仅拉取**当前端点**、**玩家视图**与**最近 40 项页面时间线摘要**并立即渲染；
2. 更早时间线由玩家显式点击「加载更早」按稳定游标向前分页读取（普通尾部追加不改写旧页或旧事件）；
3. 工具参数／结果、Provider 返回推理与 usage provenance 详情在展开单项时按需读取；
4. 世界文档与 Runtime 诊断仅在进入对应面板／页面时读取；
5. 玩法产物与调试投影在首屏之后独立加载。

### 2.3 首页「继续游玩」与 `runtime/activity.json` 本地缓存

- 首页「继续游玩」按世界最近接受端点的本地活动时间倒序排列，显示相对时间、当前时间线最后一段主持正文的**前 80 个 Unicode 码点**摘录及已提交玩家回合数。
- `runtime/activity.json` 是可重建的本地显示缓存，**不进入模型请求、世界状态、Authority、分叉闭包或世界归档**。
- 创建、游玩、时间线修订、世界修订应用与目标分叉在物化后尽力更新该缓存；缓存写入失败绝不改变提交结果。
- 正常列表仅读取小型 head 与缓存，不遍历 Authority 或完整历史；缓存缺失、损坏或端点过期时，由物化历史文件名重建回合数，仅读取最后一份主持文件重建摘录并写回。无法恢复活动时间的世界留空并排在末尾按世界名称排序。

## 3. 统一 SSE 对话观察与运行进度

普通游玩、内容包设定完善与世界修订共用浏览器对话观察模块：

- **读写分离**：发送与显式取消使用 Runtime 命令；实时进度与增量通过独立只读 SSE 连接接收。服务端由 Runtime 状态变更驱动推送，心跳仅作保活；慢观察者使用有界缓冲，必要时断开并触发客户端重同步，绝不阻塞 Provider 或权威结算。
- **重连与状态安全**：首次连接与重连先拉取当前快照，连接序号仅用于防止重复与缺口（非持久事实或模型续传）；后续增量只属于该次连接。断线、关闭页面或重连均不取消生成、不重发消息，也不覆盖尚未保存的本地文件草稿；连接故障与模型失败分开提示，本地耗时钟继续推进。
- **快照缺口退避**：客户端因跨 epoch 或跳号的增量主动重建连接时，首次等待 200 毫秒，连续缺口使等待时间翻倍，最多 5 秒，收到有效快照后复位。每个观察目标同时最多有一个待执行的重连计时器，关闭或切换目标时取消等待。网络断线仍由 EventSource 重连。
- **运行阶段诚实呈现**：生成期间持续展示 Runtime 拥有的当前阶段、总耗时、最近一次数据距今时间、Provider 派发数，以及返回推理／正文／工具参数和工具调用累计量；刷新页面后仍从同一 Runtime 进程恢复该观察。
  - **仅在收到 Provider 明示的 reasoning 增量后**才显示「思考中」；首个可区分增量到达前须诚实说明排队、模型内部处理与网络等待尚不可区分。
  - 连续 **90 秒**无新数据时提示「可能卡住」，不得断言模型内部状态。
- **待定流式与返回推理**：响应完成前的流式正文明确标作待定输出、不晋升故事、不主动改变玩家当前滚动位置；完整响应无工具调用时晋升为正式叙事，含工具调用时收进默认折叠的技术轨迹。生成中的返回推理可在当前响应下就地展开，随 SSE 增量实时更新并由重连快照恢复，不等待响应完成。

### 3.1 第一方调用与 v1 HTTP 兼容

| 入口 | 用途 |
| --- | --- |
| `GET /api/runtime/v1/events` | 网页与 Android WebView 用它观察游玩、设定完善与世界修订的进度。游玩命令回包丢失时，当前观察已确认同一调用链与 exchange 就复用该快照，省去一次 `play.chain.inspect`。 |
| `play.chain.inspect` | SSE 不可用或尚未确认本次 exchange 时，网页可单次查询。CLI 退出探针也用它在重启后核对持久记录，SSE 性能探针用它预热有订阅及无订阅样本。 |
| `world.read`、`play.timeline.page`、`setting-improvement.overview`、`world.revision.overview` | 页面首屏、手动读取、分页及故障恢复仍按需读取持久投影。作者工作区的 overview 也提供工作树、会话列表或修订状态等同步所需内容。 |
| `setting-improvement.read`、`setting-improvement.status`、`world.revision.status` | 已随 v1 HTTP 发布的只读入口。当前第一方页面没有用这些入口轮询生成。 |
| `play.chain.start`、`play.chain.append` 及作者生成命令 | 主动派发并交付命令回执。浏览器提交使用普通 JSON，未订阅 SSE 的客户端也能生成并取得最终回执。取消由对应的显式命令按调用身份执行。 |
| `Accept: application/x-ndjson` 下的 `play.chain.start`／`play.chain.append` | 已随 v1 HTTP 发布的可选命令回包。旧调用方在同一请求收到增量与终态帧，CLI 退出探针对完整 EOF 和重启后的结果继续验收。 |

**HTTP 兼容退役发布计划**。在待定发布版本中为旧只读入口与 NDJSON 公布迁移方式，覆盖 SSE 观察、JSON 派发与取消、无订阅回执和错误处理。现有 v1 路径在弃用窗口内与替代路径并行。窗口结束后，通过有版本标记的协议变更退役旧入口；若仍需提供单请求流式终态，版本化方案须保留最终回执与完整 EOF。继续满足 [#279](https://github.com/narraeon/narraeon/issues/279) 验证的在途响应行为。

## 4. 「本段调用详情」、失败警报与上下文占用提示

### 4.1 「本段调用详情」统一投影

游玩技术信息、设定完善与世界修订均以**单次用户发送**为单位，在正文下提供默认折叠的「本段调用详情」：

- 按逻辑步骤列出主链与具名后置请求（含纯正文调用），外层仅统计模型步骤数，不统计重试次数。
- **每步仅显示当前或最新尝试**：下一次实际派发时，从公共对话、分页、调用详情与上下文读取中移除被取代的失败尝试及其报错，不保留历史尝试入口、旧尝试计数或调用／重试编号标题（刷新、重启与旧存档公共投影沿用同一规则）。恢复所需的内部事件身份、前驱关系、已确认命令收据、已结算工具回执及不同步骤均保留。游玩新记录按同上下文重试前驱事件归组，旧记录仅在连续未完成且重试序号有明确证据时归组；不同发送、工具步骤、已完成回复、上下文与后置请求绝不合并。
- 每次尝试提供同级子项：**「本次上下文」**、**「模型推理」**、**「工具调用」**、**「调用量详情」**。
  - **「本次上下文」按需拉取**：仅在展开该项时发独立只读请求读取历史逻辑提示、初始材料、对话、工具交换与本次尾部提示（首屏、分页、实时观察、开启详细模式与展开外层详情均不预取全文）。读取校验历史快照、前缀与当前可达范围，省略凭据与不透明续传载荷；旧记录缺完整派发证据时仅展示已有部分并标明。
  - **「模型推理」**：仅展示 Provider 返回的文字或摘要，未返回明确标记；不透明或加密推理不向玩家投影。
  - **「工具调用」**：按执行顺序就地展示参数、结果、工具步骤正文以及已有文件差异与回滚按钮（标明内容包当前树或世界修订工作树生效位置）。
  - **「调用量详情」**：始终展示 7 项 usage 与 provenance（缺失标「未报告」，实零保 `0`，旧记录标「未记录本次用量」）；创作对话另展示会话累计统计。

### 4.2 失败警报撤下与多失败后置合并

- 开始重新发送时**立即撤下**上次失败的当前顶层警报，且下一次实际派发会按 §4.1 规则从公共对话、分页、调用详情与上下文读取中隐藏／移除同一步骤被取代的失败尝试及其报错（仅保留当前或最新尝试）；未被取代的其他发送或不同步骤的失败仍保留在各自对应步骤的调用详情中，底层亦继续保留恢复与诊断所需内部证据。运行中与成功后不再把旧失败冒充当前错误；本次重试再次失败仅展示本次错误，在产生新调用事件前被拒绝时展示本次拒绝原因。
- OpenAI Responses 流式失败的技术详情保留 Provider 实际返回的有界错误消息、类型／错误码、请求身份与终态原因，缺少字段时仅展示已知事件或状态。
- 自动退避尝试不追加顶层失败卡，仅在当前进度原位展示临时等待并在成功或进入下一步时撤下；耗尽后沿既有单条最终错误与恢复动作呈现。
- 同一回合（同一回复身份）的多个失败后置请求在正文合并为一条数量摘要，展开后保留各请求名称、失败原因与尝试信息；成功后置不计入，已提交剧情照常显示。

### 4.3 上下文窗口占用提示（85% 阈值）

- 世界页输入区展示当前调用链最近一次完整 AI 响应的**实报输入量**占冻结模型窗口的百分比；未报告输入量、旧记录无冻结窗口、新上下文尚无完整响应，或下一次发送已准备开启全新上下文时均显示「—」并说明原因（不使用估算或累计 usage）。非零且不足 `1%` 时显示 `<1%`。
- 占用达到 **85%** 时提示建议下一条使用全新上下文；快捷按钮仅准备下一次发送，不阻断玩家继续追加；开启全新上下文后旧提示消失。该信息仅用于 UI，不进入模型请求、上下文准入或检查点选择。

## 5. 输入快捷键与前端命令／读取同步契约

### 5.1 对话输入快捷键与 IME 保护

游玩、设定完善与世界修订三个对话输入框统一遵守：

- 桌面端：`Enter` 发送，`Shift + Enter` 换行；`Ctrl`／`Meta + Enter` 保留为发送别名。
- 以触屏为主且无悬停能力的设备：`Enter` 保留原生换行，通过发送按钮提交。
- 完整保护中文等输入法（IME）合成与选词确认不误触发发送，防止按键长按重复与同步重复提交。
- 快捷键与发送按钮调用同一提交动作；游玩允许空输入续写／重发，设定完善与世界修订拒绝空白消息。

### 5.2 前端命令结果与页面读取分离（ADR-0049）

传输模块解码各自协议响应，保留 HTTP 状态、Runtime 错误码与结构化详情。页面严格区分「命令已完成到哪一步」「当前页面读到了哪个版本」与「用户可执行何种后续动作」：

| 界面获得的证据 | 界面行为 |
| --- | --- |
| 收到命令回执 | 立即采用已确认结果；需要完整列表、文件或详情时再发只读请求；后续只读失败保留回执并提示同步问题 |
| 回包丢失，权威记录含本次提交标识（游玩 `exchange` / 作者 `request` 与会话） | 按持久记录恢复已接受、进行中或终态 |
| 仅可读到旧记录或核对亦失败 | 保留未确认输入，诚实说明通信问题（不把相同文字或同一页面误判为本次操作） |
| Runtime 确认模型调用中断 | 按返回原因与能力提供重发、续写或切换上下文，由用户决定是否再次调模 |
| SSE 断开或快照刷新失败 | 保留最后一次有效显示，单独提示连接／同步状态；后续有效投递清除提示，切换目标丢弃旧读取 |

- **只读恢复边界**：每个页面目标以统一只读加载入口承接首次加载、手动重读、命令失败核对与 SSE 异常恢复。普通只读失败自动恢复 1 次；仍失败时保留最后有效画面与草稿，提示「暂时无法同步」并提供只读「重新加载」。**写命令与一次性操作（文件导入、导出、原生下载、向模型端点拉取清单）绝不纳入自动重试**，出错后仅只读刷新相关工作区或配置，由用户显式再次发起。
- **竞态收敛**：同一目标合并重叠恢复请求，故障前已在途的读取不得替代故障后新读取；局部回执使较早读取失效但不取消尚待完成的完整页面读取；完整有效观察使较早读取的成功与错误一并失效；目标关闭后丢弃一切迟到结果与错误；SSE 重复断线通知合并为一次断线处理，重建后再次断线才触发新一轮恢复。读取证明对象已删除时同步修正详情与路由；Runtime 明确拒绝保存或预览时在原表单保留原因。
