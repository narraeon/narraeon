# 玩法扩展、后置请求、玩家视图与产物持久化规格

本规格定义后置请求编排、世界级扩展开关、来源脚本授权、玩法产物持久化与分叉闭包、工作台资源克隆与正则／JSON 校验、玩家视图及前端扩展宿主桥接，对应代码模块 `src/runtime/artifact/` 与 `src/runtime/extension/`，并承接 [ADR-0028](../adr/0028-artifacts-project-through-a-trusted-frontend-host.md)、[ADR-0030](../adr/0030-production-play-is-one-model-directed-call-chain.md)、[ADR-0034](../adr/0034-released-storage-formats-require-atomic-migrations.md) 与 [ADR-0046](../adr/0046-artifacts-live-in-the-world-directory-as-stateful-records.md)。

## 1. 后置请求编排与派发契约

### 1.1 编排方案内后置编排

后置编排与纯界面扩展随 `orchestration.yaml` 和资源文件组成同一修订。旧库迁移保留历史后置定义及资源，使冻结请求和旧产物继续使用原绑定。当前格式的后置顺序由 `narraeon.play-call-chain/v2` 的 `followupItems` 保存。


- 后置请求在游玩提示编排分隔线下独立排序（支持拖拽、上移／下移与 `Alt` + 方向键）；请求提示词、多产物声明、显示位置、模板／脚本／资源与保存策略集中在右侧编辑，普通新增正文与渲染资源由编辑器分配路径。
- **条目来源**：
  - **用户后置请求**：保留稳定身份、名称、默认启停与完整产物资源；停用保留全部定义与资源，保存后的新运行快照仅编译启用项。
  - **系统场景回顾示例**：正文跟随应用最新版，完整定义只读不可删除，可关闭、排序或克隆为独立用户定义；对旧编排方案默认关闭，不自动增加模型调用。
  - **内置扩展**：行动选项、Markdown / HTML 面板和产物调试器示例在每份编排中固定可见，初始均关闭。可逐项设置方案默认、排序或复制成可编辑的独立请求。每项在主叙事提交后额外派发一次模型请求；启用本身不派发。旧文件中保存的完整推荐编排继续按原有用户条目运行。缺少内置条目的旧文件会把它们显示为关闭，冻结绑定保持原样。
  - **内容包后置组占位（`package:followups`）**：不可删除或编辑正文，可关闭与排序；无来源声明时为空组。
- **格式演进**（[ADR-0034](../adr/0034-released-storage-formats-require-atomic-migrations.md)）：`narraeon.play-call-chain/v1` 保持原解析以恢复历史绑定；工作台投影为默认启用的用户项、默认关闭的系统示例与空内容包组（包组位于原用户项之后），显式保存后升级为 `narraeon.play-call-chain/v2` 的有序 `followupItems` 引用。系统和内容包占位使用含冒号的保留作用域，避免与用户 ASCII 身份碰撞；已升级方案禁止降级移除只读项。

### 1.2 内容包后置请求（`control/followups.yaml`）

- 内容编辑的文件面板提供「内容包后置请求」入口，支持创建、改名、排序、启停、编辑提示、多产物与渲染资源；禁用保留完整定义。
- 可选文件 `control/followups.yaml` 使用 `narraeon.package-followups/v1`，有序 `followups` 数组每项包含稳定 `id`、`displayName`、布尔 `enabled`、`mount`、`prompt`、`artifacts` 与 `maxArtifactBytes`；提示与渲染资源路径相对 `control/`，均为 UTF-8 文本。
- 未知字段、重复身份、损坏声明与缺失资源（含禁用项）均阻止创建世界、导出或应用世界修订；导入后的待修复包保留明确诊断。
- 编译在编排方案 `package:followups` 占位展开当前世界自有请求，保持包内顺序并过滤组或单项禁用；包请求与频道使用 `package:` 来源作用域，产物输出名局部于请求，显示名与资源路径不决定身份；每请求仅冻结自身引用的完整资源，源包后续修改或删除不影响已有世界与历史显示。

### 1.3 串行派发与工具边界

- 主叙事成功提交后，按编译冻结的有序后置清单**串行派发**；各请求共享同一份冻结主链前缀与冻结工具定义（含 `artifact_emit`、`artifact_clear`），由 Runtime 授权仅调用声明的产物工具（见 [模型 Provider 规格 §4.3](model-providers-and-resilience.md#43-allowed_tools-阶段白名单)）。
- 各后置请求之间互不可见、不共享输出，不追加主链 transcript，也不推进世界 Authority；单次后置响应可多次调用 `artifact_emit`，不按产物增发请求。
- 对声明了 `payloadContract` 的 JSON 产物，Runtime 在 Prompt Preview 和实际派发的后置提示中列出完整契约，包含所有嵌套数组元素与对象字段的类型、必填项和约束。模型把符合契约的 JSON 值传给 `artifact_emit` 的 `payload`，Runtime 按同一冻结声明校验后才接收产物。
- 后置请求失败时保留已提交剧情，通常继续派发剩余后置请求。ChatGPT 套餐请求失败时结束该轮剩余后置请求。取消生成会取消剩余未派发或等待中的后置请求。

## 2. 世界级扩展选择（`extension-controls.json`）

- 世界页输入区附近的「世界扩展」菜单分别列出**后置请求**与**不调用模型的纯界面面板**；Runtime 从完整定义枚举名称、来源、默认状态与当前世界有效状态。内容包整组与单项分别可选，组关闭优先但保留子项选择。未覆盖项跟随定义默认，明确覆盖仅属当前世界，恢复默认删除覆盖。
- 菜单只展示有条目的分类和有子项的内容包分组。点击菜单外部可关闭，按 `Esc` 关闭后焦点回到入口。
- 内置扩展可组合使用。世界覆盖与方案默认分别保存。后置条目各用独立请求和频道，沿用现有冻结、取消和产物规则；同时存在同用途的旧用户条目时，两份只会各按自己的开关派发。方案默认随编排文件复制、导出与导入，脚本权限沿用已建立的本地权限规则。
- 请求与面板身份独立于名称与排序；新建项获得新身份，删除旧定义后同名新项不继承旧选择。
- **存储与失效语义**：世界外壳的 `extension-controls.json` 保存覆盖、可见代际与独立通知版本，不进入编排方案、内容包、`control/` 或 Authority：
  - 新发送编译有效请求并冻结各请求代际；工具循环与合法原样重试保留原运行快照；源定义的默认启停或删除仅影响下一次发送。
  - 在世界菜单明确关闭某后置请求时，**立即使对应旧代际不可见**，跳过尚未派发的该请求，并尽可能中止该请求独立的 Provider 信号；其余请求与已提交剧情不受影响。迟到输出仅留作诊断，不得激活显示或执行有效清除。
  - 关闭后再开启不补跑本轮、不恢复旧产物、不调用模型，仅在下一次正常发送产生新输出。
  - 纯界面面板重新开启直接读取当前字段。内置状态栏关闭时恢复原玩家视图；已有自定义面板保持原有接管规则。
  - 状态变更推进独立扩展通知版本，即使无游玩调用链或端点未变化亦刷新页面。世界刷新与 Runtime 重启保留选择；分叉在目标 staging 复制独立覆盖与代际。启用请求永不授予脚本权限；切换编排方案不重写旧运行的冻结代际或资源。

## 3. 来源脚本授权

- 内容包与世界的脚本授权由 Runtime 分别保存在各自本地外壳，**按资源确切内容指纹绑定**，不得由便携文件声明授予，也不进入 `control/`、Provider 请求、ZIP 或 Authority。
- 新建、导入和复制的内容包默认无脚本授权；用户在「内容包脚本权限」或世界管理同名入口显式授权当前已保存资源，或撤销全部授权。
- **严格来源隔离**：可信编排方案不能授权内容包代码；启用后置请求不授予脚本权限；资源代码发生任何变化均无法沿用旧授权；撤销全部授权立即对来自该来源的全部历史脚本呈现生效，且不改写原始产物记录。
- 创建世界时，将当时匹配包资源的本地授权随控制树一并 staging 发布；分叉复制来源世界许可，之后各自独立；世界归档导入一律恢复为未授权。
- 脚本执行仍受应用模式与 iframe 规则约束；无脚本授权时 HTML／CSS 仍正常渲染。授权操作不调用模型，不推进 Authority；世界内修改脚本源码或默认启停须经世界修订。

## 4. 产物持久化、正文归属、分叉闭包与旧布局迁移

### 4.1 世界目录内状态化记录（ADR-0046）

玩法产物保存在世界目录 `worlds-file-native/<worldId>/artifacts/` 中，与 `state/`、`control/`、`history/` 同处一目录，**不再使用事件日志**：

- **产物记录**：每条产物为独立文件 `artifacts/records/<sequence>.json`，自带状态 `status`（`pending`、`active`、`superseded`、`cleared`）、绑定核心端点 `head` 及清除信息 `clearedBy`；状态更新通过临时文件加原子 `rename` 就地完成。读取直接扫描并校验目录内记录，无需事件回放。
- **Operation 文件**：`artifacts/operations/<sha256(operationId)>.json` 保存扩展状态显示与冷恢复所需上下文。
- **清除与跨尝试回滚**：清除操作直接把匹配记录置为 `cleared` 并在记录上写入 `clearedBy`（operation、request、attempt 与清除前状态）；同一 operation 内同一请求的更高 attempt 注册时，将对应记录恢复为清除前状态，保留「失败尝试不留下清除」语义。过期清除仅返回忽略结果，不写账本。
- **回退裁剪**：时间线修订回退时，`discardAfterHead` 按文件删除端点序号大于回退点的记录与 operation 文件。

### 4.2 正文附件归属与活动产物投影

- 正文附件通过扩展记录中的稳定上下文、回复事件与发送身份关联实际生成它的 AI 回复。Runtime 仅查询相关时间线摘要确认归属，先排除被时间线修订舍弃的剧情，再应用频道策略（追加、替换、按键更新、暂显或隐藏）；加载更早页面只补显对应回复，不改变归属。行动建议按钮交互仅填入输入草稿，仍需玩家主动发送；侧栏等挂载位置展示各请求的生成、更新或失败状态。
- 编排方案、内容包和界面预览共用同一套显示位置名称。`sidebar` 为世界页的「此刻侧栏」。`composer_above`、`composer_below` 分别在输入框真实的上方和下方显示各自的活动产物、玩家视图面板和请求状态。每处只在有内容时显示，默认收起，展开后的区域可独立滚动。收起界面不清除活动产物或草稿。
- 随回复保存的产物采用持久保存与对应保留策略；暂显结果沿用新运行、端点变化、运行结束或显式清除失效。旧记录缺少明确回复归属时不猜测挂正文，保留原始产物诊断并提示无法自动迁移为附件。
- 活动产物投影独立于轻量世界读取：页面在后置结算（含失败）、调用链状态或端点变化、SSE 重连与世界重读时补取活动产物及诊断；流式文字增量不触发补取。扩展读取仅接受当前世界与端点的最新响应，轻量读取中的空产物字段不得清空已加载投影。刷新不派发模型请求，也不推进 Authority。
- 配置的扩展呈现按正文、Now 侧栏、输入框上方、输入框下方、浮层和调试区提供位置与单项两级展开。正文的总开关同时控制已显示回复里的附件，附件留在所属回复。收起位置保留其各项的展开选择；当前页面按世界、位置和项身份隔离这些选择，投影刷新保留同一项的选择。收起只改变可见性，脚本、授权、世界扩展开关、原生正文和控件沿用各自的规则。

### 4.3 界面挂载

- `story` 正文附件出现在所属 AI 回复下，`sidebar` 产物与玩家视图出现在「此刻」状态栏。`composer_above` 与 `composer_below` 分别位于行动输入框上方与下方。
- 内置行动选项与工作台新建行动按钮示例建议使用 `composer_above`，便于玩家先看选项再写草稿。内容包和编排方案的显式位置及已保存的冻结呈现继续使用记录中的位置。
- 存在 `overlay` 内容或生成状态时，世界阅读工具提供「浮层」按钮。浮层初始收起，主动打开后内容可独立滚动，正文仍可操作。关闭按钮、浮层控件上的 Escape 和浮层外点按均可收起浮层。工作台使用同一个浮层宿主预览，预览中无需更改世界或阅读设置。
- `debug` 产物与产物调试器随阅读设置中的「显示技术信息」在故事下方展示。

### 4.4 分叉与归档的产物闭包发布

按 [ADR-0046](../adr/0046-artifacts-live-in-the-world-directory-as-stateful-records.md) 与当前实现（`FileNativeArtifactStore.ts:1481` `forkArtifactClosure`），分叉与备份直接随世界目录在 staging 中就地完成产物改写与原子发布，不再存在外置独立产物存储的延迟展开路径：

1. `FileNativeWorldStore.deriveWorld` 把所需文件复制到暂存区并恢复目标分叉端点后，在未发布的暂存副本上调用 `forkArtifactClosure`。
2. `forkArtifactClosure` 仅保留同时满足以下条件的记录及关联 operation 文件：`save === "commit"`、`status === "active"`、非 `hidden`（`transient` 仅在原交互仍活跃时保留）、已附着于回复（`attachment` 存在）、通过频道投影选中，且绑定端点序号不晚于分叉端点。
3. 逐文件删除其余记录与 operation 文件，并将保留记录与 operation 的 `worldId` 改写为目标世界身份、`operationId` 改写为 `artifact-fork:<targetWorldId>:<sha256(原 operationId)>` 并重算记录指纹。
4. 目标世界随一次原子 `rename` 发布，完全自足，删除来源世界不影响该闭包，且不新增 Authority 提交。

### 4.5 旧布局一次性迁移

- v0.6.0 外置 `artifact-store/` 布局，以及旧版未展开的 `runtime/artifact-fork.json` 分叉快照，统一由 `LegacyArtifactStoreMigration`（`LegacyArtifactStoreMigration.ts:28`）在世界首次访问时执行一次性可重入迁移（[ADR-0034](../adr/0034-released-storage-formats-require-atomic-migrations.md)）。
- 迁移按原事件回放规则折叠算出每条记录的最终状态与端点，写入世界目录 `artifacts/` 后再删除旧记录、事件、`runtime/artifact-fork.json` 与 operation 文件；全部世界迁走后删除旧 `artifact-store/` 目录。目标未写完前不删旧源。

## 5. 工作台资源编辑、克隆闭包与正则／JSON 契约

- **产物调试器示例**：可在当前方案或当前世界启用，向 `debug` 挂载发送一条暂存 Markdown。显示技术信息时，世界页的通用产物调试器可查看扩展状态和原始产物。单项复制保留该示例的定义，可在现有方案中独立编辑。
- **产物声明字段**：`name` 为请求内稳定提交名；`displayName`（友好名）与 `purpose`（生成用途）为可选声明字段（旧声明不补默认值，不改写冻结历史）。修改友好名与排序不改变提交名、频道或旧记录；`purpose` 作为作者指令随对应 output 一并进入生产编译。
- **克隆请求与资源闭包**：克隆后置请求时分配独立请求身份、频道与资源闭包，保留原提交名、显示配置与原有挂载；同一副本内共享资源与共享频道各自仅分配一份，多次克隆相互独立，源码中的完整静态本地资源路径随副本一次改写。闭包从请求提示与产物声明出发递归收集源码引用，缺失文件时整次克隆拒绝并保留原草稿。
- **ASCII 静态资源路径扫描边界**：仅识别符合现有声明 codec 的 ASCII 路径——`renderers/*.html`、`regex/*.yaml`、`scripts/*.js` 与 `assets/` 下路径。HTML、CSS、JavaScript、JSON、YAML、Markdown 正文中具有明确边界的完整字面路径均可识别，包括无引号 HTML 属性（如 `<link href=assets/style.css>`）与脚本字面访问（如 `window.__NARRAEON_ASSETS__["assets/data.json"]`）；重复、循环与路径前缀重叠共用同一映射。**不执行代码、不解码转义、不解析远程／绝对／相对 URL 或带查询参数 URL，也不推断动态拼接**；此类引用由作者自行维护。传递复制与索引登记不扩展宿主资源加载方式，显示仍以对象声明为准。
- **集中草稿编辑与清理**：创建、绑定、解绑、克隆与删除由前端集中资源编辑模块一次产出完整草稿，文件、声明、挂载与扩展索引协同更新，保存由 Runtime 按 codec 校验。解绑仅移除当前引用，保留原资源与其他引用；删除未引用资源时重检最新草稿声明与非结构源码，仍被引用整次拒绝，确认无引用后同步清理扩展索引；删除后置请求或产物仅清理无其他声明使用的频道挂载，保留共享挂载与资源文件。资源名称支持中文，内部引用由编辑器安全分配。
- **正则与 JSON 契约**：正则规则可选 `enabled: false`（保留原规则与顺序但跳过显示转换，缺省继续执行）；编辑器与 Runtime 共用严格正则解析、阶段、匹配限制与失败策略。JSON 产物的 `payloadContract` 仅约束该 JSON 产物，样例与提交共用完整校验函数；它**不是** Provider JSON 模式，不保证模型输出合法，也不自动往返修复。
- **Markdown 产物**：扩展宿主把具有表头和匹配分隔行的管道表格排成带列标题的表格。原文 HTML 和单元格内容沿用 Markdown 转义与正则阶段；默认文档面板在窄屏内折行，超出面板宽度的表格可在面板内横向滚动。
- **前端扩展宿主桥接**（[ADR-0028](../adr/0028-artifacts-project-through-a-trusted-frontend-host.md)）：在本地可信内容假设下执行，不承诺恶意代码沙箱，绝不赋予模型工具或权威提交权限。脚本以 `render.update` 的显示后字符串为输入，通过实例、`nonce` 与 `requestId` 关联宿主桥接回执；行动按钮仅填草稿。新建与克隆不改变本地脚本授权，便携导入默认关闭脚本。
- 内置行动选项的脚本只由应用出厂资源供应，Runtime 校对冻结呈现与应用资源后授权该实例。内置状态栏使用独立的应用资源。通用 HTML 面板使用禁用脚本的文档 iframe。开启内置开关不会授权任何方案副本、内容包或世界脚本。

## 6. 玩家视图、纯界面面板与预览契约

### 6.1 玩家视图（`control/player-views.yaml`）

- 采用 `narraeon.player-views/v1`，仅使用精确「`@短引用` + 逻辑节点」选择器：选 scalar 显示原值，选 map／list 递归显示当前子树，选 Markdown 标题显示完整标题子树；`$ref` 仅显示目标标题与短引用链接，不自动展开。
- 节点缺失或改名仅在作者诊断中报告 unresolved，不做模糊迁移、不造默认值，也不阻止世界演化。
- **非权限系统**：未选中展示不意味着秘密、角色未知或叙事禁区。Runtime 仅硬隔离凭据、模型配置、宿主机械数据、工具结算意图、账本与续传载荷。
- **绑定标记投影**：Runtime 从实际 renderer 选择器生成文档、节点与界面标签的绑定标记，于 bootstrap 及相关读取正文之外展示；容器或全文选择保留真实范围，不逐叶扩写、不推断引用目标已展示、不赋予额外读写授权。

### 6.2 纯界面面板与预览

- 编排方案工作台「界面扩展」入口独立配置玩家视图来源、布局、挂载位置与渲染资源。纯界面面板不进入游玩提示顺序，不增加模型调用。自定义面板接管同一视图的默认卡片。内置状态栏是默认关闭的样式开关，可在方案设置默认、在世界单独覆盖，或单项复制成可编辑面板。启用后在未被自定义面板接管的玩家视图中依次优先使用 `status`、`scene-status` 或作者声明的首项；其余视图维持原显示，关闭状态栏恢复该视图的标准卡片。
- **产物与纯界面预览**：使用当前未保存草稿经真实工作台解析的资源与生产渲染宿主，在内存中经既有 codec 校验草稿，**不保存方案、不调用模型、不写世界或开关**。产物预览明确标明使用本页样例；纯界面预览读取显式选择世界的安全玩家视图，无世界上下文时不伪造虚构样例，来源不可解析时保留诊断不猜测其他视图。任何编辑、目标切换或脚本许可变更立即使旧预览失效，迟到结果不得覆盖新草稿。脚本许可仍取自指定本地编排方案的已保存设置。
