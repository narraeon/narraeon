# Narraeon（叙典）产品基础

Narraeon（中文名“叙典”）是一个本地优先的开放式角色扮演工作区，其核心产品不是“把存档 JSON 发给模型”，而是**提示词管理器 + Runtime 权威连续性层**。作者和 AI 用人类可读文件表达世界语义，Runtime 在模型上下文之外保存当前世界、精确叙事与不可变提交；任何模型会话都可以丢弃或重建。

本文件定义当前 V1 产品 contract。实施进度、缺陷、研究和验收状态由 GitHub Issues 跟踪，不在本文件中维护第二份状态。

## 产品原则

1. **重要性分级连续性**：尽量不让玩家出戏，越重要的事情越不能前后冲突；不追求宿舍里每件普通衣物的位置都可查询。
2. **模型读语义，Runtime 管机械**：模型看到按 role 组织的 Markdown；Runtime 只校验文件、身份、引用、patch、端点、协议边界和原子提交。
3. **只有内容包有设定**：创建世界后，复制来的虚构文件就是世界当前状态，不再保留世界设定副本、初始记录和 current record 三层含义。
4. **状态与叙事互补**：会约束后续选择的持续结果写入当前文档；没有结构化但已经发生的细节由已提交叙事精确保留并按需追溯。
5. **提示词是产品表面**：预设中的主持／叙事／设定完善作者提示、世界提示框架、材料位置、role、Provider 参数和真实 request 必须可以查看和编辑，不能藏在临时 DTO 拼装中。
6. **Runtime 不伪装成语义 AI**：它不判断谁有敌意、什么最重要、哪段历史相关、好感度是否越界或叙事是否泄露悬念。

## 普通产品表面

普通工作区保留四个任务入口：

1. **内容编辑**：编辑内容包当前树中的 YAML／Markdown 设定与控制资产。
2. **预设**：管理跨世界复用的主持框架、叙事规则、AI 设定完善创作提示、后置请求和界面扩展。
3. **新建世界**：从一份可用内容包复制初始世界状态与世界控制，创建独立世界。
4. **提示词预览**：用真实编译器只读检查某次模型操作将采用的 role、Markdown、工具、材料、Provider 参数和缓存边界。

模型连接配置是工作区设置，不是第五个内容任务。世界列表和世界页是已有世界的使用入口；世界页提供游玩、当前文档、控制编辑、已提交叙事、重命名、修正和派生，而不把运行中世界重新叫作“设定”。世界名称是可修改、可重名的本地显示标签，不是世界身份，也不是当前情境文档的 title；重命名不改变 state、control、history、当前端点或 Authority。

直接把另一份内容包合并进运行中世界不属于 V1。若以后增加该能力，必须作为显式世界外操作定义 state／control 的原子边界，不能把内容包当成运行中世界的可同步设定副本。

## 内容包与创作

内容包是一棵可复制的当前文件树，最少包含：

```text
content-package/
  opening.md  # 玩家首次行动前立即看到的开场白原文
  world/      # 人物、地点、规则、出生时状态、初始当前情境
  control/    # 世界提示框架、创作块、玩家视图
```

`opening.md`、`world` 与 `control` 在内容包阶段统称设定。根级 `opening.md` 是作者预先写定的玩家可见开场白：只呈现玩家立即可感知的局面，停在可行动的位置，不替玩家决定行动、台词或内心。人物文件直接写 `衣着`、`修为`、`关系` 等出生时取值，不写等待 Runtime 物化的 `initialClothes`、schema record 或 genesis DTO。

导入、复制和新建都会获得新的本地身份，同名变体可以并存。导入与导出使用同一种便携 ZIP：浏览器上传 ZIP 内容，不提交本机目录路径；便携包只携带业务文件，不携带本地身份、机器路径、来源身份、发布身份或历史版本。导入先检查路径安全、资源限制、文本编码、文档身份、显式引用、控制格式和必需绑定；危险输入拒绝，安全但尚不完整的内容可以作为待修复包继续编辑，不能用于创建世界或导出。

内容包以本地身份和当前文件树作为完整持久形状，不另设 manifest、安装身份、content digest 或发布 revision。内容包保存和 AI 设定完善都先形成隔离的完整候选树，用户整批确认后才原子替换当前树；失败、取消或放弃不留下部分文件。

详细作者规则见 [`content-package-setting-authoring.md`](content-package-setting-authoring.md)。

## 创建世界与四个固定表面

创建世界是一次机械复制和发布：

```text
content-package/world/*   -> world/state/*
content-package/control/* -> world/control/*
content-package/opening.md -> world/history 的 genesis 第一条 narrator 原文
```

复制完成后：

- `state` 是该世界全部虚构当前文档，也是唯一世界当前树；
- `control` 是该世界自己的提示框架和玩家视图，不是虚构状态；
- `history` 从开场白这一条 genesis 主持原文开始，之后只追加成功提交的玩家输入与最终可见主持原文；
- `runtime` 保存不可变提交、operation outcome、索引、物化进度和恢复数据，不进入普通模型正文。

Runtime 把复制结果和开场白原子发布为世界初始权威端点。开场白逐字成为唯一 genesis narrator 历史消息；Runtime 不伪造“开始游戏”玩家消息，也不调用模型生成开场。genesis 只用于玩家可见历史，生产提示词编译会从 recent history 和附加材料中排除它，不在全新上下文里把玩家已经看到的开场重复发给模型。除此之外，Runtime 不解析人物 seed、不创建关系记录、不把世界规则编译成 schema，也不生成第二份 current。源内容包和新世界从发布后完全脱离；修改任何一方都不追溯另一方。派生世界继承所选端点的已有历史，不再额外生成一份开场白。

创建发布记录保留世界创建时的默认名称，用于 operation 幂等与恢复校验；玩家后来设置的世界名称单独保存在世界本地外壳中。读取时，有本地名称就显示它，没有则继续显示创建名称。重命名只原子替换这份本地外壳，不改写创建 operation 或不可变 Authority；派生世界的默认名称取来源世界派生当下的显示名称并加“（派生）”。

每个世界必须有一份由控制文件精确绑定的**当前情境**文档。它承接没有单一自然所有者、却会约束紧接着叙事的短期局面；字段完全开放，Runtime 不从其中的“地点”“人物”“情况”等名字推导同场、相关或重要材料。

世界外可以编辑世界控制，但必须先预览并明确应用；正在游玩的 AI 不能修改 `control`。普通游玩工具只寻址候选 `state`，不能改旧叙事、提交账本、宿主预设或世界提示框架。

## 世界文档、格式与引用

人物、地点、当前情境和轻量关键物品等开放结构默认使用受限 YAML；长篇规则、文化、背景和提示词块默认使用 Markdown。一份文件对应一个自然所有者、独立生命周期或独立长篇语义，不按每个字段拆成碎片。

每份可引用世界文档都有最小 `$document` 技术头，只保存：

- 世界内不可变文档 ID；
- 稳定短引用；
- 标题；
- 一句话稳定简介；
- aliases。

路径、hash、内部 version、operation、hostPresetId、materialId、sourceType 等 Runtime 字段不进入模型正文。模型看到的是确定性 Markdown renderer 的结果，不是 YAML 转义字符串或内部 JSON 包。

`{ $ref: id }` 是唯一世界内机械引用，且只引用整份文档；裸字符串永远是文字。局部读取、注入和 patch 使用“文档 + YAML 路径／Markdown 标题路径”的逻辑节点；持久选择器不得依赖列表下标，Runtime 不根据名称、字段名或内容猜引用。

世界不提供作者自定义 schema、类型、枚举、范围、基数、默认值、字段权限或状态转换校验。修炼顺序、好感度参考和关系含义写成自然语言规则；`好感度: 150`、`修为: 菠萝` 在机械上都可保存，是否合理只由 AI 在终态提交前自行判断并由玩家体验评价。

受限 YAML／Markdown codec 仍严格限制解析安全、重复 key、深度、容量、保留技术头、引用完整性和 patch 路径。严格的是“怎样安全操作文档”，不是“世界值应该是什么”。

## 状态维护政策

愿望、意图、尝试、计划、可能性和预测本身都不是已经发生的结果。AI 先根据玩家明确实施的行动和世界规则判断结果，再逐项检查：如果下一次行动开始时忽略某项结果，会不会造成明显矛盾，或实质改变人物行为、可用选择、物品归属、位置、伤势、关系、重要认知或仍在进行的局面？只有答案为“会”时才需要写入当前世界文档；这次行动没有文档变化是合法结果。

AI 决定是否持久化时遵循以下顺序：

1. 忘掉也不会明显出戏：只留在已提交叙事；
2. 只约束当前场面且没有单一所有者：写当前情境；
3. 持续约束人物、地点或其他自然对象：写自然所有者文档；
4. 普通物品只需记存在、归属和意义：嵌入自然所有者；
5. 必须独立引用、转移或追踪生命周期：创建独立文档；
6. 即使成为关键道具，也只记录当前玩法真正需要的字段。

例如秦龙脱掉上衣后，人物文档应写 `衣着: 光膀子，运动短裤，拖鞋`，避免下一次行动再次脱衣；普通上衣是否还搭在椅背可以不记。冠军奖杯或象征友谊的球鞋先记录存在、归属和意义，只有被盗、转赠或能力进入玩法后才升级追踪。

当前情境只保留所有直接结果和即时反应结束后仍然成立的此刻地点、在场者、进行中事件，以及下一次行动若忽略就会立刻冲突的短期限制；不回放刚完成的步骤。人物离场、动作结束或场景切换时应整份收敛，不追加“上一次行动发生了什么”的事件日志；能明确归属于人物、地点或关键物品的持续结果不得只堆在当前情境。当前情境的 title 和 summary 同样是当前场景索引；交接等过程结束后必须随正文更新，不继续挂着旧场景名。

人物对他人的关系默认直接写在产生看法的人物文档中，方向由自然所有者表达；Runtime 不镜像、不级联。只有忘记后会显著破坏人物行为的重要认知才写入人物文档，不穷举“角色不知道的所有事情”，也不建立 `secret`／`public`／`ai_private` 世界分类。

这些取舍由主持预设中的通用状态维护判据，加上世界提示框架中本世界特有的文档类型与保存位置规定，共同约束 AI（[ADR-0029](adr/0029-author-prompt-layers-split-by-capability.md)）。Runtime 不替 AI 决定该写哪里，也不在场景切换时自动提升、清理、总结或抽取内容。

## 分层提示词管理

提示词按各层的**实际能力**划分，不按语义类别划分（[ADR-0029](adr/0029-author-prompt-layers-split-by-capability.md)）。主持预设与世界提示框架一起进入生产游玩调用链的稳定 bootstrap，两者按作用域切分：跨世界恒真的作者语义属于主持预设，本世界特有的语义属于世界提示框架；描述 Runtime 自身产出与边界的说明属于机械层，描述故事该怎么演的属于作者层。玩法预设中的作者 Markdown 也作为稳定叙事规则进入 bootstrap，每当 AI 输出玩家可见正文时生效（[ADR-0030](adr/0030-production-play-is-one-model-directed-call-chain.md)）。

普通工作区中的一份 file-native **预设**是这些跨世界作者资产的共同便携与 revision 边界：它同时携带主持 frame／块库、玩法调用链／界面资产，以及 AI 设定完善作者提示。三者仍按能力分别进入对应模型操作；放进同一份预设不意味着设定完善取得游玩工具，或游玩取得内容包写权限。复制、导入、导出、选择和冻结都以整份预设 revision 为单位。

**主持预设**是世界外可复用的外层作者框架，负责跨世界成立的通用文风、默认人称、玩家代理权、裁判底线与**通用状态维护判据**——保存检验、写给自然所有者的原则、当前情境收敛规则和按需读取的触发条件。它不决定本世界的具体保存位置，也不解释工具怎样调用。设定完善无法改写它，因此必须长期成立的判据放在这里最稳。

**世界提示框架**是每个内容包提供并随世界复制的内层作者框架，只负责本世界特有的那一半：发展方式、题材边界、专属文风、本世界有哪些文档类型、某类结果该写进哪一份，以及精确材料 slot。它不重复通用判据，也不能内嵌当前地点、衣着或关系等实际值，否则会重新制造 control／state 双份事实。

**玩法预设**在全新上下文开始时冻结。生产调用链从中取得与游玩兼容的读取／世界写入工具全集、界面扩展配置和稳定叙事提示块。主响应完成后，预设声明的后置请求可以基于已结算结果生成玩法产物；这些请求不追加模型 transcript，也不推进世界 Authority。

**设定完善作者提示**也是预设中的普通可编辑 Markdown 块，只约束 AI 怎样理解、规划和创作内容包。一次设定完善开始时冻结当前有效预设 revision，后续计划修改和候选修改继续使用同一份正文；切换或修改当前预设只影响下一次新会话。旧 v1 预设没有显式引用时采用系统推荐正文，但 Runtime 不静默改写其文件，只有用户在预设工作台确认编辑后才保存新 revision。

**Runtime 机械说明**只解释当前请求真实提供的工具、文件边界和提交边界。设定完善的 `setting_*` 工具全集、参数 schema、工具介绍、只读／写入阶段边界、候选检查和终态协议始终内置，不进入可编辑预设。作者不能用提示词扩大或替换这些能力；Runtime 也不能用机械说明暗中增加故事、人称、裁决步骤或状态语义。

作者层提示必须写成**可执行语义契约**：使用模型能够直接观察的条件、判断步骤、允许无变化的分支和必要示例，不依赖“持续变化”“自然所有者”“当下切面”等未在同一提示中定义的项目术语。Runtime 能机械保证的事情只在机械说明与工具定义中出现，不靠作者提示反复提醒。

主持与世界框架都采用小型受限 YAML 编排文件加独立 Markdown 块；它们不支持任意字符串模板或 `{{与秦龙有敌意的人}}` 一类语义占位符。Runtime 只绑定明确文档、逻辑节点、节点中的显式引用、有界目录、精确历史消息和当前附加材料清单。

模型请求使用稳定逻辑 role：bootstrap 中的 `runtime_system`、`author_instruction`、`world_context`，以及随后追加的 `player_input`、`assistant`、`tool`。Provider adapter 只做协议 role 映射；无论目标 API 只有 system／user 还是支持 developer，世界状态不能被提升成宿主指令，Runtime 机械契约也不能被降成普通材料。

输入正文使用 Markdown。只有 provider 传输外壳和原生工具参数使用 JSON；不得再把内部上下文对象序列化后塞进一条 `user.content`。

## 附加材料与按需读取

全新上下文会读取当前端点已有的完整附加材料清单。清单只允许精确文档、逻辑节点、历史消息或历史提交引用，不允许自由提示词、关注理由、语义 query 或材料副本；生产调用链不会自动推断、扩充或截断它。genesis 开场白引用是唯一例外：材料账本即使含有该引用，生产编译也会明确排除。

Runtime 逐项检查引用、重叠和数量。任何一项失败都整份拒绝，不能静默截断、只保留前几项或猜测替代材料。清单是历程连续性的材料选择，不是世界事实；当前响应突然需要的材料仍由 AI 使用工具读取。

模型读取面只有三种诚实的机械能力：

- 列出有界目录和元信息；
- 对当前文档或已提交叙事做原文字面搜索；
- 按精确文档、节点、历史消息或字节区间读取。

每个结果必须说明范围、cursor 和是否完整。搜索 miss 只表示给定范围内没有字面命中，不能证明世界不存在某事。Runtime 不接受“与秦龙有敌意的人”“跟这次行动相关的规则”或“最重要的旧承诺”之类查询。工具、目录、文档、检索、命中和错误只供 AI 私下裁决；玩家可见叙事不得写“没搜到档案”或其他内部过程。

整文档精确读取把 title、summary 和 aliases 作为明示元信息与可写正文分开返回；AI 用 `set_metadata` 整组更新过时索引，不直接 patch `$document` 中的稳定身份。

Runtime 不按剩余 token 从新到旧填充历史。除 genesis 开场白外，只有世界 frame 明确声明的 history slot 或附加材料会进入全新 bootstrap，且模型看到的是“玩家原文／主持叙事”等语义标签，不是内部消息 ID。首次行动的 history slot 明确注入“最近已提交对话为空”，不让 AI 为确认不存在的第一条记录浪费一次搜索；未注入的准确旧事仍由 AI 字面搜索并精确读取。

## 游玩调用链

生产游玩只有一套模型／工具循环（[ADR-0030](adr/0030-production-play-is-one-model-directed-call-chain.md)）。界面的两个按钮是本次提交动作，不是必须预先切换并保持的模式：

- **全新上下文**从世界当前端点重新编译稳定 bootstrap，冻结当前主持预设、世界 frame、材料和玩法预设工具全集，再把玩家原文作为第一条普通玩家消息；它只替换模型工作上下文，页面继续显示此前全部剧情与调用轨迹，并在每个新起点插入分隔标记；
- **追加上下文**在已有调用链和非空输入时只追加一条玩家消息；没有既有上下文时自动按全新上下文开始；已有上下文且输入为空时不追加玩家消息，直接让 AI 沿当前完整 transcript 继续生成。

两者之后的调用完全相同：

```text
玩家消息 -> Authority
  -> 模型完整响应
       -> 可选读取／patch／create 工具结果
       -> 响应中的可见文本与世界变化 -> Authority
       -> 如有工具调用，继续下一次模型响应
```

每次模型响应都在同一份调用链契约下自由选择直接叙事、只调用工具，或同时给出文本与工具调用。世界写工具只操作当前候选，完整响应处理成功后才把变化后的完整 YAML／Markdown 写入 Authority；普通游玩不删除或移动整份文档。

调用链没有整体原子提交或集中结算。玩家原文先单独提交；每个已经完整返回且含可见文本或状态变化的模型响应再各自提交。后续模型或传输失败不会回滚已经成立的前序步骤。Provider 的 SSE 增量经 Runtime 的 NDJSON 流直接投影到浏览器，界面因此实时显示玩家、逐字 AI 响应、默认折叠且可展开的 Provider 思维链、工具名称与默认折叠的参数／结果、失败和 Provider usage，而不是轮询等待最终文本；增量只更新调用链内容，不主动改变玩家当前的滚动位置；思维链只属于调用轨迹，不成为玩家／主持历史或世界 Authority。

追加上下文继续使用当前模型上下文开始时冻结的 bootstrap，但每次 Authority 写入都必须基于该上下文当前已提交端点；若世界被其他操作推进，只能选择全新上下文重新编译。全新上下文替换旧逻辑 transcript，不把旧链嵌套进新请求；Web 另行持久保留 append-only 页面时间线，使此前的玩家输入、AI 正文、思维链、工具参数与结果、失败和 usage 在刷新或冷恢复后仍按原顺序显示，并在每个模型上下文起点显示分隔标记。

Runtime 在每次模型派发前持久保存完整 `ModelHostExchange`。若 Provider 流中断，中断片段只在界面显示，不追加到模型 transcript，也不进入 Authority；玩家保持输入为空并点击“追加上下文”时，Runtime 原样发送已保存请求，不再添加一次玩家原文，不根据片段构造“继续写”指令，也不重新拼装 frame。若上一响应已经完整结束，同样的空输入动作会用包含该完整响应的当前 transcript 发起下一次生成。界面始终只提供“全新上下文”和“追加上下文”两个提交动作。

Provider response ID、continuation token、不透明推理项和缓存只用于协议续传或加速，不成为世界状态、已提交叙事或唯一恢复来源。

## 预算、缓存与预览

模型配置继续提供 Provider 的 `contextWindowTokens` 和 `maxOutputTokens`。每次新派发直接使用当前 ModelHost 的固定 `maxOutputTokens`；原样重发使用已持久化的完整原请求。Runtime 不估算 token、不做上下文准入、不另设“连续交换输出上限”，也不在响应已经完成并计费后重新计算再拒绝结果。上下文能否容纳请求完全由 Provider 判断；Runtime 不自动摘要、压缩或截断历史。

提示词编译把稳定机械块、主持块和世界控制块放在稳定前缀，内部 ID、时间戳和 operation 数据不得污染缓存键。缓存 miss 只影响成本和延迟，不能改变请求语义或恢复能力。

Prompt Preview 必须调用真实编译器，并展示：

- provider-neutral 逻辑消息和最终 provider role；
- 每个 slot 的精确来源及未提供边界；
- 最终 Markdown 正文与真实工具定义；
- 附加材料展开和按需读取入口；
- Provider 窗口／最大输出配置、Runtime 不做上下文准入的状态和 cache 报告；
- 内部 DTO 字段泄漏扫描。

内容包和设定候选的生产 Preview 必须明确显示 `opening.md` 不进入 bootstrap，并把预览玩家原文单列为紧随 bootstrap 的首条普通 user 追加；它不能制造一条权威玩家历史。

预览不调用模型、不创建候选、不提交，也不能维护一套近似拼装逻辑。

## 玩家视图与信息边界

玩家视图保存在世界控制中，只使用精确“文档 + 逻辑节点”选择器。选择 scalar 就显示原值，选择 map／list 容器就递归显示其当前子树；文档引用显示为引用，不自动展开。节点缺失或改名只产生明确界面诊断，不做模糊迁移，也不阻止世界继续演化。

玩家视图不是字段权限系统。未显示的内容不自动成为秘密、角色未知或叙事禁区；角色知道、叙事何时揭示和界面常驻显示是三件不同的事。Runtime 只硬隔离凭据、模型配置、宿主机械数据、候选、账本和工具续传等本来就不属于虚构世界的技术内容。

## 权威提交、恢复、修正与派生

Runtime 是唯一业务提交者。每笔提交绑定稳定 operation ID 和父端点，语义载荷包含：

- 按顺序追加的精确玩家／主持原文；
- 每份变化后完整世界文档及前后 hash；
- 下一端点完整附加材料清单。

长期恢复保存最终文件效果，不保存模型 patch 语言。提交先 durable 发布不可变记录与新 head，再幂等物化 `state`、`history` 和端点清单；若提交已接受但文件物化失败，结果必须报告“已提交、待修复”，阻止新写入，并只根据同一提交补齐，不能以新 operation 重放模型。

V1 继续使用 genesis／derivation genesis 加不可变提交作为正确性来源，不再增加第二日志或强制 checkpoint。性能 checkpoint 以后只能作为可删除、可重建缓存。

同一世界不破坏性回滚。连续性修正追加一笔新的 correction 提交；玩家可以在已提交玩家／AI 历史节点点击“从这里重新开始”，重放该端点的完整 state、history 和附加材料清单，使用派生当下的当前世界控制和玩家所选主持预设，创建物理闭包的新世界。若该节点属于持久游玩时间线中的任一模型上下文，派生同时保留该上下文之前的完整页面轨迹，并截断所选上下文截至该节点的模型 transcript 与调用轨迹，包括思维链、工具参数和结果；分叉点之后的上下文和响应不进入派生世界，chain/world 身份重新分配，调用链 Authority 端点重绑为派生世界 `genesis`。截断后最后一项是玩家消息时，玩家可以留空点击“追加上下文”直接重新生成，不再提交一遍同样的玩家原文。

已提交玩家消息还提供“修改”入口。确认修改稿后，Runtime 从该玩家提交的父端点创建独立世界，只复制父端点以前的 state、history、附加材料与调用轨迹；原玩家提交和它之后的消息、思维链、工具交换与上下文都不进入新分支，修改稿作为新分支的下一条玩家消息自动提交并继续模型调用链。这个交互中的“舍弃后续”只描述新分支的截断结果，不删除或改写来源世界；来源世界与新世界发布后仍分别形成物理闭包。

## 设定完善

设定完善只面向内容包设定，不修改运行中世界状态、已提交叙事、人物当前认知或历史。它和游玩一样使用人类可读 Markdown 输入和 append-only 模型会话，不把完整旧对话反复嵌套进 JSON。

开始会话时，Runtime 同时冻结当前有效预设 revision：其中可编辑的设定完善作者提示决定创作方法，Runtime 再追加不可编辑的工具与机械契约。两者边界明确——预设可以改变创作语义，不能声明工具、参数、结果、提交方式或 Provider 协议。会话开始后，即使用户切换或修改当前预设，本次计划、候选和修改仍复用已经冻结的作者提示。

开始设定完善时，用户可以从固定内容包当前树中选择文本文件，把完整原文作为已有设定直接注入首个模型请求；未选择的文件仍可按需读取。计划优先路径允许 AI 在不修改候选的前提下使用精确 list／原文字面 search／精确 read 了解现有设定，再把主要／次要体验、反复游玩循环、焦点、节奏、冲突、信息结构、语气边界和明确排除项整理成可见计划；确认方向后才开放写工具。用户也可以明确跳过可见计划，直接让 AI 读取并生成隔离候选；“直接生成”只跳过计划确认，不跳过候选检查、审阅和最终整批应用。

候选阶段使用受管的文档 create／patch 操作生成 YAML、Markdown 和控制文件。AI 必须检查 `opening.md`：缺失时创建；开局地点、人物、局面、语气或行动钩子受本次修改影响时，先完整读取再通过专用工具更新；不受影响时保留原文。直接注入的完整文件视为已经完整读取。

创作 AI 可以创建或修改开场白与内容包的世界提示框架；普通游玩 AI 不可以。候选需要通过开场白唯一性／文本／大小、文件安全、身份、引用、控制格式、必需 slot、玩家选择器和真实 Prompt Preview 检查，但 Runtime 不校验世界专属字段、关系值、修为枚举或开场白是否有趣。

只有用户整批确认才原子替换内容包当前树；候选必须完整符合当前格式，且不做静默 merge、rebase 或部分勾选。应用前必须展示完整文件差异和真实提示词预览。

## 目标模块边界

- `ContentWorkspace` 拥有内容包本地身份、当前树、安全导入／导出和整批候选应用。
- `WorldDocumentStore` 拥有世界文档身份、受限 codec、精确读取、候选 patch／create、引用索引和当前树物化。
- `PromptCompiler` 拥有主持／世界 bootstrap 的确定性编译、Runtime 机械说明、slot 绑定、Markdown 渲染、role 映射、Provider 参数、缓存报告和真实预览；生产游玩调用方只提交编译输入，不另行构造提示词或材料 DTO。
- `PlayCallChain` 拥有两个提交动作、空输入续写、模型／工具循环、跨全新上下文的持久页面时间线、浏览器增量投影、tool-call 幂等、逐响应 Authority 衔接和中断请求原样重发。
- `FileNativeWorldStore` 拥有不可变提交、operation outcome、head、物化恢复和派生；它不向模型暴露提交 DTO。
- `FileNativeArtifactStore` 拥有后置请求产物的 pending 记录、结算、保留策略和活动投影；玩法产物不混入世界 Authority。
- `ModelHost` 与 provider adapter 只拥有协议编码、流式交换和续传，不拥有世界事实或提示词语义。
- `Runtime` 协调这些深模块，是唯一业务权威。

## 当前格式边界

所有持久业务数据只接受当前 Narraeon 命名空间和当前 schema。Runtime 在读取前校验格式与完整性；不符合当前 contract 的记录会被拒绝，库级损坏则隔离后重建。系统不根据未知字段推断别名，不双读、双写或静默迁移，也不在结果不明时触发模型重放。
