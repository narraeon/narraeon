# Narraeon 产品基础

Narraeon 是一个本地优先的开放式角色扮演工作区，其核心产品不是“把存档 JSON 发给模型”，而是**提示词管理器 + Runtime 权威连续性层**。作者和 AI 用人类可读文件表达世界语义，Runtime 在模型上下文之外保存当前世界、精确叙事与不可变提交；任何模型会话都可以丢弃或重建。

本文件定义当前 V1 产品 contract。实施进度、缺陷、研究和验收状态由 GitHub Issues 跟踪，不在本文件中维护第二份状态。

## 产品原则

1. **重要性分级连续性**：尽量不让玩家出戏，越重要的事情越不能前后冲突；不追求宿舍里每件普通衣物的位置都可查询。
2. **模型读语义，Runtime 管机械**：模型看到按 role 组织的 Markdown；Runtime 只校验文件、身份、引用、patch、端点、协议边界和原子提交。
3. **只有内容包有设定**：创建世界后，复制来的虚构文件就是世界当前状态，不再保留世界设定副本、初始记录和 current record 三层含义。
4. **状态与叙事互补**：会约束后续选择的持续结果写入当前文档；没有结构化但已经发生的细节由已提交叙事精确保留并按需追溯。
5. **提示词是产品表面**：预设中的主持／叙事／设定完善作者提示、世界提示框架、材料位置、role、Provider 参数和真实 request 必须可以查看和编辑，不能藏在临时 DTO 拼装中。
6. **Runtime 不伪装成语义 AI**：它不判断谁有敌意、什么最重要、哪段历史相关、好感度是否越界或叙事是否泄露悬念。

## 普通产品表面

普通工作区保留四个任务入口：

1. **内容编辑**：编辑内容包当前树中的 YAML／Markdown 设定与控制资产。
2. **预设**：管理跨世界复用的主持框架、叙事规则、AI 设定完善创作提示、后置请求和界面扩展。
3. **新建世界**：从一份可用内容包复制初始世界状态与世界控制，创建独立世界。
4. **提示词预览**：用真实编译器只读检查某次模型操作将采用的 role、Markdown、工具、材料、Provider 参数和缓存边界。

模型连接配置是工作区设置，不是第五个内容任务。世界列表和世界页是已有世界的使用入口；世界页提供游玩、当前文档、控制编辑、已提交叙事、重命名、修正、修改和创建分叉，而不把运行中世界重新叫作“设定”。内容包标题与世界名称分别是两种可修改、可重名的本地显示标签：前者标识尚在创作的模板，后者标识已经创建的世界；两者都不是身份、世界内事实或当前情境文档的 title。重命名不改变内容包当前树，也不改变世界的 state、control、history、当前端点或 Authority。

世界页首次打开以故事可读为完成边界：先取得当前端点、玩家视图和最近 40 项页面时间线摘要并开始显示；更早时间线由玩家显式向前加载，工具／Provider 返回推理详情在展开单项时读取，世界文档与 Runtime 诊断只在进入对应页面时读取，玩法产物和调试投影在首屏之后独立加载。首屏不得为了计算“完整对话”而遍历 Authority、读取全部模型上下文或重放全部工具记录。

直接把另一份内容包合并进运行中世界不属于 V1。若以后增加该能力，必须作为显式世界外操作定义 state／control 的原子边界，不能把内容包当成运行中世界的可同步设定副本。

## 内容包与创作

内容包是一棵可复制的当前文件树，最少包含：

```text
content-package/
  opening.md  # 玩家首次行动前立即看到的开场白原文
  world/      # 人物、地点、规则、出生时状态、初始当前情境
  control/    # 世界提示框架、创作块、玩家视图
```

`opening.md`、`world` 与 `control` 在内容包阶段统称设定。根级 `opening.md` 是作者预先写定的玩家可见开场白：只呈现玩家立即可感知的局面，停在可行动的位置，不替玩家决定行动、台词或内心。人物文件直接写 `衣着`、`修为`、`关系` 等出生时取值，不写等待 Runtime 物化的 `initialClothes`、schema record 或 genesis DTO。

导入、复制和新建都会获得新的本地身份，同标题变体可以并存。每份本地内容包另外拥有独立标题；新建时取得本地化默认标题，复制时保留来源标题，浏览器导入时以 ZIP 文件名作为初始标题，之后均可单独修改。导入与导出使用同一种便携 ZIP：浏览器上传 ZIP 内容，不提交本机目录路径；便携包只携带业务文件，不携带本地身份、标题、机器路径、来源身份、发布身份或历史版本，导出文件名只把本地标题用作方便人的外部标签。导入先检查路径安全、资源限制、文本编码、文档身份、显式引用、控制格式和必需绑定；危险输入拒绝，安全但尚不完整的内容可以作为待修复包继续编辑，不能用于创建世界或导出。

内容包以本地身份、独立标题和当前文件树作为完整持久形状，不另设业务 manifest、安装身份、content digest 或发布 revision。标题保存在 Runtime 拥有的本地外壳中，不能从 `current-situation` 或其他文档的 title 动态推导；升级前尚无独立标题的旧包会在第一次读取时持有包级互斥权，并把旧显示值原子固化到本地外壳。浏览器手动编辑仍以本地未保存缓冲区整批替换当前树；AI 设定完善不维护第二棵持久草稿树，而是像游玩推进一样，把一份完整 Provider 工具响应中的成功变化作为一个当前树事务原子发布。流式半响应和未结算工具调用不能修改当前树。

详细作者规则见 [`content-package-setting-authoring.md`](content-package-setting-authoring.md)。

## 创建世界与四个固定表面

创建世界是一次机械复制和发布：

```text
content-package/world/*   -> world/state/*
content-package/control/* -> world/control/*
content-package/opening.md -> world/history 的 genesis 第一条 narrator 原文
content-package 的本地标题 -> 新世界的初始本地名称
```

复制完成后：

- `state` 是该世界全部虚构当前文档，也是唯一世界当前树；
- `control` 是该世界自己的提示框架和玩家视图，不是虚构状态；
- `history` 从开场白这一条 genesis 主持原文开始，之后只追加成功提交的玩家输入与最终可见主持原文；
- `runtime` 保存不可变提交、operation outcome、索引、物化进度和恢复数据，不进入普通模型正文。

Runtime 把复制结果和开场白原子发布为世界初始权威端点。开场白逐字成为唯一 genesis narrator 历史消息；Runtime 不伪造“开始游戏”玩家消息，也不调用模型生成开场。genesis 只用于玩家可见历史，生产提示词编译会从 recent history 和附加材料中排除它，不在全新上下文里把玩家已经看到的开场重复发给模型。除此之外，Runtime 不解析人物 seed、不创建关系记录、不把世界规则编译成 schema，也不生成第二份 current。源内容包和新世界从发布后完全脱离；修改任何一方都不追溯另一方。分叉世界继承所选端点的已有历史，不再额外生成一份开场白。

创建发布记录把来源内容包的独立标题保存为世界初始名称，并把标题纳入 operation 幂等载荷；它不从任何世界文档标题推导。玩家后来设置的世界名称单独保存在世界本地外壳中。读取时，有本地名称就显示它，没有则继续显示创建名称。重命名只原子替换这份本地外壳，不改写创建 operation 或不可变 Authority；分叉世界的默认名称取来源世界创建分叉当下的显示名称并加“（分叉）”。

每个世界必须有一份由控制文件 `bindings.currentSituation` 精确绑定的**当前情境**文档。它承接没有单一自然所有者、却会约束紧接着叙事的短期局面；职责不由路径、ref、文档标题或简介猜测。其 `$document.title` 与 `summary` 是随正文一起更新的当前场景索引，可以写成“暴雨中的码头”而不保留“当前情境”字样。字段完全开放，Runtime 不从其中的“地点”“人物”“情况”等名字推导同场、相关或重要材料。

世界外可以编辑世界控制，但必须先预览并明确应用；正在游玩的 AI 不能修改 `control`。普通游玩工具只寻址候选 `state`，不能改旧叙事、提交账本、宿主预设或世界提示框架。

## 世界文档、格式与引用

人物、地点、当前情境和轻量关键物品等开放结构默认使用受限 YAML；长篇规则、文化、背景和提示词块默认使用 Markdown。一份文件对应一个自然所有者、独立生命周期或独立长篇语义，不按每个字段拆成碎片。

每份可引用世界文档都有最小 `$document` 技术头，只保存：

- 世界内不可变文档 ID；
- 稳定短引用；
- 标题；
- 一句话稳定简介；
- aliases。

路径、hash、内部 version、operation、hostPresetId、materialId、sourceType 等 Runtime 字段不进入模型正文。模型看到的是确定性 Markdown renderer 的结果，不是 YAML 转义字符串或内部 JSON 包。

`{ $ref: id }` 是唯一世界内机械引用，且只引用整份文档；裸字符串永远是文字。局部读取、注入和 patch 使用“文档 + YAML 路径／Markdown 标题路径”的逻辑节点；持久选择器不得依赖列表下标，Runtime 不根据名称、字段名或内容猜引用。

世界不提供作者自定义 schema、类型、枚举、范围、基数、默认值、字段权限或状态转换校验。修炼顺序、好感度参考和关系含义写成自然语言规则；`好感度: 150`、`修为: 菠萝` 在机械上都可保存，是否合理只由 AI 在终态提交前自行判断并由玩家体验评价。

受限 YAML／Markdown codec 仍严格限制解析安全、重复 key、深度、容量、保留技术头、引用完整性和 patch 路径。严格的是“怎样安全操作文档”，不是“世界值应该是什么”。

## 状态维护政策

愿望、意图、尝试、计划、可能性和预测本身都不是已经发生的结果。AI 先根据玩家明确实施的行动和世界规则判断结果，再逐项检查：如果下一次行动开始时忽略某项结果，会不会造成明显矛盾，或实质改变人物行为、可用选择、物品归属、位置、伤势、关系、重要认知或仍在进行的局面？只有答案为“会”时才需要写入当前世界文档；这次行动没有文档变化是合法结果。

保存时机另按可恢复性划分：玩家视图绑定值发生变化时，本轮最终叙事前写回；需要保留但玩家原文与最终叙事没有记录的信息当场保存；能从原文恢复的其他结果可在事件收尾归并。检查点前整理自然所有者、重要认知、待兑现承诺和有界文档；新上下文核对补充原文时保持幂等，不重复消耗资源或转移物品。这些属于可编辑作者政策，既有用户预设与冻结上下文保留原文；Runtime 不自动清理用户创作资产，也不为核对增加独立模型调用。

AI 决定保存位置时遵循以下顺序：

1. 忘掉也不会明显出戏：只留在已提交叙事；
2. 只约束当前场面且没有单一所有者：写当前情境；
3. 持续约束人物、地点或其他自然对象：写自然所有者文档；
4. 普通物品只需记存在、归属和意义：嵌入自然所有者；
5. 必须独立引用、转移或追踪生命周期：创建独立文档；
6. 即使成为关键道具，也只记录当前玩法真正需要的字段。

例如秦龙脱掉上衣后，需保存的当前状态是 `衣着: 光膀子，运动短裤，拖鞋`，避免下一次行动再次脱衣；普通上衣是否还搭在椅背可以不记。冠军奖杯或象征友谊的球鞋先记录存在、归属和意义，只有被盗、转赠或能力进入玩法后才升级追踪。

当前情境只保留所有直接结果和即时反应结束后仍然成立的此刻地点、在场者、进行中事件，以及下一次行动若忽略就会立刻冲突的短期限制；不回放刚完成的步骤。检查点前根据人物离场、动作结束和场景切换整理当前内容，不追加“上一次行动发生了什么”的事件日志；能明确归属于人物、地点或关键物品的持续结果不得只堆在当前情境。当前情境的 title 和 summary 同样是当前场景索引；整理时随当前正文更新，不继续挂着旧场景名；玩家视图选中的值仍遵守本轮及时写回的规则。

人物对他人的关系默认直接写在产生看法的人物文档中，方向由自然所有者表达；Runtime 不镜像、不级联。只有忘记后会显著破坏人物行为的重要认知才写入人物文档，不穷举“角色不知道的所有事情”，也不建立 `secret`／`public`／`ai_private` 世界分类。

这些取舍由主持预设中的通用状态维护判据，加上世界提示框架中本世界特有的文档类型与保存位置规定，共同约束 AI（[ADR-0029](adr/0029-author-prompt-layers-split-by-capability.md)）。Runtime 不替 AI 决定该写哪里，也不在场景切换时自动提升、清理、总结或抽取内容。

## 分层提示词管理

提示词按各层的**实际能力**划分，不按语义类别划分（[ADR-0029](adr/0029-author-prompt-layers-split-by-capability.md)）。主持预设与世界提示框架一起进入生产游玩调用链的稳定 bootstrap，两者按作用域切分：跨世界恒真的作者语义属于主持预设，本世界特有的语义属于世界提示框架；描述 Runtime 自身产出与边界的说明属于机械层，描述故事该怎么演的属于作者层。玩法预设中的作者 Markdown 也作为稳定叙事规则进入 bootstrap，每当 AI 输出玩家可见正文时生效（[ADR-0030](adr/0030-production-play-is-one-model-directed-call-chain.md)）。

普通工作区中的一份 file-native **预设**是这些跨世界作者资产的共同便携与 revision 边界：它同时携带主持 frame／块库、玩法调用链／界面资产，以及 AI 设定完善作者提示。三者仍按能力分别进入对应模型操作；放进同一份预设不意味着设定完善取得游玩工具，或游玩取得内容包写权限。复制、导入、导出、选择和冻结都以整份预设 revision 为单位。

**主持预设**是世界外可复用的外层作者框架，负责跨世界成立的通用文风、默认人称、玩家代理权、裁判底线与**通用状态维护判据**——保存检验、写给自然所有者的原则、当前情境收敛规则和按需读取的触发条件。它不决定本世界的具体保存位置，也不解释工具怎样调用。设定完善无法改写它，因此必须长期成立的判据放在这里最稳。

**世界提示框架**是每个内容包提供并随世界复制的内层作者框架，只负责本世界特有的那一半：发展方式、题材边界、专属文风、本世界有哪些文档类型、某类结果该写进哪一份，以及精确材料 slot。它不重复通用判据，也不能内嵌当前地点、衣着或关系等实际值，否则会重新制造 control／state 双份事实。

**玩法预设**在全新上下文开始时冻结。生产调用链从中取得与游玩兼容的读取／世界写入工具全集、界面扩展配置和稳定叙事提示块。主响应完成后，预设声明的后置请求可以基于已结算结果生成玩法产物；这些请求不追加模型 transcript，也不推进世界 Authority。

**设定完善作者提示**也是预设中的普通可编辑 Markdown 块，只约束 AI 怎样理解、讨论和创作内容包。系统推荐正文同时检查材料是否有充分发现路径，以及同一语义是否因跨文档、控制块或叙事块重复而获得过高注入权重；默认定向修改，用户要求审查或精简时则在指定范围内先按概念、再按句子完整去重。世界文档只承载已经成立的事实、不变量和持续倾向，“怎样选择、揭露或描写”属于世界作者控制，玩家可见语体只属于开场白与未来叙事。一段设定完善对话开始时冻结当前有效预设 revision，后续继续该对话时复用同一份正文；切换或修改当前预设只影响显式开启的全新上下文。旧 v1 预设没有显式引用时采用系统推荐正文，但 Runtime 不静默改写其文件，只有用户在预设工作台确认编辑后才保存新 revision。

只有仍带 Runtime 所有权标记的系统推荐预设种子会跟随新版内置正文或界面语言产生新 revision；用户一旦编辑或重命名该预设，所有权标记立即移除，此后升级、重启或切换语言都不得覆盖它。复制、导入和用户新建的预设从不带这项标记。

**Runtime 机械说明**只解释当前请求真实提供的工具、文件边界和提交边界。设定完善的稳定 `setting_*` 读写工具全集、参数 schema、工具介绍、当前树读取授权、逐响应原子发布和写后检查始终内置，不进入可编辑预设。作者不能用提示词扩大或替换这些能力；Runtime 也不能用机械说明暗中增加故事、人称、裁决步骤或状态语义。

作者层提示必须写成**可执行语义契约**：使用模型能够直接观察的条件、判断步骤、允许无变化的分支和必要示例，不依赖“持续变化”“自然所有者”“当下切面”等未在同一提示中定义的项目术语。Runtime 能机械保证的事情只在机械说明与工具定义中出现，不靠作者提示反复提醒。

主持与世界框架都采用小型受限 YAML 编排文件加独立 Markdown 块；它们不支持任意字符串模板或 `{{与秦龙有敌意的人}}` 一类语义占位符。Runtime 只绑定明确文档、逻辑节点、节点中的显式引用、有界目录、精确历史消息和当前附加材料清单。

模型请求使用稳定逻辑 role：bootstrap 中的 `runtime_system`、`author_instruction`、`world_context`，以及随后追加的 `player_input`、`assistant`、`tool`。Provider adapter 只做协议 role 映射；无论目标 API 只有 system／user 还是支持 developer，世界状态不能被提升成宿主指令，Runtime 机械契约也不能被降成普通材料。

Provider 响应进入 Runtime 后形成两条不能互相替代的轨道（[ADR-0035](adr/0035-provider-continuation-is-opaque-and-bound.md)）。**模型调用投影**解析可见正文、返回推理、工具调用、usage 与错误，供工具执行、诊断和界面呈现；**Provider 续传载荷**则保留下一次请求所需的完整协议原生片段。Chat Completions 保留完整 assistant message，Responses 保留完整 `output` items，Anthropic Messages 保留完整 assistant `content` blocks；下一次 append 必须直接使用这些片段，不能保存整个 HTTP response，也不能从投影重新拼装消息。尤其不能把 Claude 文本按标签或字段猜测成 thinking：签名 thinking、redacted thinking 和 Responses encrypted reasoning 都必须作为不透明协议项保留，且不得展示成玩家正文。

工具结果也由各协议的 encoder 从 Runtime 工具事实直接生成，而不是从 assistant 投影反推：Chat Completions 使用逐项 `tool` message，Responses 使用逐项 `function_call_output`，Anthropic Messages 把同一 assistant 响应触发的并行 `tool_result` blocks 合并在紧随其后的同一个 `user` message 中，并用 `is_error` 明示失败。Provider wire 上每个自定义工具的输入 schema 必须是没有顶层 `oneOf`／`allOf`／`anyOf` 的单一对象；状态目录枚举与已提交历史枚举分别使用 `state_list` 和 `history_list`，让模型接口本身表达两种互斥意图，Runtime 仍在执行边界严格验证参数。旧调用链若冻结了合并式 `context_list` 及不兼容 schema，只在该调用链的 Provider wire 投影处迁移，并仅在冻结工具全集确实包含它时继续执行；不能改写持久 transcript、替换原工具名或从解析投影重建消息。工具调用和结果可以进入模型上下文与诊断，但不能越权进入玩家叙事或世界 Authority。

输入正文使用 Markdown。只有 provider 传输外壳和原生工具参数使用 JSON；不得再把内部上下文对象序列化后塞进一条 `user.content`。

## 附加材料与按需读取

全新上下文会读取当前端点已有的完整附加材料清单。清单只允许精确文档、逻辑节点、历史消息或历史提交引用，不允许自由提示词、关注理由、语义 query 或材料副本；生产调用链不会自动推断、扩充或截断它。genesis 开场白引用是唯一例外：材料账本即使含有该引用，生产编译也会明确排除。

Runtime 逐项检查引用、重叠和数量。任何一项失败都整份拒绝，不能静默截断、只保留前几项或猜测替代材料。清单是历程连续性的材料选择，不是世界事实；当前响应突然需要的材料仍由 AI 使用工具读取。

模型读取面只有三种诚实的机械能力：

- 列出有界目录和元信息；
- 对当前文档或已提交叙事做原文字面搜索；
- 完整读取精确文档、逻辑节点或历史消息。

目录与搜索结果必须说明范围、cursor 和是否完整；精确读取则一次返回所选内容的完整原文，不按字节截断或分页。搜索 miss 只表示给定范围内没有字面命中，不能证明世界不存在某事。Runtime 不接受“与秦龙有敌意的人”“跟这次行动相关的规则”或“最重要的旧承诺”之类查询。工具、目录、文档、检索、命中和错误只供 AI 私下裁决；玩家可见叙事不得写“没搜到档案”或其他内部过程。

世界 frame 中的 catalog 目录是确定性材料选择，也是 Runtime 声明的状态创建目的地。即使该目录当前没有任何文档，state_list 仍必须返回它的 `@dir-*` 句柄，world_create 可以在其中创建第一份文档；新的全新上下文随后按同一 catalog 自动注入这份文档的索引。游玩 AI 可以用 `world_retire` 切换一份状态文档的退役标记：退役文档继续出现在 state_list，也仍可搜索、精确读取、引用和恢复，但后续全新上下文的 frame catalog 不再注入它；这不会销毁叙事记录。空目录句柄只是冻结 frame 对当前工具面的投影，不是独立持久文件或第二份世界状态。只有句柄形式正确但既不存在、也未被 frame 声明的目录，Runtime 必须拒绝。

整文档精确读取把 title、summary 和 aliases 作为明示元信息与可写正文分开完整返回；AI 用 `set_metadata` 更新过时索引，不直接 patch `$document` 中的稳定身份。Runtime 不通过文档、读取或世界写入字节上限替 Provider 管理上下文窗口。

Runtime 不按剩余 token 从新到旧填充历史。全新 bootstrap 完整补入当前时间线上最近生效整理检查点之后的玩家原文和最终主持叙事；没有检查点时从世界起点选取，并排除 genesis 开场白。这段历史非空时替代 frame 的 recent 选择，即使没有 history slot 也补入；为空时仍沿用 frame 的 recent 声明。补充放在当前世界材料之后，以精确历史身份和其他材料去重，保留原文字节与顺序，不设重放预算、不截断、不摘要，也不包含工具中间步、工具结果或返回推理。模型看到“玩家原文／主持叙事”等来源标签，不把旧输入当成本次指令；原文中的部分结果可能已经保存，核对不能重复执行事件或推翻明确的连续性修正。尚未发生对话时，声明的 history slot 明确显示最近已提交对话为空；更早的准确旧事仍可字面搜索并精确读取。

成功世界写入的紧凑回执使用整份工具响应结算后的最终状态与当前控制，说明若现在开启全新上下文的全文、精确节点及实际目录摘要覆盖；未全文注入但目录摘要可见时回显摘要原文。它与 Preview 共用材料选择，不声称已有冻结上下文重新注入，也不回显整份正文或内部提交编号。覆盖诊断失败不能撤销已接受写入；无变化不推进 Authority。

## 游玩调用链

生产游玩只有一套模型／工具循环（[ADR-0030](adr/0030-production-play-is-one-model-directed-call-chain.md)）。界面的两个按钮是本次提交动作，不是必须预先切换并保持的模式：

- **全新上下文**从世界当前端点重新编译稳定 bootstrap，冻结当前主持预设、世界 frame、材料和玩法预设工具全集，再把玩家原文作为第一条普通玩家消息；它只替换模型工作上下文，页面继续显示此前全部剧情与调用轨迹，并在每个新起点插入分隔标记；
- **追加上下文**在已有调用链和非空输入时追加玩家消息；没有既有上下文时自动按全新上下文开始；已有上下文且输入为空时不追加玩家消息，直接让 AI 沿当前完整 transcript 继续生成。

每条真实玩家输入之前另附一条 Runtime 计数提示，说明距最近生效整理检查点已完成多少玩家回合；尚无检查点时明确从起点计数。提示和玩家原文分开持久化，不进入 Authority 玩家／主持历史；工具循环、重试和空输入续写不增加回合。原样重发保留当时提示，不重建旧 bootstrap。

主持完成事件收尾整理后可以调用空参数 `world_checkpoint {}`，工具先持久登记，只有本轮无工具调用的最终叙事提交后才生效，截止位置包含该叙事。Runtime 不认证语义整理充分，也不因回合数自动打点。对应叙事下方显示开启全新上下文的建议；点击只准备下一次输入的上下文选择，不自动提交。检查点通过已有推进结算幂等保存，沿当前时间线继承；修改和分叉不采用被替换后续中的检查点。正常开启新上下文本身不产生检查点。详见 [ADR-0039](adr/0039-narrative-checkpoints-bound-complete-history-replay.md)。

两者之后的调用完全相同：

```text
玩家消息 -> Authority
  -> 模型完整响应
       -> 如有读取／patch／create 工具调用：
            -> 工具结果与世界变化；世界变化 -> Authority
            -> 同响应 text 只留在调用轨迹与 Provider 续传载荷
            -> 继续下一次模型响应
       -> 如无工具调用：非空 text -> 主持叙事 -> Authority
```

每次模型响应都在同一份调用链契约下选择直接叙事或调用工具。只要完整响应包含至少一个工具调用，它就是**工具中间步**：Runtime 忠实解析并保存其中的 text，但该 text 只属于调用轨迹和下一次请求所需的 Provider 原生续传载荷，不进入主持历史，也不成为玩家可见叙事。模型收到全部工具结果后，必须用一个不含工具调用的后续响应给出最终叙事；Runtime 提示词明确说明这条规则，结算层仍独立强制执行，不能依赖模型自觉。世界写工具只操作当前候选，完整工具响应处理成功后便把变化后的完整 YAML／Markdown 写入 Authority。`world_patch` 的 YAML locator 可混合 map key 与从 0 开始的数组下标，`remove` 只删除精确节点；普通游玩不物理删除或移动整份文档，需要让对象退出常驻 catalog 时使用可恢复的退役状态。

调用链没有整体原子提交或集中结算。玩家原文先单独提交；工具中间步只在确有状态变化时提交那份状态，终态无工具响应只在 text 非空时提交主持叙事。后续模型或传输失败不会回滚已经成立的前序状态步骤。Provider 的 SSE 增量经 Runtime 的 NDJSON 流直接投影到浏览器，但响应完成前的 text 明确标作待定模型输出，不进入故事；完整响应无工具调用时才晋升为正式叙事，有工具调用时则收进默认折叠的技术调用轨迹。增量只更新调用链内容，不主动改变玩家当前的滚动位置。生成期间界面持续显示 Runtime 拥有的阶段、总耗时、最近一次数据距今时间、Provider 派发数以及返回推理／正文／工具参数和工具调用的累计量；浏览器刷新后仍从同一 Runtime 进程恢复这份观察。只有收到 Provider 明示的 reasoning 增量后才能显示“思考中”，首个可区分增量之前只能说明排队、模型内部处理与网络等待尚不可区分；连续 90 秒无新数据可以提示“可能卡住”，不能断言模型状态。Provider 返回推理、工具参数／结果和 usage 只属于调用轨迹，不成为玩家／主持历史或世界 Authority；每份完整模型响应旁始终显示 input、uncached input、cache read、cache write、reasoning、output 与 total token 明细，返回推理、工具和 usage provenance 则在展开单项时读取完整详情。Runtime 不声称这些内容是模型隐藏思维。不透明或加密推理为协议续传保留，但不向玩家投影。

追加上下文继续使用当前模型上下文开始时冻结的 bootstrap，但每次 Authority 写入都必须基于该上下文当前已提交端点；若世界被其他操作推进，只能选择全新上下文重新编译。全新上下文替换旧逻辑 transcript，不把旧链嵌套进新请求；它既可以由普通“全新上下文”提交开始，也可以由玩家消息修改明确选择。修改路径从所选消息的逻辑父端点重新编译当前主持／玩法／模型绑定，把已经由时间线修订提交的修改稿只作为首条普通玩家 append，不再重复推进 Authority。Web 另行持久保留当前时间线上此前成立的玩家输入、AI 正文、Provider 返回推理、工具参数与结果、失败和 usage，使其在刷新或冷恢复后仍按原顺序可达，并在每个模型上下文起点显示分隔标记；普通全新上下文保留完整旧链，修改路径只保留修改点以前的页面轨迹。页面时间线按不可变上下文链和追加事件保存，首次打开只返回最近的有界摘要页；“加载更早”使用稳定游标向前读取，普通尾部追加不会改写旧页或旧事件。

Runtime 在每次模型派发前持久保存完整 `ModelHostExchange`。Provider 完整返回后，Runtime 先保存去除临时诊断的完整结果和协议原生续传载荷，再执行工具、准备精确结算并尝试 Authority 提交；因此进程在 Provider 返回后退出时只能继续结算同一结果，不能再次调用模型。若 Provider 流中断或进程可能已开始派发但未保存完整结果，中断片段只在界面显示，不追加到模型 transcript，也不进入 Authority；此时外部结果未知，旧请求绝不能重发，当前模型会话终止并要求玩家使用全新上下文。玩家可以用当前 world、call chain 与 exchange 的精确身份显式取消生成；AbortSignal 必须贯穿 Chat Completions、OpenAI Responses 和 Anthropic Messages 的真实 fetch 及后置请求。已提交的玩家原文和先前 Authority 步骤不回滚，未结算输出不进入 transcript 或故事；取消发生在 Provider 派发后时同样禁止旧请求重放，只有能证明下一次派发尚未发生时才保留原样继续资格。取消是玩家操作而非错误，页面时间线以独立状态事件呈现；浏览器 NDJSON 断开只是呈现故障，绝不隐式取消 Runtime 正在执行的交换。Provider 明确报告 context window 已超出时，Runtime 不截断消息、文档或工具结果，也不重试同一请求；当前模型会话终止并要求玩家使用全新上下文。除这类必须重开上下文的拒绝外，只有 Provider 在开始生成前明确拒绝请求，或持久状态能证明请求尚未派发时，空输入“追加上下文”才会原样重发已保存请求，不重复玩家原文，不根据片段构造“继续写”指令，也不重新拼装 frame。若上一响应已经完整结束，同样的空输入动作会用包含其原生续传载荷的当前 transcript 发起下一次生成。完整响应的续传载荷缺失、损坏或与冻结模型绑定不兼容时同样必须 fail closed，不能退回到解析投影重建。界面始终只提供“全新上下文”和“追加上下文”两个提交动作，运行中的生成另有“取消生成”控制但不构成第三种提交模式。

模型会话冻结 endpoint、协议与方言、模型、续传 codec、Effort、Thinking 模式／手动预算、返回 thinking 内容、输出能力、工具策略和缓存策略；只允许凭据与传输超时在保持同一语义绑定时更新。CLIProxyAPI 模型名的 thinking 后缀优先于请求 body，因此模型 ID 含 `(high)`、`(max)` 等后缀时只能把结构化 Effort 与 Thinking 都留在 `Provider 默认`，不能同时制造两个配置权威；返回 thinking 内容仍是正交的可见性意图，可以随该后缀独立传递。Provider response ID、continuation token、不透明推理项和缓存只用于协议续传或加速，不成为世界状态、已提交叙事或唯一恢复来源。Claude 通过 Chat Completions 代理时通常只能得到 `reasoning_content`，协议本身不能保证携带签名 thinking；需要可验证续传时必须使用能保留完整原生块的 Anthropic Messages，或使用携带 `reasoning.encrypted_content` 的 OpenAI Responses 兼容路径，而不是切割正文猜测。

Effort、Thinking 模式和返回 thinking 内容是三项独立意图。OpenAI Responses 使用 `reasoning.effort` 与 `reasoning.summary`；Chat Completions 只在协议／方言确实定义的扩展上发送对应字段；这两种 OpenAI-shaped 协议都没有独立 `thinking` 请求字段，因此界面必须诚实固定为 `Provider 默认`，不能假造一项配置。Anthropic effort 只写入 `output_config.effort`；Thinking 则按用户选择省略、写入 `adaptive`、写入带 `budget_tokens` 的 `enabled`，或写入 `disabled`，手动预算至少为 1024 且必须小于最大输出；`thinking.display` 独立控制 summarized／omitted 返回内容。Provider 返回的 thinking block 无论是否显示摘要都原样保留以供续传。不受目标模型支持的组合或等级由 Provider 明确拒绝，Runtime 不猜测模型能力或静默换档。

## 预算、缓存与预览

模型配置继续提供 Provider 的 `contextWindowTokens` 和 `maxOutputTokens`。每次新派发直接使用当前 ModelHost 的固定 `maxOutputTokens`；原样重发使用已持久化的完整原请求。Runtime 不估算 token、不做上下文准入、不另设“连续交换输出上限”，也不在响应已经完成并计费后重新计算再拒绝结果。上下文能否容纳请求完全由 Provider 判断；Runtime 不自动摘要、压缩或截断历史。

提示词编译把稳定机械块、主持块和世界控制块放在稳定前缀，稳定前缀指纹不包含内部 ID、时间戳和 operation 数据。Anthropic Messages 在这些真实稳定块上编码显式 cache breakpoint；CLIProxyAPI 方言的 Chat Completions／Responses 使用代理明确支持的 `cache_control` 扩展。标准 Responses 的 `prompt_cache_key` 按稳定前缀分组，使等价前缀可复用 Provider 缓存；CLIProxyAPI 中该字段还承担 session affinity／重放隔离职责，因此改为按冻结模型会话生成稳定散列：同一会话各轮不变，不同调用链绝不共享。两种路径都不把原始内部身份写入 wire。没有等价显式块的标准协议只报告 provider-managed 策略。Runtime 不能把字节估计伪装成 token 命中，而要持久投影 Provider 实际报告的 input、uncached input、cache read、cache write、reasoning、output 与 total usage，并分别保留 provider／派生／不可用 provenance；游玩时间线和设定完善进度都直接显示全部七项，未报告字段显示为未报告而不是零。缓存 read／write 是 input 的构成，reasoning 已包含在 output 中，界面不能重复相加。改变 Thinking 或 Effort 会改变 Provider prompt/cache key 的语义并使旧缓存边界失效；缓存 miss 只影响成本和延迟，不能改变请求语义或恢复能力。

Prompt Preview 必须调用真实编译器，并展示：

- provider-neutral 逻辑消息和最终 provider role；
- 每个 slot 的精确来源及未提供边界；
- 最终 Markdown 正文与真实工具定义；
- 附加材料展开和按需读取入口；
- Provider 窗口／最大输出配置、Runtime 不做上下文准入的状态和 cache 报告；
- 去除凭据后的真实 HTTP method、endpoint path、header 名称与 request body；
- 内部 DTO 字段泄漏扫描。

内容包设定完善与世界修订的生产 Preview 必须明确显示 `opening.md` 不进入 bootstrap，并把预览玩家原文单列为紧随 bootstrap 的首条普通 user 追加；它不能制造一条权威玩家历史。

预览不调用模型、不创建设定对话、不写入内容树，也不能维护一套近似拼装逻辑。

世界控制可以声明文档和稳定 slot 的 UTF-8 建议体积，以及记录写入时世界时间的明确节点。报告区分正文、真实注入贡献、历史补充、作者／Runtime 提示和工具定义；超过建议值只提示，不拒绝写入或裁切。增长基准来自世界起点或文档首次接受的正文，分叉保留来源基准，空基准不计算倍数。正文和元信息最近写入位置按当前可达 Authority 历史分别计算，不用文件 mtime；世界时间仅取当次写入时的显式绑定值，未记录则如实显示。可选维护诊断失败显示不可用，不阻断正常结算和修订，也不展示旧事实冒充现值。

“AI 读取”比较相邻冻结上下文的真实编译来源、顺序和公共前缀，并展示生产首次派发的无凭据编码、缓存键／断点及 Provider 实报 usage。正文和元信息变化次数按叙事上下文分别统计，分叉或继续原上下文修订保留原分节身份。报告只建议作者显式调整 frame 顺序，不自动排序或改变 Provider 隔离；逻辑文本与 JSON 公共字节不代表缓存 token 命中，收益需独立实测。控制示例与报告边界见[世界状态维护指南](world-state-maintenance.md)。

## 玩家视图与信息边界

玩家视图保存在世界控制中，只使用精确“文档 + 逻辑节点”选择器。选择 scalar 就显示原值，选择 map／list 容器就递归显示其当前子树；文档引用显示为引用，不自动展开。节点缺失或改名只产生明确界面诊断，不做模糊迁移，也不阻止世界继续演化。

玩家视图不是字段权限系统。未显示的内容不自动成为秘密、角色未知或叙事禁区；角色知道、叙事何时揭示和界面常驻显示是三件不同的事。Runtime 只硬隔离凭据、模型配置、宿主机械数据、工具结算意图、账本和工具续传等本来就不属于虚构世界的技术内容。

Runtime 从实际 renderer 选择器生成文档、节点和界面标签的绑定标记，在 bootstrap 和相关读取的正文外展示；容器或全文选择保留其真实范围，不逐叶扩写，不把引用目标推断为已展示，也不赋予额外读写授权。默认主持预设要求玩家视图的持久值发生变化时在本轮最终叙事前写回，特别检查行动、等待、赶路和睡眠带来的时间变化。时间推进多少由主持判断，未变化的字段不要求写入。

## 权威提交、恢复、修正、修改与分叉

Runtime 是唯一业务提交者。每笔提交绑定稳定 operation ID 和父端点，语义载荷包含：

- 按顺序追加的精确玩家／主持原文；
- 每份变化后完整世界文档及前后 hash；
- 下一端点完整附加材料清单。

长期恢复保存最终文件效果，不保存模型 patch 语言。提交先 durable 发布世界中立的内容 blob、state manifest、history segment、材料集合、直接结果 root 和 Authority 事实，再发布独立的“接受已准备”operation receipt，随后原子切换小型 continuity head，最后幂等物化 `state`、`history` 和材料清单；若事实已接受但投影物化失败，结果必须报告“已提交、待修复”，阻止新写入，并只根据同一结果 root 补齐，不能以新 operation 重放模型。每次追加只新增本次 epoch 并替换小 head，不重写此前事实。

V1 继续只用 genesis anchor 加不可变 Authority 事实作为正确性来源，不增加第二份权威日志。`worldId` 只属于世界本地外壳；历史消息使用 Authority 内局部身份，事实摘要不包含 world 或 operation 身份。`commit:N` 是 V1 世界内别名，父关系同时携带不可变摘要，结果 root 是恢复 state、history 和材料的直接入口。物化检查点只证明本地投影已经追到哪个接受点，不能接受新事实或覆盖 Authority。普通打开与继续游玩读取小 head 和当前投影；旧端点直接读取对应结果 root，完整审计才遍历 audit chain。

“创建分叉”是唯一创建独立世界的历史操作。玩家可以在任一已提交玩家／AI 节点点击该按钮；Runtime 先持有统一来源 snapshot lease，再保留截至所选端点的世界中立 Authority 物理闭包，使用创建分叉当下的当前控制和玩家所选主持预设，在同一 target staging 中物化一次最终 state/history／材料投影并发布新世界。当前 head 直接采用小 root 的结果引用，不解码或重算 Authority 事实；共享不可变文件优先 hardlink，失败时 reflink 或逐字节复制，可变投影绝不 hardlink，删除来源后目标仍完全自足。分叉不解析、改写、重算或逐笔物化祖先事实，也不调用 Provider 或重新执行工具。若节点属于持久游玩时间线，staging 同时保留此前完整页面轨迹，并截断所选上下文截至节点的模型 transcript 与调用轨迹，包括返回推理、工具参数和结果；分叉点之后的上下文和响应不进入目标，活动 chain 身份重新分配。截断后最后一项是玩家消息时，玩家可以留空点击“追加上下文”直接重新生成，不再提交一遍同样的玩家原文。

“修改”只作用于当前世界，不创建新 world ID（[ADR-0032](adr/0032-player-edits-append-current-world-timeline-revisions.md)、[ADR-0036](adr/0036-authority-facts-are-world-neutral-and-forks-retain-physical-closures.md)）。玩家确认修改稿后，Runtime 在当前 audit head 上原子追加 timeline revision：`auditParent` 指向修改前当前 head，`timelineParent` 指向所选玩家消息的逻辑父端点，事实只保存双父关系、请求指纹、修改稿与直接结果 root，不嵌入完整 replacement state/history。玩家同时明确选择后续模型上下文策略：**沿原上下文继续**时，新 chain 身份保留逻辑父端点以前的 transcript、Provider 原生续传与原冻结绑定；**作为全新上下文保存**时，页面先把修改点前的调用轨迹封成旧上下文前缀，再用当前主持预设、玩法预设和模型绑定从逻辑父端点重新编译 bootstrap，修改稿成为新上下文唯一的首条玩家 append。后一条路径不读取、不重建旧 Provider 续传，因此旧上下文缺少 durable binding 也不会阻止它。旧提交和旧端点继续精确可恢复，但不进入当前结果 root；“舍弃后续”因此不等于删除审计记录。

连续性修正仍只针对当前端点的文档或材料清单，追加普通 correction 提交；它不替换玩家消息，也不改变活动调用轨迹。时间线修订、连续性修正和创建分叉是三种不同授权，界面不得用同一个含混的“重新开始”动作代替。

## 世界修订

运行中世界的创作入口使用一份持久世界修订 epoch，而不是把内容包设定完善直接指向 Authority，也不为每条手动或 AI 修改建立独立候选。开启入口时，Runtime 从当时的当前端点和控制指纹建立唯一的 `state/*`／`control/*` 工作树并取得非过期独占锁；`opening.md` 已经成为 genesis 主持原文，没有对应的可写当前世界文件。锁存在期间，游玩、时间线修订、连续性修正、控制草稿发布、创建分叉和删除世界都必须在产生世界效果前失败；只读检查和本地世界名称修改仍然可用。浏览器关闭或 Runtime 重启只恢复同一 epoch，不释放锁，也不把工作树重建到更新的世界上。

手动保存和每份完整 AI 工具响应都针对同一工作树 revision 串行结算，并把精确逐文件 before／after 追加到同一改动历史；二者使用同一文件编辑、对话、历史与 diff 界面，不存在“手动修订”和“AI 修订”两个模式。历史中的任一文件可以在活动 epoch 内显式恢复为某次改动的 before-image，即使它后来又被修改；这次恢复本身继续追加为一笔 rollback 改动，不删除模型 transcript 或旧差异。因此玩家可以保留早先若干次修改而只撤销最后一次，不需要整批接受或拒绝一个草稿。epoch 封存后历史继续可读，但所有回滚入口失效。

“应用”先验证整棵工作树及生产等价 Prompt Preview，再用稳定 operation ID 将全部 state 变化作为一次 correction 推进 Authority，随后用确定的 staging／previous 路径幂等发布 control；Runtime 持久记录 prepared、state committed 与 control published 阶段，只有 epoch 已可恢复地标记 applied 后才释放锁。进程在任一阶段中断时只补齐同一操作，不重复推进 Authority，也不把半份 control 当作成功。“放弃”只把 epoch 标记 discarded 并释放锁，不改变 Authority、state 或 control。两种结果都封存此前回滚能力。

世界修订 AI 会话复用设定完善的 Provider／工具循环，但世界工作树、锁、应用和恢复由独立目标模块拥有。会话可以在应用或放弃后继续；下一条新消息会从届时最新世界创建新的 epoch，在 Runtime-system 层追加明确的 epoch 边界，并清空此前 list／search cursor 和完整读取授权。旧 Provider 续传和工具历史原样保留，AI 必须重新读取现有文件后才能写入。浏览器轮询只读取轻量运行状态；durable revision 变化后才重新取得完整工作树和 transcript。

## 设定完善

设定完善只面向内容包设定，不修改运行中世界状态、已提交叙事、人物当前认知或历史。它和游玩一样使用人类可读 Markdown 输入和 append-only 模型会话，不把完整旧对话反复嵌套进 JSON。

显式开启全新上下文时，Runtime 同时冻结当前有效预设 revision、模型绑定和工具全集：其中可编辑的设定完善作者提示决定创作方法，Runtime 再提供不可编辑的工具与机械契约；同一 revision 中实际启用的主持与叙事作者块以明确标注的未来游玩语义边界进入稳定 bootstrap，让创作 AI 能检查兼容性、重复和注入权重，但不能把这些块当成本轮玩家可见叙事指令或设定文档语体范本。参考仍保留实际启用块的原文与顺序，Runtime 不摘要内容，也不根据文件名猜测其语义类别。当前内容包的独立标题也作为明确的数据标签进入稳定 bootstrap，并同时说明它不是世界事实或文档标题、当前情境只由 frame 绑定而其文档标题应随当前场景变化。预设可以改变创作语义，不能声明工具、参数、结果、提交方式或 Provider 协议。继续既有对话时复用其冻结预设、模型绑定、Provider 原生续传、建立当时的标题标签和 append-only transcript；切换当前预设、模型或重命名内容包只影响下一个全新上下文，不改写既有会话的稳定 bootstrap。

开始设定完善时，内容包正文不预先塞入首个模型请求；模型通过固定工具从内容包当前树按需读取，浏览器只提交普通用户消息以及显式的“继续所选对话／全新上下文”选择。默认选择最近对话，历史中的任一对话也可随时选中继续；“全新上下文”从当时的内容包当前树重新编译，但不删除或关闭旧历史。固定机械契约同时解释内容包在创建世界时怎样拆成独立 state／control／genesis、游玩怎样按 frame 精确注入或按需发现材料、普通游玩 AI 能更新什么，以及玩家视图怎样投影原值。模型始终看到稳定的 list／search／read／create／write／patch／move／delete 工具全集，并根据消息本身决定读取、讨论、提问或直接修改当前树。用户若要求先讨论计划，AI 应只读取并回复；这属于作者语义，不形成 Runtime 的计划阶段、生成动作或读写能力切换。意图不明确时应先询问，不应为了展示工作而擅自修改。会改变结构、发现路径或未来更新位置的目标，必须先完整读取 frame、它启用的世界指令、当前情境、开场白和受影响文档。

AI 使用受管的文档 create／write／patch／move／delete 操作修改 YAML、Markdown 和控制文件。YAML patch 的 locator 可用 map key 或从 0 开始的数组下标，`remove` 删除一个已有节点，避免为删键或改一条列表项而重写全文。内容包整理需要的 delete 是物理删除；只有目标已完整读取，且它不是 currentSituation、未被 frame slot 或 player-view selector 选择、也未被其他文档以 `$ref` 指向时才接受，否则工具结果列出全部阻挡位置。ref 仍不可修改，move 仍拒绝覆盖已有路径。一份完整 Provider 工具响应中的调用按模型给出的顺序执行：成功调用看得到此前成功结果，失败调用只在自己的工具结果中返回精确原因，后续调用继续执行；整份响应结算时，全部成功变化一次原子发布到内容包当前树，不能让浏览器观察到半棵新旧混合树。新建文档时 AI 提供唯一 `ref`、标题、摘要、别名、路径与正文，Runtime 生成并隐藏 `$document.id`；所有模型读取、引用和控制选择器只使用 `@ref`，既有内部 ID 自动投影为对应引用。疑似被重复 JSON 转义后留下的字面 `\uXXXX` 内容直接拒绝本次调用，Runtime 不猜测解码。AI 必须检查 `opening.md`：缺失时创建；开局地点、人物、局面、语气或行动钩子受本次修改影响时，先完整读取再更新；不受影响时保留原文。由 AI 创建或已经成功修改过的完整文件视为已经完整读取。完整读取授权只属于产生它的精确当前树 revision；其他对话或手动编辑发布新树后，旧对话必须重新读取才能覆盖既有文件。

创作 AI 可以创建或修改开场白与内容包的世界提示框架；普通游玩 AI 不可以。本响应的写调用结算后，Runtime 自动计算逐调用完整差异，并检查开场白唯一性／文本／大小、文件安全、身份、引用、控制格式、必需 slot、玩家选择器和真实 Prompt Preview；同时从这份真实 Preview 确定性生成设定改动游玩读取覆盖，把改动材料标为全文／节点注入、仅目录摘要、由已注入材料直接引用、仅按需发现、genesis、控制投影，或未被 frame 启用的控制块，并附在最后一个成功写调用的结果中返回给模型。覆盖报告不判断材料重要性，也不替模型做语义选材。模型不需要调用预览或结束工具。Runtime 不校验世界专属字段、关系值、修为枚举或开场白是否有趣。机械检查失败不会回滚已经原子发布的安全文件树；模型可以在后续工具响应中继续修复。模型给出一个无工具调用的完整回复时只结束当前用户推进，不宣告设定终态。

设定完善会话、完整 Provider 续传、Provider 返回推理、工具参数、工具结果、逐调用已生效差异、失败和结算恢复状态由 Runtime 持久保存；浏览器断线不取消生成，不完整 Provider 响应不进入 transcript、也不执行其中工具。Runtime 在“完整 Provider 工具响应与原树指纹已保存／当前树已发布／工具收据已追加”三者之间保存可恢复结算意图；重启后只补齐已确认的发布或从该精确原树重放完整响应，绝不从流式片段或任意更新的树猜测工具。当前会话 schema 对所有非 opaque 字段使用完整 codec，未知或损坏结构 fail closed。旧 schema 的隔离草稿迁移时先严格验证完整已发布结构，再保留不可变旧源、transcript 和历史差异，未应用草稿绝不静默写入当前树；待定旧 Apply 收据在内容包租约内按 base/draft/当前树指纹记为已应用、未应用或结果未知，迁移本身不写树。迁移后的 bootstrap 在 Runtime-system 层追加当前树写入契约并换用当前工具定义，使旧高优先级草稿指令无法支配后续消息；原 Provider assistant 续传载荷仍原样保留。界面在每个工具结果下直接显示与该调用对应的统一 diff：删除为红色、新增为绿色；不存在另一个 Apply、Discard 或候选预览表面。

每条成功且非空的历史工具差异同时获得稳定的改动集身份，作者可以在该 diff 中逐份选择文件直接回滚。回滚不调用模型，也不回到整份内容包快照：Runtime 在内容包租约内只把所选路径恢复为该次 AI 修改记录的前像；create 的前像为空所以删除所选文件，delete 则重新创建，move 的来源和目标也是两个可独立选择的文件。所选路径即使有后续手动修改或其他 AI 修改，也以这次显式回滚为准直接覆盖；已经等于前像时返回幂等成功。原 Provider 对话、工具回执和当时差异保持 append-only，回滚不会往模型上下文写入伪造消息。

## 目标模块边界

- `ContentWorkspace` 拥有内容包本地身份、独立标题、当前树、安全导入／导出和当前树原子替换。
- `WorldDocumentStore` 拥有世界文档身份、受限 codec、精确读取、候选 patch／create／retire、引用索引和当前树物化。
- `PromptCompiler` 拥有主持／世界 bootstrap 的确定性编译、Runtime 机械说明、slot 绑定、Markdown 渲染、role 映射、Provider 参数、缓存报告和真实预览；生产游玩调用方只提交编译输入，不另行构造提示词或材料 DTO。
- `SettingImprovementSession` 拥有设定完善对话、显式继续／全新上下文、稳定工具全集、逐响应当前树结算、历史差异的单文件直接回滚、自动检查、模型调用轨迹和失败恢复；`FileNativeSettingImprovementStore` 只保存可恢复会话、读取授权、结算意图与工具回执，不保存第二棵内容树。
- `ModelToolConversation` 只拥有作者型 Provider／工具交换、流式观察、取消和请求幂等；内容包与世界修订各自在其结算 seam 后拥有目标树的发布语义。
- `WorldRevisionWorkspace` 拥有独占 epoch、共享 `state`／`control` 工作树、统一改动历史、逐文件回滚和可恢复 Apply／Discard；`WorldRevisionSession` 拥有跨 epoch 对话、工具授权与重新读取边界，`FileNativeWorldRevisionStore` 保存二者的 durable 状态。
- `PlayCallChain` 拥有两个提交动作、空输入续写、模型／工具循环、浏览器增量投影、tool-call 幂等、逐响应 Authority 衔接和中断请求原样重发。
- `FileNativePlayTimelineStore` 拥有跨全新上下文的页面时间线、稳定游标摘要页、单事件详情和可恢复的追加投影。
- `FileNativePlayAdvanceStore` 拥有冻结请求、完整 Provider 结果、精确响应结算和已结算端点等不可变游玩推进事实。
- `FileNativeAuthorityV3` 拥有世界中立不可变事实、双父关系、直接结果 root、物理闭包复制和小 continuity head；`FileNativeWorldStore` 拥有世界外壳、operation receipt、投影物化、时间线修订、原子分叉 staging 与修订 control 发布；`FileNativeWorldOperationCoordinator` 在世界语义写入和持久修订锁之间仲裁。它们都不向模型暴露提交 DTO。
- `FileNativeArtifactStore` 拥有后置请求产物的 pending 记录、结算、保留策略和活动投影；玩法产物不混入世界 Authority。
- `ModelHost` 与 provider adapter 只拥有协议编码、流式交换和续传，不拥有世界事实或提示词语义。
- `Runtime` 协调这些深模块，是唯一业务权威。

## 持久格式与升级边界

正式发布或公开预发布过的持久格式属于产品兼容契约。Runtime 在旧世界第一次跨越对应的 Authority／页面时间线 seam 前，必须按明确版本执行一次性迁移：先校验旧 Authority、调用链、全部可达端点和物化检查点，再确定性归一旧 world-bound 身份，写完并验证当前不可变事实、operation receipts 与可重建投影，最后原子发布 `continuity-head.json` 作为当前布局已经完整成立的 durable marker。进程在 marker 发布前退出时旧累计源仍然完整，重启只从旧源重建或复用未接受对象；marker 发布后只读取和写入当前格式，旧源保留为只读恢复证据，不再随游玩增长。

这项迁移义务不等于长期兼容猜测。Runtime 只迁移能够精确识别的已发布 schema；未知字段、未知命名空间或损坏记录仍然 fail closed，不能推断别名、部分导入、双读、双写，也不能在结果不明时触发模型重放。
