# 世界状态维护与上下文衔接指南

本指南面向内容包作者与提示词调优者，提供世界状态维护的写作实践、典型判断案例以及合成场景的实模验证方法。

> [!NOTE]

> - 游玩读取授权内存态与重启／回退重放恢复、检查点生命周期与 `world_patch` 规则：[游玩调用链、历史导航与世界生命周期规格](specs/play-history-and-world-lifecycle.md)
> - 编排方案叠加存储、旧四复合块退役映射与 `control/frame.yaml` 的 `maintenance` 声明 schema：[提示词编排、编排方案与世界控制框架规格](specs/prompt-orchestration-and-presets.md)
> - Prompt Preview 与「AI 读取」对比诊断：[模型 Provider 协议、容错与可观测性规格](specs/model-providers-and-resilience.md)

## 主持怎样维护连续性

### 1. 保存位置与优先级

决定一项变化该写在哪里时，可按以下顺序取舍：

1. **忘掉也不会明显出戏**：只留在已提交叙事，不写入世界文档；
2. **只约束紧接着的局面且没有单一所有者**：写入当前情境文档；
3. **持续约束人物、地点或其他自然对象**：写回对应的自然所有者文档；
4. **普通物品只需记存在、归属和意义**：直接嵌入自然所有者文档；
5. **必须独立引用、转移或追踪生命周期**：升级为独立世界文档；
6. **即使成为关键道具**：也只记录当前玩法真正需要的字段，不铺开冗余物理属性。

**典型案例**：

- **衣着与普通环境物**：秦龙脱掉上衣后，需写回人物文档的当前状态是 `衣着: 光膀子，运动短裤，拖鞋`，避免下一次行动再次脱衣；至于那件普通上衣是否仍搭在椅背，忘掉不会出戏，可以不记。
- **物品升级边界**：校际赛冠军奖杯或象征友谊的球鞋，初期只需在人物文档记录存在、归属与意义；只有当奖杯被盗、球鞋转赠或物品能力进入具体玩法，需要独立引用与生命周期追踪时，才拆出独立文档。

### 2. 互动范围、保存时机与随时整理

- **先定本轮停笔范围，再维护事实**：意图、计划、承诺与日程可以是当下成立的事项，但其目标不因此成为已经实现的结果；尝试也不证明成功。持续互动中，只要新反馈会影响玩家如何接话或调整，应留出回应机会；允许开始活动不默认授权包办全过程。
- **按可恢复性把握保存时机**：
  - 玩家视图实际绑定的当前值发生变化时，在最终叙事提交前及时写回（时间推进由主持依据行动、等待、赶路、休息等情境判断）；
  - 当前情境采用顶层 `背景` 字段且定位变化时，同步更新该节点；
  - 需要持久保留但玩家原文与最终叙事未记载的信息，当场写回；
  - 可从近期原文恢复的其余进展，可在事件收尾或合适的中间整理点归并。
- **整理随时可做**：持续活动跨多轮积累了需要归并的进展，或出现重复、过期记录时，可直接在本轮工具调用中整理自然所有者、重要认知、承诺与有界文档，**不需要等待事件结束，也不需要登记检查点**。已写回的事实核对后沿用，不重复写入；仅保存进行中活动的实际进展、必要原话与待回应事项，不提前写成完成。

### 3. 当前情境收敛与文档边界

- **当前情境不是完整状态汇总**：只保留本轮停笔位置仍然成立的地点、在场者、进行中事件以及下一次行动若忽略就会立刻冲突的短期限制（含待回应的话语与反馈）；不回放刚完成的步骤，不追加「上一次行动发生了什么」的事件流水账。可明确归属于人物、地点或关键物品的持续结果，不应长期堆在当前情境。
- **`title` 与 `summary` 的职责**：文档简介（`summary`）用于目录发现与识别身份／主题／稳定线索，不在简介中维护具体状态或事件经过的副本；仅在识别信息变化时更新标题与简介。当前情境的场景身份切换时及时更新其索引，具体地点、在场者与待办留在正文。
- **事实、过程、事件与主观认知分责**：
  - 对象文档保存当前取值，过程保存实际进展与有效条件，意图／承诺／日程保存尚未实现的目标；
  - 重要事件需要共同引用、追溯或重新解释时按事情独立成文（不按回合机械建档），保留当时经过、结果、条件、原话与来源，区分客观事实与人物声称；最新状态与看法仍留在各自文档并通过引用关联，事件不充当滚动状态表；
  - 人物对他人看法写在产生看法的人物文档中（方向自然表达，不强制镜像），只有忘记后会明显破坏人物行为的重要认知才持久化，不穷举角色「不知道的所有事」；已经形成的看法不因切换上下文从事件重新推算，也不随世界真相自动同步；偿还、伤愈、完工结束对应待办，同时保留有意义的经历、后遗影响或成果。
- **补录与混合请求**：补录旧结果、去重与索引整理不导致事件重新发生，不重复消耗资源或转移物品；纯世界外查询或维护请求简洁答复整理结果，不为小说形式硬添动作或时间推进；混合请求中的维护要求不成为角色行为。

### 4. 事件间隙检查点与新上下文衔接实践

关于 `world_checkpoint {}` 的生效时点、历史补充重放与浏览器预选规则，见 [游玩调用链规格 §3.3](specs/play-history-and-world-lifecycle.md#33-叙事检查点与完整原文重放adr-0039)。在作者写作与调优实践中：

- **适合登记的时机**：对话、交易、冲突或活动自然结束，或地点、时间、在场者等场景实际转换且前一段事情告一段落（追逐穿过街道仍属进行中活动）。事件结束不等于无话可接，自然结束也不必硬添等玩家接续的话语。
- **不适合登记的时机**：持续活动尚在进行，或当前事情仍待玩家决定、给出关键回应时，不因普通停笔或整理完成而登记；不为凑间隙而加快节奏、压缩过程或提前结束事件。
- **登记前核对**：核对上次检查点后的交互，把后续仍需要的当前状态、重要认知、承诺、待办与界面值写回，使后续互动不必依赖前一阶段的全部过程，且不要把需持久保存的新承诺唯一地留在检查点当段原文里。玩家通过本轮临时要求表达「在此收尾」时，结合输入按其意图收束、保存并登记，不代作无关决定。
- **读取授权与新上下文边界**：同一原生对话的读取授权存于内存，重启或回退时从 bootstrap 按保留对话重放成功精读并在写入时逐文件校验原内容（详情见 [游玩调用链规格 §2.3](specs/play-history-and-world-lifecycle.md#23-游玩精读授权的内存态与重启回退恢复)）；全新上下文不继承旧对话授权，但会完整补入最近检查点后的已提交原文以衔接连续性。
- **编排方案定制提示**：系统内置作者策略属于可停用、可克隆的推荐条目，不与 Runtime 机械边界绑定；旧四复合块退役后的原位展开规则见 [提示词编排规格 §2.2](specs/prompt-orchestration-and-presets.md#22-应用目录演进新块插入与旧四块退役映射)。如需采用新版内置规则，可在编排方案工作台对照新版内置块替换或改用系统引用。

### 5. 可选的整理提示与缓存排序建议

- 作者可在 `control/frame.yaml` 中声明可选的 `maintenance.documents`、`maintenance.clock` 与材料槽 `advisoryBytes`（完整 schema 与增长基准定义见 [提示词编排规格 §6.2](specs/prompt-orchestration-and-presets.md#62-maintenance-维护声明与体积时钟诊断-schema)），在文档或槽位膨胀时收到非阻断的整理提示。
- 调优提示词顺序以提升前缀稳定性时，可在「AI 读取」面板查看相邻发送的真实编译来源对比、上下文变更频次与实报缓存用量（完整诊断契约见 [模型 Provider 规格 §7.2](specs/model-providers-and-resilience.md#72-ai-读取对比诊断)），并在 `control/frame.yaml` 中显式将高频变动材料后移。真实模型的时间更新、检查点收尾、跨上下文连续性与缓存收益验收见 [Issue #29](https://github.com/narraeon/narraeon/issues/29)。

## 合成场景验证

`scripts/validate-interaction-model.mjs --list` 列出持续互动、普通连带动作、授权快进、新条件、中途主动开新上下文、工具混合正文与仅整理场景。`autonomous-checkpoint-scene-change` 与 `autonomous-checkpoint-ongoing` 在同一上下文连续发送普通玩家输入，分别观察自然收尾／换场景时登记和活动中途整理但不登记；所有玩家输入都不提示维护。换场景场景随后主动开启全新上下文核对借阅与归还约定；`mid-activity-checkpoint` 不要求打点，验证活动中途玩家主动开启全新上下文后，整个当前事件的原文与待回应内容继续成立。`--preview <新证据目录>` 使用临时虚构世界和真实编译器生成首条输入的预览，并列出后续输入，不读取模型配置或调用 Provider；这只能验证拼装，不模拟后续回合。

实模运行显式传入一份可用的 `model-connections-v1.json`，脚本沿用其中当前连接的完整配置，不改变模型、Effort、Thinking 或输出参数，也不读取已有世界与调用轨迹。末尾源码根参数可指向带可用依赖的改前 checkout；省略时使用本脚本所在仓库。使用同一脚本、配置与场景分别重复运行改前和改后，证据目录必须是新目录：

```sh
node scripts/validate-interaction-model.mjs /path/to/model-connections-v1.json /path/to/new-before-evidence all /path/to/before-checkout
node scripts/validate-interaction-model.mjs /path/to/model-connections-v1.json /path/to/new-after-evidence all
```

脚本保存实际提示、工具交换、最终叙事和状态，每条输入最多允许 24 次模型请求，临时世界在结束时清理。证据中的 `observe` 是人工核对判据，不注入模型；`semanticVerdict` 始终待评估。逐次观察越过回应窗口、代玩家接话、提前写完成状态等行为；活动中途需核对有实际整理写入却没有登记，且活动未提前结束；间隙场景需核对工具是否实际调用成功、登记前已保存后续所需结果及新上下文的连续性，不能用显式要求打点的结果替代。证据中的 `checkpointStats` 记录请求次数、登记尝试、成功登记和每次输入的频率，供同场景改前／改后比较；它不自动判定事件是否结束。工具混合正文只有实际出现时才算覆盖。没有实模证据时不宣称互动改善通过；运行与验收状态记在 GitHub Issues。
