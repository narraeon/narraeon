# 世界状态维护与上下文衔接

写入回执、预览、设定完善检查共用真实材料编译器。成功写入后的回执说明“按当前状态和配置，若现在开启全新上下文”的正文、节点和目录摘要覆盖；它不会声称本次工具循环已重新注入。覆盖判定失败会说明原因，并保留真实写入结果。

## 主持怎样维护连续性

默认玩法预设使用三档保存规则：玩家视图显示的值发生变化时，本轮最终叙事前写回；需要保存但玩家原文与最终叙事没有记录的信息当场保存；其余可恢复状态在事件收尾集中归并。时间推进由主持根据行动、等待、赶路、休息等情境判断。Runtime 标记玩家视图的真实文档与节点绑定，不推断时间增量或赋予额外读取权限。

主持整理自然所有者、重要认知、承诺和有界文档后，可调用空参数 `world_checkpoint {}`。整理须包含本轮收尾将确立的重要结果；登记后新增重要结果时仍可继续调用工具补齐。最终叙事成功提交后检查点生效，边界包含该叙事，不能把新承诺唯一地留在收尾原文里。叙事下方显示开启全新上下文的建议；点击只准备下一次输入，玩家仍需主动提交。

当前事实写回自然所有者，持续过程保存实际进展和仍有效的条件，意图、承诺和日程保存尚未实现的目标。重要事件的经过集中保存，需要共同引用、追溯或重新解释时使用独立可引用的事件文档；按事情划分，不按回合机械建档。事件记录保留当时的经过和结果；最新状态、待办和看法仍在各自文档维护，通过引用关联，事件不充当滚动状态表。对象保存事件留下的当前结果，主体保存各自的认知、态度和简短依据，并关联必要事件，不各抄一遍经过。人物声称与猜测不因记录而成为已证实事实。

认知和态度有持有者，已经形成的看法不因换上下文而从经历重新推算，也不随世界真相自动更新。客观的任职、结盟、归属和债务另按事实维护；玩家未表达的感情不能代填。偿还、伤愈和工程完工会结束相应待办，不抹去有意义的交易经历、后遗影响或现有成果。沿用世界允许的文档与目录安排承载和发现路径，不要求固定字段、事件数量或目录名称。

summary 只提供简短身份、主题或稳定线索，供识别文档和决定是否读取；具体状态与事件经过放在正文。仅在识别信息改变时更新标题与简介，避免每次状态变化都维护第二份事实。内容包设定描述世界起点；运行中世界修订承接已经演化的当前世界，整理本身不生成新剧情。

补录旧事件、归并和去重不要求再次演出，不重复扣费或转移物品。只有世界外查询或维护的请求简洁回答或说明整理结果，不为小说形式新增动作、对话或时间推进；混合请求中的维护要求不成为角色行为。本轮新结果按实际保存时机写入并在玩家能感知时表现。当前状态、旧叙事和明确的世界外修订需要一起核对；材料读取失败不改变角色记忆。

同一原生对话每次发送重编译时，仅在旧读取凭据与当前完整状态指纹一致时承接原精确写入范围，并合并本次注入授权。未读兄弟节点仍未授权，目录与界面标记不扩大范围；可创建目录按当前 frame 声明。全新上下文不继承旧对话授权。

新上下文完整补入最近可达检查点之后的玩家原文与最终叙事；没有检查点时从世界起点开始，开场白不重复注入。尾段非空会替代 recent 历史选择，即使 frame 没有 history slot 也补入；尾段为空仍采用 recent 声明。补充不包含思维链、工具调用、工具结果或工具中间文本，不设 Runtime 重放预算。每条真实玩家输入前另附完成回合数；空输入续写不增加回合，历史范围按精确消息位置选取。

默认保存规则属于新默认预设和可编辑作者提示。已有用户编辑、复制或导入的预设保留原文，已保存请求继续采用当次冻结的提示与工具集合，下一次正常发送按当前预设和材料重新编译。

## 可选的整理提示

在世界控制编辑器中，可为文档和材料槽填写建议体积，也可选择记录写入时世界时间的明确节点。对应控制如下：

```yaml
maintenance:
  documents:
    '@current-situation': 8000
    '@alex': 12000
  clock:
    document: '@current-situation'
    locator: { yaml: [时间] }
context:
  - slot: { kind: document, document: '@world-rules', id: rules, advisoryBytes: 24000 }
  - slot: { kind: current_situation, id: scene, advisoryBytes: 10000 }
  - slot: { kind: additional_materials }
```

这是可合并到现有 frame 的局部示例，保留原来的 format、bindings 和 instructions。文档通过稳定短引用定位；材料槽 id 必须唯一、稳定，调序后保留。建议值为正整数 UTF-8 字节，不是 token，也不是写入或历史补充的硬限制。超限时工具回执仅附简短提示，完整报告在 Prompt Preview、设定检查和“AI 读取”中展示。

报告区分正文原始字节、去重后的实际注入贡献、世界材料总量、其中的检查点历史、作者与 Runtime 提示以及逻辑工具 JSON。单文档贡献包含其真实选取的标题和标记，合计不包含所有跨文档公共标记；不能把所有正文之和当作请求大小。

增长基准来自世界起点文档正文；游玩中新建文档使用第一次接受的正文，标为创建后新增。分叉保留来源基准，空基准不计算倍数。相对基准增长不代表冗余。

精确读取在正文外附最近已提交的正文和元信息变更位置。只有摘要变化时，正文位置保持不变；no-op、重启和文件复制不刷新位置。时间只记录明确绑定节点当次写入时的标量或 Markdown 文本；未绑定、节点不可读、复杂 YAML 对象或旧提交没有记录时显示未记录。此信息不代表角色知情程度。诊断读取失败时明确显示不可用，已经接受的写入和后续叙事继续结算，不展示旧位置冒充现值。

## 诊断缓存顺序

“AI 读取”比较同一时间线上相邻发送的运行编译结果，并另列下一次发送候选。报告给出逻辑文本公共前缀、变化来源及其顺序；文档表区分发生真实正文和元信息变化的上下文数，同一上下文多次修改只计一次；分叉和继续原上下文的玩家消息修订继承原分节身份，不因 Provider 会话改名而重置回合。旧提交没有可识别上下文时，不伪造变更次数。

生产 Provider 每次运行首次派发时记录不含凭据的实际编码，用于核对 JSON 前缀、内容块、缓存断点和缓存键。没有历史记录的上下文显示缺少对照。JSON 公共字节和逻辑文本公共字节不等于 Provider 能命中的 token 前缀。CLIProxyAPI 的上下文隔离键保持原有语义；任何排序建议均需作者在控制中显式修改，并在下一次正常发送生效。

报告保留 Provider 实际返回的 cache read、cache write 和 uncached input；缺失值显示未报告。相邻请求 usage 并非受控收益实验，不能据此宣称节省比例。真实模型的时间更新、检查点收尾、跨上下文连续性和缓存收益验收见 [Issue #29](https://github.com/narraeon/narraeon/issues/29)。
