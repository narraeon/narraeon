# 故障日志、世界修订与内容包导入基准

从仓库根目录运行。探针只创建隔离的合成内容包、世界、配置和本机模型服务。结束后清理临时 Runtime 数据，保留出参、计量数据和合成事故原始 JSONL。为降低计时噪声，可在主机负载平稳时执行。

```sh
npm ci --prefer-offline --no-audit --no-fund
mkdir -p .scratch
node scripts/maintenance-benchmark/measure.mjs .scratch/343-rerun --repeats 5
```

输出目录须尚不存在。可用 `--suite faults`、`--suite revision`、`--suite session` 或 `--suite import` 重跑单项，默认每档 5 次。每个 JSON 保留逐次原始数值，时间用 ms，空间用字节。

## 计量边界

| 项目                 | 负载与边界                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 游玩故障日志         | 每次从新世界经真实 HTTP 和 Chat Completions SSE 走游玩主链。前 8 轮含 10 次 Provider 调用和 2 个成功工具。随后测试一次工具拒绝后自动完成，以及一次 HTTP 503 后重建 Runtime、用同一上下文手动重试。每次恢复后另做 3 轮正常游玩。记录 `ai-failures/*.jsonl` 与其 `.state/*.json` 的逻辑文件字节数、捕获的交换和状态。请求和响应的字节是日志所存正文，不计文件系统分配块、其他 Runtime 日志和世界目录。                                                                 |
| 手动保存世界修订     | 每档每次用独立世界，同一已初始化 Runtime 交替跑大小两档。一份未计时的小草稿预热保存路径。计时从发送预先编码的 HTTP 请求到读完回复，包含普通 JSON 请求处理、校验、生产落盘以及概览回执序列化和传输。工作树已锁定，每次只改一份现有 Markdown 的等长标记，浏览器同款命令发送完整工作树，连续保存 3 次。记录初次和后续保存，以及累积改动历史带来的回复与落盘尺寸。建档、首个锁定请求、客户端 JSON 编解码和读回另外执行。                                                 |
| 世界修订会话         | 两个独立世界各用本机模型预先完成 2 轮和 24 轮，随后各追加 5 次正常作者消息。每轮回复约 8 KiB，纯文本，无工具。HTTP 时间包含本机响应和生产存储。每次生产 `FileNativeWorldRevisionStore.saveSession` 的单独计时只覆盖存储方法，从调用到返回，包含现有和新会话的校验、读取及原子发布。保存方法保持原样执行。样本轮次会增长，另有存储大小和调用次数。                                                                                                                    |
| 内容包 ZIP，经 HTTP  | 先生成合法、可用的 UTF-8 内容包。小包为约 20 KiB 文本，两种大包均为约 24 MiB 文本，采用不同压缩率。实际执行本机 `POST /api/runtime/v1` 的 `content.import`，从客户端发送预编码请求开始，到客户端完整读完回复。计入服务端 Base64 JSON 解析、校验、解码、ZIP 解压与校验、落盘，以及成功响应的 JSON 序列化与传输。客户端生成 Base64、编解码 JSON 和浏览器渲染均在计时范围外。记录 ZIP、解压 UTF-8 文件正文与 RPC JSON 的字节数。HTTP 失败单独记录状态、耗时和是否发布。 |
| 内容包 ZIP，存储入口 | 计时从向生产 `ContentWorkspace.importPortableContentPackageArchive` 传入已读取的 ZIP Buffer 到方法返回。包括解压、检查、发布和构造内部返回值。ZIP 读取、HTTP、Base64、JSON 网络编解码均在计时范围外。                                                                                                                                                                                                                                                                |

两种 ZIP 路径的每个样本与空闲基线各有一个独立 Node 进程，数据根互相隔离。HTTP 客户端在进程外。冷样本在 Runtime 或工作区就绪后马上执行首次导入。热样本先在同一进程另导入一个小包。系统文件缓存保持自然状态。空闲工作区基线预读同尺寸 ZIP，与工作样本的输入一致。空闲 HTTP 服务基线持有空闲服务状态。启动后观察 50 ms 建立起始测量，空闲对照再观察 200 ms。使用 Node `process.resourceUsage().maxRSS` 的进程生命周期高水位（换算为字节），保留空闲对照差、同进程高水位升幅以及开始和结束 RSS。峰值包括 Node 及本机库，暖进程的高水位包含预热。浏览器和发请求的 Node 客户端内存均在范围外。请求串行执行。

## 可选的实模工具拒绝统计

使用 #161 独立合成实模评测的 `live` 目录，其中应有 `manifest.json`、`summary.json` 和完整的 27 个案例文件。下面的脚本校验案例摘要并只输出回合状态、Provider 调用数和工具结果计数以及被拒工具名。它不输出提示词、设置、凭据或叙事正文。按游玩日志的同一判据统计 `tool_result.ok === false`，一次模型响应可以包含多个失败结果。样本是一个模型的两轮欠据场景矩阵，用来观察这组玩法下的触发情况。

```sh
node scripts/maintenance-benchmark/count-rejections.mjs \
  .scratch/161-iou-default-20261125/live > .scratch/343-rejections.json
```
